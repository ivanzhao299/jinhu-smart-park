# 玉舟 V10 旧客户端现场只读遍历台账

日期：2026-08-27  
状态：`IN_PROGRESS`  
证据边界：旧客户端真实运行页面的脱敏人工观察记录；当前为 L3 现场补证，不计入 L4 兼容分；不记录连接地址、账号、密码、员工值、工资值或未脱敏截图。  
操作边界：只读导航；不保存、不审核、不反审核、不结账、不发薪、不导出。

## 1. 闭环判定

本台账完成不等于生产导入获准。只有下列条件全部满足，`legacyRuntimeTraversal` 才可从 L0 升为 L4：

1. 全部一级模块和可见功能入口有稳定 ID、页面类型和可访问结果。
2. 维护页逐项记录字段、默认值、必填/校验、编号和状态动作；查询页记录过滤器、列表列、汇总、打印/导出，但不保存业务值。
3. 每项旧能力被判定为 `preserve`、`modernize`、`archive` 或 `reject`，并绑定新 route/API/entity/atomic permission/test。
4. 现场条目与 162 表、2,364 字段、212 规则、46 帮助主题完成双向对账；孤儿项必须有稳定 gap reason。
5. HR、薪酬、财务业务负责人另行完成 L5 签署；生产历史 import 在此之前保持 `HOLD`。

当前 v1 台账只允许 `IN_PROGRESS / L3_RUNTIME_PARTIAL / compatibilityScoreContribution=0`。即使人工把完成布尔值全部改为真，验证器也必须失败；L4 需要升级合同并提供逐页、逐原子绑定及角色矩阵证据，不能由本台账自我宣告。

## 3. 已确认的页面级业务语义

### 3.0 单位、部门与职位

- 一级模块只有单位设置、部门管理和职位管理三个主入口，组织与职位是员工生命周期的基础主数据。
- 部门管理使用层级树，支持新增同级、新增下级、删除和移动位置；字段包含部门名称/编码、人数计算、联系方式/地址和说明类信息。
- 新系统必须保留稳定部门编码、父子层级和历史组织版本；人数应由有效任职关系计算，不作为可任意编辑的事实值。
- 删除/移动部门需要引用检查、有效期和审计，不能照搬旧客户端的直接动作权限。

### 3.1 人员录入/员工就职

- 采用独立“员工就职”动作，而不是直接编辑员工主档。
- 空白页可见员工编号、员工姓名、身份证号、所属部门、所在职位、工资标准/等级、就职日期、备注和业务记录号。
- 员工编号附近存在编号辅助动作；底部存在继续维护员工附属资料的入口。
- 新系统应保留“生命周期事件创建员工”的语义，同时将身份证、工资字段拆成原子字段权限和审计。
- 未执行保存；编号是否永久不复用仍为 `EMPLOYEE_CODE_NON_REUSE_UNPROVEN`。

### 3.2 劳动合同维护

- 页面是部门树 + 员工合同台账，不是单一附件页。
- 已确认列族：员工编号、员工姓名、身份证号、合同类型、合同编号、首次签订/终止、首次期限、续签日期/期限、最后签订日期、续签次数、累计期限、转正/合同状态、变更日期、备注。
- 主入口旁另有查询、员工转正、合同导入、试用期提醒和合同到期提醒，证明提醒与转正是独立业务动作。
- 页面默认展示真实人员值，因此不保存截图、不记录行值；后续只记录列结构和空白动作页。
- 续签链与提醒边界在专门页面验证前继续为 `LEGACY_SEMANTICS_UNCONFIRMED`。

### 3.3 工资核算设置

- 进入核算设置前必须先选择工资账套；现场列表证明旧系统存在多账套并行，而不是单一全集团工资模板。
- 账套设置页按工资项目逐行配置，现场可见项目名称、数据类型/来源、顺序、参与计算/显示类开关和公式相关操作。
- 页面提供项目管理、删除项目、公式测试/自动创建、表头/公式查看，以及新增、排序、修改、保存、取消、退出等动作。
- 新系统必须把“账套→项目→公式→输入→核算→账表/工资条→银行报盘→月结”建成版本化状态链；公式范围、容差和审批证据未完成前不得生产计算。
- 银行代发页按工资账套、代发银行、年月/批次选择输出列及顺序，并支持分隔文本、定长文本或自定义类文件格式；新系统必须把格式模板版本、生成审批、文件哈希、下载权限和敏感访问审计分开。
- 月结入口先选择账套，再显示账套、年度、月份、锁定/结账状态的期间台账；现场只查看历史状态并退出，未触发结账。
- 旧系统银行报盘与月结虽然保留为功能需求，但生产启用继续是硬门禁，不能因最近三年数据已迁移而自动开放。

### 3.4 考勤方案与规则

- 考勤以方案为根，方案可关联考勤项目、考勤设置和人员设定，不是单一打卡表。
- 方案页存在上/下班及迟到早退等时间或阈值参数；项目规则页存在分级/区间/数值设置。
- 现场结构证明考勤结果可能被项目规则量化后输入工资或绩效，必须保留来源版本和计算审计。
- `N/N1/N2` 等旧符号与具体分级含义仍需结合项目页和真实历史结构复核，当前不得猜测。

### 3.5 绩效考核标准

- 页面按组织/对象维护考核设定，包含考核类别、统计单位及考核项目维护入口。
- 主模块另有记录录入、结果管理和结果汇总，形成标准→记录→结果→汇总链。
- 新系统 360 评价是现代扩展，不能替代旧考核项目、权重、来源联动和汇总口径。

### 3.6 招聘申请

- 现场页包含申请主题、招聘职位、需要人数、人员条件、申请部门、申请日期、申请人和职位要求/说明。
- 历史列表带审批状态，一级入口还包括招聘审批、招聘发布、招聘录用和应聘人员。
- 新系统必须实现申请→审批→发布→录用/入职的受审计状态链；候选人身份证明、联系方式和附件使用独立字段/导出权限。

### 3.7 保险人员缴费方案

- 页面采用组织树 + 员工列表 + 缴费方案/生效区间结构，说明保险政策需要落实到人员和期间。
- 该页默认展示真实员工信息，现场截图不保存；只记录结构。
- 新系统需区分政策版本、人员参保方案、险种基数/比例/单位与个人额、月度计算、补缴/更正和关账状态。

### 3.8 培训课程与计划

- 课程设置包含课程编号、课程名称、培训目的和培训内容，课程是独立主数据。
- 培训计划包含计划名称/编号、培训课程/项目、主办部门、内训/外训、培训方式、讲师、费用、对象、起止日期/时间、地点、说明和完成状态。
- 计划页维护参加人员明细，并提供选择参训人员动作；因此新系统不能只保留课程标题和日期。
- 培训记录、课程/记录查询、统计分析需要关联同一计划版本、人员明细和经费口径。

### 3.9 奖惩类别设置

- 类别台账包含稳定序号、奖惩项目、奖励/惩罚类型及两类正负数值参数；现场项目既有奖励也有惩罚。
- 数值参数证明奖惩可能与绩效或工资联动，但字段精确语义仍需和表结构/过程交叉确认。
- 新系统应版本化类别，不允许修改历史记录所引用的旧口径；绩效/薪酬联动必须记录来源和审批。

## 4. 现场发现对当前基线的修正

1. 招聘存在申请→审批→发布→录用→应聘人员链，不能只按“人才库/渠道/Web 查询”实现。
2. 合同模块必须包含员工转正、试用期提醒和合同到期提醒三个独立能力。
3. 工资必须保留账套、核算设置、数据输入、账表、个人查询、银行报盘、月结七类职责分离；最近三年热数据策略不等于删除这些功能门禁。
4. 系统管理的旧权限拒绝本身是证据：新系统需验证菜单、动作、字段和数据范围四层授权，不得只做页面级角色。
5. 旧客户端页面会默认暴露身份证、合同等敏感字段；新系统必须默认最小展示、字段脱敏、导出单独授权和访问审计，不能照搬旧行为。

## 5. 46 个帮助主题与现场的规则交叉确认

- 员工浏览可在在职、退休、请辞、停薪留职、外调等人员状态间切换；新系统使用同一员工主档 + 有效任职/状态事件，不复制物理分库，但必须保持历史查询语义。
- 员工编号支持自动生成、编号宽度和补空；存在姓名重复提示。补空是否允许复用离职员工工号仍未证明，因此永久不复用继续是硬缺口。
- 员工档案至少包含基本/扩展资料、简历、家庭与社会关系、工作经历、技能、证照、异动、培训、奖惩和自定义字段；每个子域需要独立字段权限和审计。
- 调职单自动编号格式为 `DZyyyymmxxxx`，离职/退休单为 `LZyyyymmxxxx`，复职单为 `FZyyyymmxxxx`；员工就职编号前缀仍需现场/过程双证据。
- 异动查询区分就职、调动、退休、离职、复职和就职未满期限，并返回人员清单及统计数字。
- 合同新建包含编号、日期、类别、期限、试用期、薪资、状态和续订；提醒系统包含试用期与合同到期。
- Excel 导入覆盖人事、合同和奖惩，均要求先检验再导入；人事导入要求员工编号/所属部门映射并预置部门、职位、学历等字典，集团版还需选择目标公司/部门；合同/奖惩日期格式和类别必须校验。
- 工资项目类型含数值、字符、日期；数据来源含上月继承、每月变动、自动计算；系统可生成应发小计、应扣小计、实发工资、个人所得税四类公式。
- 工资数据维护支持新增、批量条件修改/删除、计算和刷新。新系统拒绝无幂等键、无审批、无逐行结果的危险批量写入，但保留业务能力。
- 工资报表包含工资表、工资单、汇总、统计图，并支持部门、输出列、栏宽和 Excel；银行报盘格式可定义。新系统将导出、打印、报盘拆成独立权限。
- 培训记录包含员工号、课程、开始/结束、评定、测试和费用；课程、记录、经费分别可查询。
- 奖惩可按日期期间和类别组合查询，导入前必须与奖惩类别匹配。
- 绩效支持年度/季度/月度方案、项目权重、结果统计/图表/打印，并从考勤和奖惩导入来源数据。
- 提醒还包含生日、父母生日、证照到期和工作年限，并支持提前天数；新系统使用统一提醒规则/实例/已读/处理状态和权限审计。
- 旧系统初始化可清除全部数据且仅管理员可用；该破坏性能力不得复刻为普通 HR 页面，生产初始化/恢复必须使用独立受控运维流程。

## 6. 未完成清单

### 6.1 客户端版与集团 Web 版的独立边界

- 现场确认集团 Web 是 IIS 6 上的独立经典 ASP 站点，拥有独立登录页、站点目录和 Web 会话；它不是客户端页面的浏览器外壳。
- 客户端版承担 HR 专员/管理员的档案、异动、合同、工资、考勤、保险、绩效、培训、奖惩、招聘及系统配置等完整操作流程。
- 集团 Web 版使用 `person.loginid/password/allowlogin`、`sysTab`、`func`、`Web_GetSysTab`、`Web_GetUserRight` 和 `web_*` 查询过程，承担员工自助、经理/集团范围查询以及按 Web 菜单授权的功能。
- 客户端系统管理员身份不能替代 Web 自助登录身份；现场验证该身份未获得 Web 会话。因此两端必须分别建立角色、菜单、字段投影、数据范围、动作和审计矩阵，任何一端的页面证据不得替代另一端。
- 当前仅完成 Web 独立站点及登录入口的 L3 运行时确认；登录后菜单和 HR/经理/员工角色仍待使用有效 Web 身份逐项脱敏遍历。
- 结构化数据库目录确认 Web 菜单至少包含 15 个独立入口：人员浏览、人员照片、信息查询、人事异动查询、人事异动统计、合同到期查询、培训记录查询、考核记录查询、奖惩记录查询、保险福利、工资数据查询、考勤管理、招聘管理、用户列表和修改密码。该清单是 L2/L3 结构证据，不等于登录后页面已完成现场验收。
- Web 权限由 `Web_GetUserRight(username, programunit)` 查询 `Rights.authorise`，菜单由 `Web_GetSysTab(tabid)` 按 `indexid` 排序生成；旧客户端系统管理员账号不能直接获得 Web 会话，进一步证明客户端用户与 `person.loginid/password/allowlogin/manageruser` 自助身份是两套认证和授权边界。
