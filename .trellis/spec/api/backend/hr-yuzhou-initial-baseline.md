# Evidence-bound initial employee / contract field baselines

Applies to shared incremental witnesses, DTOs, offline package helpers, original receipt verification and migration 329.

- Witness version 1 is a complete original v1 canonical target projection: all scope and canonical fields, including original dependency UUIDs. Hash with the original domain prefix/table and original canonical JSON algorithm, including JavaScript integer-key ordering. Contract source_snapshot is authenticated even though not writable. Keep a parity test against the original model/writer.
- Authenticate exact record -> projection receipt -> batch -> active map, successful operation/phase/batch, original scope/canonicalization and no rollback. Resolve every original dependency from its exact receipt chain; ambiguity fails closed. There is no per-record payload hash in the database.
- Source comparison facts are derived only from verified original projection fields; current target version is only CAS evidence. Never infer original fields from modern values, employee names or separately asserted client facts. Do not reinterpret formalDate. Profile/T5 restoration requires distinct proof and is excluded.
- Preview may persist the existing encrypted package operation, but must not write baseline or business records. Commit serializes the same source identity, atomically appends immutable encrypted provenance and runs the ordinary three-way/CAS path. No original receipt/map rewriting or T0-T5 replay.
- Unknown rows with old conflict revisions may be anchored; successful accepted revisions may not be rebaselined. A repeated identical witness reuses the accepted baseline; different witness bytes reject. Preserve original revision history. New source facts, original witness/projection, baseline state and revision snapshots remain encrypted at rest.
- Source-unchanged fields do not overwrite modern edits; changed same-field modern values conflict. Real source status transitions require normal workflows, even when modern status already matches. Non-draft contract field changes remain protected. Baseline-only acceptance is unchanged with no business version increase.
- Shared transport limits are 2000 items and 8388608 bytes. Increase JSON parsing only for the preview path with a separately named middleware wrapper, preserving Nest ordinary JSON parsing and default limit. Real Nest HTTP tests prove legal >100 KiB, >8 MiB rejection, and ordinary JSON parsing/100 KiB rejection.
- Offline builders count the exact serialized UTF-8 JSON + newline, including witnesses, envelopes and batch IDs. Split by bytes and count, fail on an oversized single item, and preserve deterministic dependency order. File outputs are exclusive 0600 under 0700; public output contains no personal rows.
- Real PG tests use fresh guarded loopback-only named databases, current_database assertion and residual-zero cleanup. Apply actual original receipt migrations, hash fixtures with the original writer, exercise independent connections and post-write failure rollback. Synthetic tests never prove production acceptance.
