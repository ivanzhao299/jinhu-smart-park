## Findings

### Existing API path and enforced sequence

The current API already provides the formal path; no missing calculate endpoint or arithmetic engine was found.

1. **Rule preparation/review:** `/hr/payroll/rules` supports book options, source-reference read, rule-set creation, version create/update/submit, independent version review, and effective-rule lookup. `HR_PAYROLL_MANAGE` authors; `HR_PAYROLL_FORMULA_REVIEW` reviews; effective lookup is rule-read. See `apps/api/src/modules/hr/hr-payroll-formal-rule.controller.ts:17-41`; service methods at `apps/api/src/modules/hr/hr-payroll-formal-rule.service.ts:75,121,183,218,231,257`. A rule set must be linked to the matching modern book and its reviewed version must be effective for July. Existing formula review tooling/spec supplies legacy formula/source context but does not itself create a modern effective rule: `.trellis/spec/api/backend/hr-payroll-formula-review-workflow.md` and `.trellis/spec/api/backend/hr-payroll-formal-rules.md`.
2. **Frozen source and full roster:** `/hr/payroll/inputs/preparation` accepts `reconciliationSourceId`; source mode locks/revalidates source, month, effective rule, current employee cohort and roster. Optional direct source-value fill is explicitly opt-in and park-scoped. See `apps/api/src/modules/hr/hr-payroll-formal-input.controller.ts:20-21`, `apps/api/src/modules/hr/hr-payroll-formal-input.service.ts:182-212,237`, and `.trellis/spec/api/backend/hr-payroll-formal-rules.md:108-135`. Create/update input then `POST /hr/payroll/inputs/:id/confirm` creates the separately reviewed confirmation; authors cannot confirm their own input (`hr-payroll-formal-input.service.ts:262-303`).
3. **Whole-month trial:** `GET /hr/payroll/trial-comparisons/options` reports source census, frozen sources, confirmed inputs, and item versions. `POST /hr/payroll/trial-comparisons` calculates both selected books transiently, compares modern totals/items against frozen legacy values, audits metadata, and persists no payroll run or payslips. Controller permissions and route are `apps/api/src/modules/hr/hr-payroll-trial.controller.ts:12-21`; transactional validation/calculation is `apps/api/src/modules/hr/hr-payroll-trial.service.ts:25-49,74-116,119-186`. It requires exact complete book set, current receipt, available/unambiguous rows, source-to-book/month match, latest confirmed input, and exact roster (`:130-150`). Result holds per-book source/input/rule/calculation hashes and record-level item differences (`:171-186`).

The separate formal payroll-run workflow (`/hr/payroll/formal-runs`, `hr-payroll-formal-run.controller.ts:14-35`) creates/reviews/confirms a persisted formal run. It is not needed for the requested **calculate-only** journey and would exceed it. Do not create/cancel a formal run to simulate a trial.
