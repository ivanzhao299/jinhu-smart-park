# Design
Use a small route-local typed preparation intent from actual PayrollTrialOptions book and selected actual source period. HrPayrollClient owns intent/last selected trial period in the existing authenticated workspace, keyed by identity/scope. Thread callbacks through PayrollModernOperations and PayrollTrialComparison; clicking the explicit book action switches to existing rules area, preserving only selection intent. RuleMaintenance receives optional intent/return handler and continues existing ordinary behavior when absent.

Context resolver uses existing read APIs, not a new backend. Reuse collectScopedExport complete bounded pagination with token/abort/current checks (rule page100, cap2000; book candidates same bounded mechanism if needed). Resolve unique sourceBookId; then lookup exact fresh unlinked book via keyword scheme and exact ID/scheme check. Existing scoped API metadata is advisory; the create endpoint retains authoritative uniqueness, scope and audit. Read failure/overflow/drift/unavailable target blocks contextual create and offers retry, never clears intent into standalone create. If linked rule exists open it; no default choice of rule revision or approval month. No unconditional arbitrary-book navigation or UUID UI.

On contextual success use returned association, existing source-reference editor/CSV, save/review unchanged. New return controls disabled during write. After return restore selected period only if authoritative options still contain it and reload whole-month books; do not reuse prior result, versions or financial drafts. Changing selected period or auth/scope clears incompatible intent. No persistent browser storage.

Use DS panel/action/record layouts and small route-local intrinsic layout only. No new financial math, API or schema changes. Verify entry/read/create/return as actual component interactions, not source-string assertions.
