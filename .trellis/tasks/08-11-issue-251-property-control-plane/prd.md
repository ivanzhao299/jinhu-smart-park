# Issue #251 共享房产控制面与住房长租房源资格校验

## 1. 背景

共享房产底座已具备 `asset_unit` 与 `biz_unit` 的显式映射、经营模式配置、统一占用账本、模式切换审批、数据范围校验及数据库级占用防重叠约束，但产品层仍存在两个缺口：

1. Shared/API 已声明经营配置、占用记录和模式切换审计能力，Web 端没有对应的资产控制面页面和菜单入口。
2. 住房租约房源候选查询只按租户、园区、数据范围和软删除状态筛选，尚未限制为当前启用且可用于长租的合格房源；历史不合格草稿也缺少稳定的资格说明与前置阻断。

权威需求跟踪：[GitHub Issue #251](https://github.com/ivanzhao299/jinhu-smart-park/issues/251)。

## 2. 目标

- 提供 3 个独立共享房产控制面页面，并从房源详情提供快捷入口。
- 允许授权岗位创建人工维修/运营锁房、普通释放人工锁房，并通过审批强制释放业务占用。
- 保证所有经营模式切换均创建审批请求，不存在免审批路径。
- 住房租约只允许选择当前合格的长租房源，并在关键生命周期阶段重复校验。
- 保留历史不合格草稿，明确展示资格阻断原因，修复经营配置后可继续原流程。

## 3. 产品决策

### 3.1 页面结构

- `/assets/property-operations`：房源经营配置列表。
- `/assets/property-operations/[unitId]`：单房源经营详情、配置和模式切换申请。
- `/assets/property-occupancies`：统一占用列表及人工锁房入口。
- `/assets/property-occupancies/[occupancyId]`：占用详情、普通释放或强制释放申请。
- `/assets/property-mode-transitions`：经营模式切换聚合审计。
- `/assets/units` 房源详情提供经营配置和占用记录快捷入口，不将三个控制面挤入同一超大抽屉。

### 3.2 长租房源资格

住房租约候选必须同时满足：

- `biz_unit.status = 1`；
- `biz_property_operation_config.operating_mode = 'long_rent'`；
- `biz_property_operation_config.status = 'enabled'`；
- 位于当前租户、园区及用户数据范围内。

候选接口不因缺少租期参数而猜测未来占用；创建/提交时按租约起止日期校验占用冲突，后续关键阶段再次校验。

### 3.3 人工占用与释放

- 首期允许创建 `maintenance` 和 `operations` 来源的人工占用。
- 人工占用可由具备普通释放权限的岗位直接释放，必须填写原因并保留审计。
- `homestay`、`housing_rental`、`commercial_leasing` 等业务占用只能由来源业务流程释放，或申请审批式强制释放。
- 强制释放必须具备强制释放及审批创建权限；审批执行重新校验版本和效果清单。

### 3.4 模式切换

- `none`、`short_stay`、`long_rent` 之间的所有切换均走审批。
- 申请时记录阻断快照、当前版本和业务意图键；执行时重新加锁并校验，陈旧审批不得落地。
- 不提供管理员、超级管理员或任何角色的免审批快捷路径。

### 3.5 历史草稿兼容

- 已有不合格租约草稿继续可见，不删除、不自动改房源、不自动改变状态。
- 列表和详情返回资格状态及稳定原因码。
- 提交时提前阻断；审批执行、签署和激活阶段重新校验，避免配置变化或并发占用绕过。
- 操作人员通过房源控制面修复经营模式/状态后，可继续原租约流程。

## 4. 功能需求

### 4.1 经营配置控制面

- 按关键词、楼栋、配置模式、经营状态和阻断码筛选。
- 展示房源编码/名称、资产映射、模式、状态、生效时间、暂停原因、当前有效占用和阻断摘要。
- 配置更新要求幂等键、版本控制和完整审计。
- 模式切换按钮只创建审批请求，并展示待审批、已执行或失败结果。

### 4.2 占用控制面

- 按房源、来源域、来源类型、状态和时间区间筛选。
- 展示半开区间 `[start_at, end_at)`、保留到期、版本、释放信息和来源记录。
- 创建人工锁房前执行可用性检查；重复请求遵循幂等重放/冲突语义。
- 普通释放与强制释放在页面上按来源域和权限明确区分。

### 4.3 模式切换审计

- 提供受权限和数据范围保护的聚合查询，避免按房源逐个请求。
- 支持房源、原模式、目标模式、审批状态、执行状态和时间筛选。
- 展示原因、申请人、审批与执行时间、版本和阻断快照摘要。

### 4.4 权限与数据范围

- 三类页面要求 `asset` 模块和各自页面权限。
- 列表按允许房源集合过滤；越界详情使用既有非泄露式拒绝策略。
- 普通释放、强制释放、人工占用创建/激活、经营配置修改和模式切换各自使用精确权限。
- Shared 端点清单、API 装饰器、服务断言、权限包和 Web capability 必须一致。

### 4.5 页面质量

- 使用全局 Design System surface classes。
- 桌面使用表格，390px 移动端提供卡片记录且无横向溢出。
- 覆盖加载、空态、错误、权限拒绝、陈旧版本、离线提示、表单校验、键盘焦点和可读标签。

## 5. 非目标

- 不合并物理资产表与经营房源表。
- 不增加房间或床位级库存。
- 不重写民宿订单、住房租约或商业租赁状态机。
- 不开放业务占用的直接普通释放。
- 不访问生产环境、不自动部署、不声明 `production_ready`。

## 6. 验收标准

- [ ] 三个控制面页面及两个详情页面可由授权菜单访问，房源详情快捷入口正确。
- [ ] 页面路由、页面权限、模块依赖、首发白名单和端点清单通过共享契约测试。
- [ ] 列表按租户、园区、楼栋、楼层和房源范围过滤；越权详情非泄露式拒绝。
- [ ] 任意经营模式切换均生成审批请求，执行前重新校验版本、当前模式和阻断快照。
- [ ] 人工维修/运营锁房可创建和普通释放，原因与审计完整。
- [ ] 业务占用普通释放被拒绝；强制释放只能通过审批，陈旧审批无副作用。
- [ ] 住房候选只返回状态启用、`long_rent`、经营状态 `enabled` 且在数据范围内的房源。
- [ ] 租约提交按租期检查资格与冲突；审批执行、签署和激活重新检查。
- [ ] 历史不合格草稿保持可见，并返回稳定资格原因码和可操作提示。
- [ ] API/Web/Shared 专项测试、lint、typecheck、build 和必要回归通过。
- [ ] 本地隔离环境完成桌面与 390px 真实浏览器验收；证据绑定最终被测 commit。
