# Design

Modify the existing execute-production-import.mjs only at the plan-specific limit and load site. Export the constant MAX_SEALED_PLAN_BYTES for boundary tests; no config override. 384 MiB is finite and below the Node/V8 single-string ceiling; compared with the demonstrated ~253 MB T3 plan it leaves room for the lighter phases and metadata. It is not a promise that any plan within this cap fits the production process heap; final real-plan read-only preparation must measure that separately.

Keep all file ownership/mode/single-link/no-follow/change checks, SHA-256 checks, cumulative actual-read accounting, activation and authorization unchanged. Reuse execute-production-import.contract.mjs fixtures rather than adding a new executor or permissive validator. Mandatory small tests use a sparse cap+1 file to prove preallocation rejection and existing read-budget test for exact byte boundaries. Optional env YUZHOU_SEALED_PLAN_LARGE_READ_TEST=yes appends JSON whitespace to a valid synthetic sealed plan to reach 65 MiB, updates only its byte descriptor SHA, uses the REAL plan validator, and records callbacks to prove no database/crypto/writer invocation. This exercises file read/hash/parse size acceptance, not 250k-record validation complexity. Write bounded chunks to avoid multiple giant fixture buffers. If useful return only bytes/timing/resource aggregates via test diagnostic; no private paths.

Docs must state the narrower proven acceptance, new plan limit and unchanged other limits; preserve the existing large-writer memory warning. No source data files or production artifacts are read or rewritten.
