# 园区餐厅 POS 触摸屏界面设计说明（pos-ui.md）

> 模块：园区餐厅管理（食堂承包经营）｜代码 slug：`canteen`
> POS 终端路由：`apps/web/app/canteen/pos`（全屏、横屏触摸）
> 配套静态原型：[`prototypes/pos.html`](./prototypes/pos.html)（可点击高保真原型）、[`prototypes/diagrams.html`](./prototypes/diagrams.html)（业务/架构/ER/状态机图）。
> 本说明与冻结设计基线 v1 口径一致：二维码收款=真实资金，员工餐补=虚拟账户核销；终端账号共用、补贴账户到人。

---

## 1. 设计目标

- **短路径收银**：点餐 → 选择收款方式 → 成功，主链路 ≤ 3 步；高峰档口减少收银员操作步数与误触。
- **大按钮、高对比、远可读**：触摸屏作业环境（戴手套/远距离/强光），所有触控热区与字号按 1920×1080 横屏设计。
- **两条收款链路清晰分流**：「扫码收款」（微信/支付宝真实资金）与「员工餐补」（虚拟核销，不走真实支付）并列为主按钮，另设「混合支付」入口。
- **离线/容错友好**：断网、支付超时、余额不足、售罄等异常有明确可见反馈与降级路径。
- **数据口径与基线一致**：订单 `channel=qr_pay/subsidy/mixed`、`qr_pay_amount` 与 `subsidy_amount` 分列；班次 `qr_pay_total/subsidy_total` 用于日结。

## 2. 适配硬件与规格类别

> 以下给规格类别与区间，不指定具体品牌型号；落地时按采购硬件实测微调。

| 项目 | 规格类别 / 建议区间 |
| --- | --- |
| 形态 | 桌面/壁挂电容触摸一体机，横屏全屏（kiosk 模式） |
| 目标分辨率 | **1920×1080（16:9）**；向下兼容 1366×768、向上兼容 1920×1200，均等比缩放居中、不变形不裁切关键操作区 |
| 屏幕尺寸 | 10.1″ ~ 15.6″ 电容触摸（多点）； POS 主屏按 1920×1080 栅格设计，运行时等比 scale |
| 触控热区 | **最小 ≥ 64×64 px**（原型主按钮 104px 高、加减键 44px 并加大点按容差）；相邻可点元素间距 ≥ 8px |
| 主字号 | 餐品名 20px、合计金额 40px、收款按钮 30px、金额大字 46~74px；正文不低于 15px |
| 对比度 | 正文与背景对比度 ≥ 4.5:1；主按钮用实色填充 + 白字，不用低对比描边按钮 |
| 可选外设（接口形态类别） | ① **小票打印机**：ESC/POS 类热敏，系统层提供打印服务，原型中以“小票已打印（可选）”标注；② **顾客显示屏（客显）**：同步显示应收/找零/支付结果，走串口/USB 虚拟串口；③ **扫码盒/扫码枪**：USB-HID 即插即用，用于扫顾客付款码与员工个人码；④ 钱箱由打印机/驱动触发 |
| 网络 | Wi-Fi/有线双链路；弱网时进入离线容错态（见 §6） |

## 3. 页面布局与区域尺寸（设计基准 1920×1080）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 76px：档口名/设备账号 · 收银员 · 业务日期/餐段 · 联网状态 · 开班/结班 │
├───────────────────────────────────┬──────────────────────────┤
│ 餐段页签 52px + 品类页签 46px         │  购物车栏 430px           │
│ ────────────────────────────────  │  · 清单（数量±/备注/删除） │
│ 餐品网格：4 列 × 行高 150px          │  · 商品合计/折扣占位       │
│ （餐品图占位 + 名称 + 价格 + 售罄态）  │  · 应付合计（大字 40px）   │
│ 区域自适应高度、纵向滚动             │                          │
├───────────────────────────────────┴──────────────────────────┤
│ 底部收款区 148px：本班次实时金额 │ [扫码收款] [员工餐补] │ 混合/退款入口 │
└──────────────────────────────────────────────────────────────┘
```

- 左/中部餐品区 `flex:1`，右侧购物车固定 `430px`；底部收款区固定 `148px`，两个主按钮等高、等宽、实色。
- 运行时对 `#stage(1920×1080)` 整体 `transform: scale(min(vw/1920, vh/1080))` 居中，保证任何常见笔记本比例下横屏布局完整、无横向溢出。

## 4. 完整交互流程

### 4.1 主流程：开班 → 点餐 → 收款 → 成功 → （下一位）→ 结班
1. **开班**：顶栏「开班」→ 生成 `cashier_session`（班次号 `CS…`），状态置“已开班”。
2. **点餐**：选餐段（早/午/晚）→ 选品类 → 点餐品加入购物车；数量 `＋/−`、单品备注占位（加饭/免辣）、删除、清空账单。
3. **收款（二选一主链路，≤3 步）**：
   - **扫码收款**：弹层内创建 `order(pending, channel=qr_pay)` → 展示动态收款二维码（原型为自绘矩阵占位）+ 金额 + 120s 倒计时 → 顾客扫码支付 → 回调/轮询到 `paid/completed`。
   - **员工餐补**：弹层内扫员工个人码/刷卡/输工号手机号 → 查询并展示脱敏员工（张*、工号）与当月额度/已用/剩余/到期提示 → 确认核销，写 `order(channel=subsidy,paid)` + `meal_record` + `wallet_txn(consume)`。
4. **成功反馈**：全屏绿色 ✓ + 金额 + “下一位”，点击后清空账单进入下一单。
5. **结班/日结**：顶栏「结班/日结」→ 展示本班次二维码收款合计、餐补核销合计、订单数、退款数 → 确认结班，上报管理端/财务端。

### 4.2 退款 / 撤单（入口与权限）
- 底部「退款/撤单」为受限入口：**收银员（canteen-cashier）仅可发起，canteen-admin 审核**。
- 规则对齐基线：`paid` 前可撤单（void_before_pay）；`paid` 后原路退（二维码退支付平台、餐补退回虚拟账户并写反向 `refund` 流水）。原型中以 toast 提示权限与占位，不直接执行。

## 5. 组件清单与各状态

| 组件 | 正常态 | 异常/边界态 |
| --- | --- | --- |
| 餐品按钮 | 图占位、名称、价格、可点 | **售罄/已下架**：灰底 + 蒙层“售罄/已下架”，禁用点击 |
| 购物车条目 | 数量±、备注占位、删除 | 数量减到 0 自动移除；空车引导文案 |
| 合计区 | 件数、商品合计、应付（大字） | 整单折扣/抹零为占位按钮 |
| 扫码收款弹层 | 二维码、金额、倒计时、模拟支付成功 | **倒计时≤30s 变红**；超时/点“超时关单”→ `payment=closed / order=cancelled` |
| 员工餐补弹层 | 员工脱敏卡、余额、确认核销 | **余额不足**：出现「餐补+扫码混合」与「全部扫码」两个分支；余额为 0/冻结给提示 |
| 联网状态 pill | 绿点“Wi-Fi 已连接·在线” | **断网**：红点“离线”，收款转容错态 |
| 班次状态 | “已开班”绿字 | “已结班”红字；未开班时点收款提示先开班 |
| 成功反馈屏 | ✓、金额、“下一位” | —（成功态唯一全屏） |
| 日结弹层 | 四项合计，确认结班 | 无进行中班次时拦截提示 |

## 6. 异常与容错
- **断网**：顶栏切红点离线；点餐本地暂存，待恢复后补单；收款类操作降级（二维码依赖在线，给出“请检查网络/改用现金登记”类提示），不允许在离线时虚假核销餐补余额。
- **支付超时**：倒计时归零自动关单（`closed/cancelled`），不挂死界面。
- **支付结果未知**：以后端 `GET /payments/{no}/status` 轮询 + webhook 验签幂等为准，避免重复收款。
- **餐补余额不足/并发**：余额不可为负（`CHECK period_balance>=0`），核销走事务 + 行锁/乐观锁（version）防并发超扣；余额不足给混合/全扫码分支。
- **无效/越权操作**：未开班、空账单收款、无权限退款均 toast 拦截，不产生脏数据。

## 7. 可访问性与误触防护
- 触控热区 ≥64px，可点元素间距 ≥8px，主按钮大而实色；危险操作（清空、确认结班）二次确认。
- 高对比配色，关键金额用大字 + 颜色双重编码（不只靠颜色区分）。
- 全屏成功态需主动点“下一位”才关闭，避免收银员误以为已完成而漏单。
- 弹窗遮罩点击 × 或取消才关闭，防止误触穿透到主屏。

## 8. 多角度界面清单
1. **点餐主屏**：顶栏 + 餐段/分类页签 + 餐品网格 + 购物车 + 底部双收款按钮。
2. **扫码收款弹层**：动态二维码、应收金额、倒计时、模拟支付成功/超时关单。
3. **员工餐补弹层**：员工识别输入 → 脱敏信息与钱包额度/已用/剩余/到期 → 确认核销；含余额不足混合分支。
4. **支付成功全屏反馈**：✓、金额、子说明、“下一位”。
5. **结班/日结弹层**：二维码收款合计、餐补核销合计、订单数、退款数、确认结班。

> 以上界面在 [`prototypes/pos.html`](./prototypes/pos.html) 中可直接点击切换；端到端流程、模块集成、16 张表 ER 与状态机见 [`prototypes/diagrams.html`](./prototypes/diagrams.html)。

## 9. 生产终端技术与样式策略

> **定位说明**：[`prototypes/pos.html`](./prototypes/pos.html) 是**目标作业界面的设计/交互基线**（布局、信息架构、流程、异常态以此为准）。若选用成熟开源 POS/收银终端，可将其原始 UI 直接落地，或按本原型做适配；不要求把它改造成管理后台样式。

POS 触摸屏是**高频专用作业终端**，不强制套用 `@jinhu/ui` 管理后台原语，也不必硬造 PageShell 式后台组件。选型判断标准是**作业效率、触摸可用性、稳定性与性能**，而非是否符合后台 Design System。

### 9.1 三种落地策略（三选一，择优）

| 方案 | 做法 | 适用 / 取舍 |
| --- | --- | --- |
| ① 直接复用成熟开源 POS/收银终端 UI | 采用成熟开源收银终端的界面与原始样式，仅做业务对接与品牌适配 | 上线最快、触摸交互经长期验证；需评估其技术栈与本仓库 Next/Nest 体系的集成成本、维护与授权 |
| ② 在开源终端基础上二次开发 | 以开源终端为底座，改造点单宫格、购物车客单、数字键盘、结算页，并接入本模块 API | 平衡效率与贴合度；适合需要深度定制餐补/分账流程时 |
| ③ 独立现代化设计 | 按本原型从零实现现代化触屏终端 UI | 完全贴合业务与品牌；成本最高，需自行打磨触摸可用性与性能 |

> 无论选哪种，核心作业区必须具备：**大按钮点单宫格、右侧购物车客单、数字/金额键盘、独立结算页/弹层**，并满足 §9.3 的硬性指标。

### 9.2 品牌统一与组件复用策略（轻量）
- **只做轻量统一**：在**品牌色、Logo、必要设计令牌**（主色、关键状态色、圆角、字号阶梯）层面与全局对齐即可；不要求改成 `PageShell/PageHeader/FilterPanel` 等后台原语，POS 可以保有自己的触摸式视觉语言。**终端允许复用开源/原始样式**，不做“不得照搬内联样式/硬编码色值”式一刀切。
- **后台 Design System 的硬性约束对终端不强制**：例如“禁 Tailwind、globals.css 不得加页面级选择器、全部走 `ds-*` 原语”等条目是**管理/表单页面**的要求；POS 终端**仅做品牌色/Logo/必要令牌轻量统一**，技术栈与样式可随所选开源终端。
- **`@jinhu/ui` POS 原语由“必须新增”降级为“可选抽取”**：下列组件（`PosShell / PosTopBar / PosCategoryTabs / PosProductGrid / PosProductButton / PosCart / PosCartLine / PosPayBar / PosModal / PosKeypad / PosSuccess / PosShiftClose`）仅在**多终端复用确有价值**（如另有自助点餐机、移动收银端共用点单/购物车逻辑）时，才在 `packages/ui` 内实现；**不为合规而硬造**。**也可直接采用成熟开源终端 UI，不抽取这些原语。**
- **与后端契约不变**：前端形态自由，但数据口径仍遵守基线——订单 `channel=qr_pay/subsidy/mixed`、`qr_pay_amount` 与 `subsidy_amount` 分列；终端账号共用、补贴账户到人。

### 9.3 保留并细化的硬性体验与性能指标
- **横屏 16:9**：目标 1920×1080，运行时等比缩放居中，不裁切关键操作区，常见笔记本比例下不错乱。
- **触控热区 ≥64px**，相邻可点元素间距 ≥8px；主按钮大而实色、高对比。
- **主路径 ≤3 步**：点餐 → 选收款方式 → 成功。
- **首屏与渲染性能**：首屏只拉取当前 outlet 的品类与在售餐品；点单宫格用虚拟列表，改数量只局部重渲染购物车条目，避免整屏 diff；图片懒加载。
- **轮询节奏与退避**：支付状态轮询 `/payments/{no}/status` 先密后疏、成功即停，并以 webhook 验签幂等为准，不常驻高频请求。
- **断网容错**：点餐本地暂存、恢复后补单；离线禁止虚假核销餐补；联网状态实时可见。
- **误触防护**：危险操作（清空、确认结班）二次确认；弹窗需主动关闭；成功态需点“下一位”才进入下一单，避免漏单。
- **多角度界面清单**：点餐主屏、扫码收款弹层、员工餐补弹层（含余额不足混合分支）、支付成功全屏反馈、结班/日结弹层——均见 §8 与 [`prototypes/pos.html`](./prototypes/pos.html)。

### 9.4 边界：管理/表单类页面仍严格走全局 Design System
本放宽**仅适用于 POS 高频作业终端**。以下管理与表单类页面仍**严格遵循全局 Design System**（`@jinhu/ui` 后台原语、globals.css 令牌），不受本节放宽影响：
- 餐品/品类管理（上下架、定价、库存）；
- 订单与流水查询、退款/撤单审核；
- 承包方月度结算对账、差异处理、审批与付款凭证；
- 经营报表（销售/日报/菜品排行/餐补使用率）；
- 员工个人中心“我的餐补”表单与明细、出示个人码。

> 与冻结基线一致：订单 `channel=qr_pay/subsidy/mixed`、`qr_pay_amount` 与 `subsidy_amount` 分列；终端账号共用、补贴账户到人。
