# 完善用户角色配置闭环

GitHub Issue: https://github.com/ivanzhao299/jinhu-smart-park/issues/260

## Goal

把后端已经存在但未接入 Web 用户管理的用户—角色绑定能力补齐，使授权管理员可以在新增、编辑用户时查看和配置当前租户/园区作用域内的角色，并保持角色权限、数据权限和字段策略继续由角色管理统一维护。

## Confirmed Facts

- `sys_user` 通过 `rel_user_role` 关联 `sys_role`，角色再通过 `rel_role_perm` 关联权限。
- 后端已有 `POST /users/:id/roles`，要求 `system:user:assign-roles`、幂等键并记录“角色变更”审计日志。
- 用户新增/编辑 DTO 和 `UserView` 不包含角色；Web 用户管理没有加载、展示或提交角色。
- 角色管理负责角色 CRUD、功能权限、数据权限和字段策略，不负责用户归属。
- 当前分配服务先软删旧链接再写入新链接，但没有显式事务。
- 平台角色不属于普通租户/园区角色候选范围，不能通过该入口下放。

## Requirements

- 为用户管理提供当前用户角色读取契约，返回角色 ID、编码、名称、范围和状态所需的最小信息。
- 用户新增与编辑抽屉提供角色多选；候选只包含当前目标租户/园区内可分配的启用角色。
- 只有拥有 `system:user:assign-roles` 权限的操作者可以查看可编辑角色控件并提交角色变更。
- 新增用户成功后调用独立角色分配接口；编辑时账号资料与角色变更分别按各自权限、审计和幂等契约提交。
- 用户列表展示角色摘要，编辑时回显已有角色。
- 角色替换必须事务化，失败时保留原角色集合。
- 保持现有用户 CRUD、角色管理、认证聚合与平台角色边界兼容。
- 桌面和 390px 手机宽度下可用，不引入横向溢出。

## Acceptance Criteria

- [ ] 授权管理员新增用户时可以选择一个或多个角色，保存后重新打开能正确回显。
- [ ] 授权管理员编辑用户时可以增加、移除角色，保存后登录授权按新角色生效。
- [ ] 没有 `system:user:assign-roles` 权限的用户不能调用分配接口，前端不提供可编辑入口。
- [ ] 角色候选不包含其他租户、其他园区的园区角色、停用/删除角色或平台角色。
- [ ] 清空角色有明确行为并可成功保存；活跃无角色用户仍只保留 current-user 基础权限。
- [ ] 分配过程中发生写入失败时，原角色绑定不丢失。
- [ ] 重复角色 ID、越界角色 ID 和超过数量上限返回明确错误。
- [ ] API 单测、Web 类型检查、相关 E2E、lint 和 build 通过。
- [ ] 用户管理页面完成桌面与 390px 视口实页检查。

## Out of Scope

- 不在用户管理中编辑角色所拥有的功能权限、数据权限或字段策略。
- 不允许租户管理员分配 platform 角色。
- 不改造为用户直接绑定权限；权限仍必须经角色继承。
- 不修改已执行的历史迁移，除非实现发现确实需要新的前向约束。
