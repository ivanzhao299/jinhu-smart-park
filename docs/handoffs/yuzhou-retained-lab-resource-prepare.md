# Dedicated retained lab resource prepare

The exclusively created container carries Compose service/project, `container-number=1`, oneoff=false and config-hash labels required by Compose exec selection. The config-hash value is the SHA-256 of this tool's generated `compose.json` bytes, retained as `composeSourceSha256`; it is not claimed to be Docker Compose's canonical configuration digest. This tool never invokes Compose up/reconciliation. Owner checks reject missing or changed selector labels before starting/migrating the container.

`prepareYuzhouRetainedLabResources({ runId, name, imageId, port, outputDirectory, capacityObserver, dockerHost })` creates fresh resources only. `name` follows the strict dedicated lab naming rule and identifies the new database/container/Compose project/volume/network. `imageId` is an already-local pinned SHA-256 image identity; no pulling is performed. `capacityObserver` contains an explicitly supplied existing legacy lab `container`, `containerId`, `imageId`, and loopback `port`, used only for capacity observation. Output must be a fresh private directory.

```sh
node scripts/hr-cutover/yuzhou-retained-lab-resource-owner.mjs --prepare --request /absolute/private/request.json --request-sha256 <sha256>
```

The request must explicitly supply a canonical local `unix:///.../docker.sock` endpoint, including a real Colima socket when applicable. lstat/realpath must prove a real non-symlink Unix socket owned by root or the current user; TCP/SSH endpoints are rejected. Every command and migration/seed Compose invocation uses the same DOCKER_HOST, never an inherited context or fallback. Socket device/inode are rechecked before commands. The receipt exposes only an endpoint identity hash, not its path. Observer inspection projects only identity/state/labels/ports, not Env. Existing host/Docker capacity thresholds are checked before creation using host statfs and the verified observer's df/du.

A fixed private per-user `.jinhu-hr-lab-resource-leases` directory holds exclusive daemon-ID plus resource-name leases shared across output directories/worktrees. Existing/stale leases are never stolen or deleted by prepare, including after failure. Lease identity and ownership contents are checked before commands. All created resources carry a unique owner nonce label, checked along with exact IDs before subsequent work. Volume idempotence cannot admit a foreign owner; containers use exclusive `docker container create` then exact-ID start, never `compose up` against an existing name. Compose is only used by the existing migration/seed exec scripts. Failed acknowledgements are not blindly retried.

Prepare creates a default local volume, dedicated bridge network and standard PostgreSQL container bound only to 127.0.0.1. The random password is stored only in mode-0600 `postgres.env`. `compose.json` references that file rather than embedding the secret. PostgreSQL starts with its maintenance database; the new database is explicitly created from template0. Existing `db-migrate.sh` and `db-seed-prod.sh` run with a controlled environment against this Compose file. No bootstrap admin, source extraction or historical loading occurs.

The strict resource descriptor is read back before and after migration/seed. The private `registry` directory receives the descriptor and receipt-last `prepare-receipt.json`. The public return value contains safe status/hash metadata; command output, Env, SQL and raw errors are not printed. Synthetic command injection is API-only and labeled in the receipt. Real CLI has no such injection.

Stage journals and `prepare-failure.json` retain observed identities privately. Partial failures do not delete anything automatically. A command acknowledgement loss may leave a resource whose final identity was not observed; the prior stage journal records the attempted dedicated name, and explicit read-only reconciliation is required. A failure is not a cleanup receipt. SIGINT/SIGTERM abort current commands and retain available evidence, not automatic cleanup.

No cleanup entrypoint is provided in this slice. A later cleanup owner must authenticate this registry/hash, verify current live identities and final side LAB_PASS rollback/residual evidence, then delete only registered container/network/volume objects in order and prove absence. Existing source artifacts, passwords/keys and audit files are not to be erased by guessed names or global prune. Preparation does not prove the seeded scope/count baseline; the existing readonly lab preflight remains required before a side run.
