# 修复安全管理 Issues 206-213

## Goal

修复 GitHub Issues #206–#213 覆盖的安全管理 UAT 缺陷，并通过共享数据加载、边界归一化和回归测试防止同类问题再次出现。

## Requirements

- #206：巡检点位新增表单的点位类型、风险等级可选择。
- #207：巡检模板新增表单的模板类型、状态可选择。
- #208：巡检计划新增表单的频率可选择。
- #209：巡检任务点击“执行”不得因 API 返回的受字段策略影响或异常形态数据导致整页崩溃。
- #210：从“超期隐患”页新增隐患后，新增记录应符合当前强制过滤语义并立即可见。
- #211：应急联系人新增表单的值守类型可选择。
- #212：应急事件转工单表单的工单类型、优先级、紧急程度可选择。
- #213：作业许可新增表单的风险等级可选择。
- 所有安全管理页面不得再通过分页的 `/dict-types` 列表将字典 code 转成 id；统一按 `dict_code` 使用共享加载器。
- 修改保持现有 API、数据库枚举值、权限和财务/生产安全行为兼容，不改历史迁移。
- 用户可见的现场作业页面继续满足移动端与共享设计系统基线。

## Acceptance Criteria

- [x] Issues #206、#207、#208、#211、#212、#213 涉及的选择器均由 `loadDictMapByCodes` 按 `dict_code` 加载，不受字典类型总数和分页顺序影响。
- [x] 安全管理目录内不存在业务页先请求 `/dict-types` 再请求 `/dict-items?dict_type_id=...` 的旧模式。
- [x] 巡检执行表单能安全处理数组、空值和字段策略返回的非数组/非数字值，不发生 `.join` 或 number input 运行时崩溃。
- [x] “超期隐患”页新增记录默认标记为超期，保存后在当前强制超期列表可见。
- [x] 为字典加载、巡检执行输入归一化和超期新增语义添加可执行回归测试。
- [x] Web lint、typecheck、build 与相关单元测试通过；API/共享层检查按实际改动范围执行。
- [x] 桌面与 390px 级移动视口完成实际页面检查；若浏览器连接不可用，明确记录并以构建/测试替代。

浏览器连接器因当前 sandbox cwd 元数据不是连接器可接受的本地 URI 而无法启动。
本次没有布局/CSS 改动；使用生产构建、类型检查、lint 和目标回归测试替代，并在交付中明确记录。

## Out of Scope

- 修改历史迁移或生产业务数据。
- 重做安全管理页面视觉系统。
- 改变隐患超期的后端判定规则。
