# Modern formal position maintenance

Organization page mounts PositionWorkbench under the full authenticated user-context key, including tenant/park, permissions and data scopes. Read-only actors get scoped positions with HR_POSITION_READ; create/edit requires HR_POSITION_MANAGE. Candidate context uses /hr/positions/maintenance-options or /:id/maintenance, never directoryOptions or employee account data. Source metadata is omitted; origin does not limit ordinary editing.

Create and edit expose all15 business fields. Respect API lengths: code64/name100/family64/level32/authority-qualification-responsibilities1024/manual256/remark500; integer headcount0–100000, hierarchy0–32767, sort0–2147483647. Missing optional inputs become null; zero remains zero. Edit includes rendered expectedVersion and a reason. Do not let React action reset a rejected form: prevent submit and reset/remount only on explicit success continuation or explicit reload.

Synchronous write lock blocks navigation. Unconfirmed writes retain serialized original body and idempotency key, lock controls and navigation, and retry that body even when disabled controls are absent from FormData. Known validation/scope/version errors retain the draft and permit correction or explicit reload. Confirmed writes stay saved if list refresh fails; do not submit twice. Ignore old completions after identity change/unmount. Runtime malformed contexts/responses fail without presenting saved status.

Shared DS panels/buttons/form fields and hr-workbench grid are authoritative. Local CSS expresses only all-width record visibility, long-field grid span, action wrapping and44px targets. Card lists must remain visible on desktop; shared ds-mobile-record-list defaults alone hide them. Long text uses full-width rows to avoid uneven text/control whitespace. Actual component synthetic browser evidence covers desktop and390px iframe; it does not prove production role acceptance or exact real-device metrics.

Validation: actual component interaction tests cover15 fields/version/null/zero, creation correction, exact retry under disabled fieldset, stale version refresh, post-save read failure, bounds, read-only/malformed data and identity invalidation.
