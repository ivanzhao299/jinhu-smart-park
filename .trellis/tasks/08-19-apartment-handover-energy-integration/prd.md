# 公寓交接与能源计量闭环

## Goal

将公寓入住、退房交接中的水电底数写入统一能源表计与读数账本，使房号、入住记录、交接单、表计和后续计费使用同一身份链。

## Requirements

- 交接前按 stay 对应的统一运营房号加载启用的水表、电表，显示表计名称、编码、当前读数和单位。
- 交接提交按表计 ID 传读数；兼容现有单水表/单电表字段，但遇到同类型多表必须显式选择，不得猜测。
- 房号存在启用水电表时，入住和退房交接必须覆盖全部表计；无表计房号允许交接，但清晰提示尚未接入能源管理。
- 交接、能源读数、表计当前值和入住状态在同一数据库事务提交；任何一步失败全部回滚。
- 交接读数自动确认为正式读数，来源可追溯到唯一交接单；重试不得生成重复读数。
- 读数不得小于表计当前值；并发交接或表计变化必须在锁后重新校验并失败关闭。
- 后续能源查询可识别公寓入住/退房来源，交接详情返回生成的能源读数。

## Acceptance Criteria

- [ ] GET 交接表计接口严格按 tenant/park/stay/unit 返回启用的 WATER/ELECTRIC 表计。
- [ ] 入住与退房分别创建唯一、已确认的能源读数并更新表计当前读数。
- [ ] 缺读数、重复表计、跨房号表计、倒挂读数和并发变化均回滚交接状态。
- [ ] 无表计的存量/代管房兼容完成交接。
- [ ] Web 动态展示真实表计，不再把水电固定为两个与表计无关的输入框。
- [ ] 契约、隔离 PostgreSQL、API/Web lint/typecheck/build 与公寓回归通过。

## Out Of Scope

- 自动创建实体表计、能源单价、账单与应收；这些继续由能源模块管理。
- 气表、热表和公共分摊表的公寓交接。
- 修改既有已确认读数。
