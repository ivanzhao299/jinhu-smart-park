# 岗位编制人数字段的生产候选映射

## 事实链与修复

旧字段 `dbo.job.defpersons` → 抽取字段 `headcountLimit` → 现代字段
`hr_position.headcount_limit`。抽取脚本已经包含该字段，隔离 T0 装载器也保存它；
生产 T0 候选器此前固定赋值 `null`，会在准备载荷时丢失已有编制人数。
本片修复候选映射，不改变源抽取、数据库结构或生产执行开关。

- 有效 PostgreSQL int4 整数保留原值，包括 0；字符串数字允许前后空白。
- null、缺失和空白保持 null，不转换为 0。
- 非整数、布尔值、对象、非数字和 int4 越界进入 `POSITION_HEADCOUNT_INVALID` 隔离，
  不默默变成空值继续导入。依赖该岗位的员工也不得越过未解决依赖。
- 对来源中的有效负整数，本片不擅自改成 0 或删除；存储层允许有符号整数。
  这不是对负数业务含义的认可，业务解释仍须由旧规则和具体来源证据判定。

## 旧证据过期的审查

对照旧引用对应 Git 内容与当前主线逐项审查：

1. T0 lab loader：新增 JSON/NUL、整数/日期 cast 预校验，以及 trim/空串规范化；
   `headcountLimit` 到 `headcount_limit` 仍存在，没有新增旧 `realpersons` 的装载。
2. HR service：只改变敏感服务 import 位置，`workforceDecisionSnapshot` 报表逻辑未改。
3. HR permission contract：新增员工旧编码校验 helper，编制查询所需权限常量未改。

因此更新这些文件引用及候选器的关联引用，同时把“生产候选没有映射编制人数”改为
“候选已映射，但真实隔离装载和运行回读未验证”。不会因引用更新或合成测试而增加兼容积分。

## 明确仍未完成

旧 `u_job_r` 编制差异报表依然不是完整复现：`realpersons` 口径、超编/缺编分支不同的
`rightscope` 过滤、逐岗位五列投影、缺失部门名称和真实角色/API/页面运行都仍需闭环。
报表合同仍为 `GAP_CONFIRMED`、零兼容积分、`productionImport=HOLD`。

本片不读取真实人员数据、不写生产、不重跑 A/B 或工资提取；测试只覆盖合成字段、
实际候选生成代码和静态关联证据。真实源的合法/隔离数量不能从这些测试推断。

## 验证结果

- T0 artifact CI 入口：完整候选生成回归与 7 组纯测试通过。
- 合成完整生成：12、0、null、-1 保留；非法小数岗位被隔离，其 2,949 条合成员工依赖
  保持隔离，包括目标员工精确匹配的情况；其他 17 个合法岗位不受影响。
- 关联公司/编制差异/冻结清单/异动/进度/产品目标契约：59/59，通过且没有授予兼容积分。
- 既有 T0 抽取和装载契约、Node/Shell 语法、`git diff --check` 通过。
- 未安装应用依赖、未跑本地应用 lint/build，没有运行真实 PostgreSQL 或浏览器 UAT；
  本片没有 API/页面代码变更，不能用这些合成结果充当生产回读。
