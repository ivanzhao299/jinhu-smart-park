# Root 实施中边界核对

以下是对实施中实际代码的具体发现，均已发给实施者集中修复。它们不是最终审查结论；当前代码、实际PG/HTTP/页面结果和独立check优先，不按此表旧状态重做研究。

| 边界 | 已定位的初稿问题 | 具体通过条件 |
| --- | --- | --- |
| 日历窗口 | 仅构造businessDate所在年份；dueDate-window落在窗口，实际选中window至2window天后 | 2026-12-30/3天命中12-31和2027-01-01；当天及明天命中，窗口外排除 |
| 闰日 | 周年分支直接make_date在非闰年2/29会异常 | 生日和周年均按显式skip/feb_28/mar_1处理；周年满一年，未来源日期不成立 |
| 收件授权 | 初稿仅HR_MANAGER角色码及员工/经理绑定，未证明对应读取权限 | 当前有效身份、范围、权限同时成立；自定义窄HR角色可收件，缺权限不发送，不为验收扩大工单权限 |
| 历史回读 | 详情只返回列表项，无办理轨迹 | 按目标重新授权后返回并显示顺序不可变actions，含来源/关系失效原因 |
| 来源变动 | 初稿比较profile/employee整体version，普通姓名等变更会误取消日期事件 | 同生日/同入职日的非日期变更不取消；日期/当前任职/当前收件关系变更正确失效，不覆盖已办历史 |
| 真实动作主体 | 自动取消把recipient当作actor，可能伪造他人办理 | 记录实际触发者或明确系统主体，保留取消原因；读权限不借全园扫描修改无关业务 |
| 消息可达 | integrated WorkflowController消息端点要求workorder模块和WORKORDER_READ，独立HR适配则已有自己的reader | 复用已有消息服务，对窄HR/team/self提供本人HR来源消息入口；链接精确授权并能进入提醒，不扩工单范围 |
