# 公寓房源纳入与可用性闭环

## Goal

将公寓“新增房源”明确改造成把统一运营房号纳入公寓管理的流程，提供可分页、可筛选、可解释的候选服务，并保证候选展示与最终写入使用同一套资格规则。

## Requirements

- `GET /apartments/unit-candidates` 从固定 500 条数组升级为稳定分页响应，支持关键字、运营楼栋、运营楼层和仅可纳入筛选。
- 候选投影返回物理资产映射、房号启停、公寓配置、物业运营模式、当前/未来跨域占用、维修/运维占用和能源表计数量。
- 每条候选返回 `eligible` 与稳定机器码 `ineligibleReasons[]`，而不是只把不可用房号从结果中隐藏。
- `createRoom` 在锁定房号后复用同一资格判断并重验，拒绝过期候选、错范围、停用、已有配置、父级映射不完整和占用冲突。
- 集团自有房号（已声明 `asset_unit_id`）必须具有完整楼栋/楼层映射链；无资产映射的代管/外部房号保持兼容，但候选明确标识。
- 公寓管理状态切换同步公寓域保留占用：停用释放、恢复重建；存在活动/预留/待退住人员记录时不得停用或退出。
- 容量增加创建床位；容量减少只停用无历史床位，不删除历史，不允许低于当前活动占用或无法安全缩减。
- Web 将“新增公寓房源”改为“纳入公寓管理”，支持搜索、级联筛选、分页、不可用原因和资产来源展示。

## Acceptance Criteria

- [ ] 超过 500 个房号仍可通过分页/搜索访问，响应包含 `items,total,page,page_size`。
- [ ] 候选与最终写入对相同快照给出一致资格结果；并发变化在写入事务中失败关闭。
- [ ] 不可用原因至少覆盖已有公寓配置、房号停用、父级资产映射不完整、其他业务占用和停用中的物业运营配置。
- [ ] 停用公寓配置会释放公寓域保留占用，恢复会在重新检查冲突后创建/激活保留；活动 stay 阻断停用。
- [ ] 缩容不删除历史床位，所有状态变化可审计且不破坏既有 stay 外键。
- [ ] API/DTO/服务回归、PostgreSQL 状态机测试、Web 类型/规范和相关公寓契约通过。

## Out Of Scope

- 本任务不生成能源读数；能源交接闭环在后续子任务完成。
- 不自动批量关联存量物理资产与运营房号。
- 不删除旧 `biz_unit`、`asset_unit` 或公寓历史记录。

## Compatibility

- 旧的不带查询参数调用继续返回第一页，但响应由数组升级为分页对象；本仓库 Web 同步切换。
- 保留现有 `CreateApartmentRoomDto` 核心字段与公寓权限。
