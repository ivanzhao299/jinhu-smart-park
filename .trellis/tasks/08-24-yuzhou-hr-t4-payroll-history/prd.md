# 玉舟工资历史兼容与双轨核算

## Goal

在不改变旧工资结果、不启用正式发薪的前提下，把玉舟集团版 46,092 条历史工资、35 套动态工资表、711 个工资项目、244 条公式、1,431 条月度关账记录、647 条员工到账套关系和 9 条旧税率证据迁入金湖 Smart Park 的规范化、可审计模型；同时建立新旧双轨核算与差异复核能力，为后续正式工资切换提供可验证基线。

## User Value

- 员工可按本人权限查看已确认的历史工资条，不暴露他人或内部迁移字段。
- HR 可按期间、账套、组织和员工核对历史结果、异常公式及差异原因。
- 薪酬专员可在“只算不发”模式运行新规则，与旧结果逐项对账，不影响旧系统和生产发薪。
- 审计人员可追溯每个金额的旧表、旧行、工资项目、公式版本、迁移批次和复核结论。

## Confirmed Facts

- 旧系统使用 `salary01..35` 动态宽表；真实只读库逐表 `COUNT_BIG(*)` 合计 46,092 行、覆盖 2010～2026。`sys.partitions` 的 46,095 是近似统计，不得用于迁移守恒；另有 711 个工资项目、244 条公式、1,431 条月度关账记录、647 条员工到账套关系和 9 条旧税率证据。
- 历史工资必须按旧系统已确认结果原样迁移，禁止用现行税法或新公式重算后覆盖。
- Jinhu 已有 `hr_compensation*`、`hr_payroll*`、`hr_payslip*` 基础，以及 M6 考勤月结工资输入快照，但不足以表达旧动态工资项、公式解析状态和逐项差异。
- T4 仅交付历史兼容与双轨核对，不启用银行代发、税务申报、正式发薪或生产旧库写入。

## Requirements

- 设计工资账套、工资项目、公式版本、历史工资条明细、迁移来源、人工复核队列和差异账的规范化模型；不得复制旧动态列结构。
- 保留旧账套、期间、工号、原工资项目名/顺序、金额、状态、关账语义和可核验来源；内部主键使用新系统标识。
- 历史工资条及明细一旦装载即不可原地修改；纠错必须使用新迁移批次或更正版本并保留前后链路。
- 旧公式转换为白名单受限 DSL，仅允许登记变量、数值、四则运算、比较和条件分支；禁止 SQL、任意函数、循环、动态标识符和外部调用。
- 无法安全解析、字段无法映射、金额不平或员工无法定位的数据进入隔离/人工复核，不得静默丢弃或猜测映射。
- 迁移守恒：已装载 + 已隔离 = 源记录；按表、期间、账套、员工及工资项校验行数与金额汇总。
- 双轨核算只能产生独立的新规则结果和差异账，绝不覆盖历史快照；默认关闭正式发薪、代发和对外通知。
- 工资读取采用本人/团队/园区/无权限的服务端范围和工资敏感字段权限；团队范围默认仅返回非金额的流程/异常摘要，部门负责人不得由团队范围推导工资金额权限。所有高敏感读取执行 required audit，审计失败阻断响应。
- 迁移脚本必须可重复演练、精确回滚本批次、重载后结果一致；日志不得输出完整工资明细、银行卡、身份证、手机号或数据库凭据。
- Web 工作台保持简洁：历史查询、异常复核、双轨差异三个生产工作面；手机端只提供本人历史工资条和必要摘要，不提供批量敏感管理。

## Acceptance Criteria

- [ ] 全量源 catalog/profile 明确 35 张动态表、工资项目、公式、关账记录及实际可迁移行数，并以 source backup SHA-256、catalog/file hashes 的受控 evidence manifest 绑定本次数字与不可逆校验摘要；源 hash 改变必须重新建立基线。
- [ ] 新增迁移为前向迁移且 migration number 无冲突；fresh、upgrade、重复执行和失败回滚均在隔离 PostgreSQL 通过。
- [ ] 历史工资总数和金额按源表/期间/账套守恒，`loaded + quarantined = source`，抽样明细可追溯至旧来源。
- [ ] 公式解析结果明确区分 `parsed/manual_review/rejected/approved_for_simulation`；解析成功不等于获准执行，只有人工批准为 `approved_for_simulation` 的白名单 AST 可在模拟环境执行。
- [ ] 历史快照不可变；更正、重载和双轨计算不会更新旧工资条或旧明细。
- [ ] 双轨差异可按员工和工资项展示旧值、新值、差额、公式版本、输入来源和复核状态，且“只算不发”由服务端强制。
- [ ] HR、部门负责人、员工三类角色的页面、动作、字段和数据范围最小授权测试通过；负责人团队投影不含工资金额，除非后续新增独立显式金额权限；无权限路径 fail closed。
- [ ] 工资明细 API 使用显式字段投影和 required audit；日志、错误、通知与消息体不泄露敏感金额明细或身份数据。
- [ ] API/Web 定向测试、全仓 lint/typecheck/build、数据库真实门禁、生产 seed 重放、桌面与手机视觉检查通过。
- [ ] 发布前再次完成本地候选、远端合并提交、生产运行提交三端一致；健康、就绪、受保护账号和 Docker 清理均有证据。
