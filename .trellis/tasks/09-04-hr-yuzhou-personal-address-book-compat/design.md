# 玉舟个人通讯录兼容闭环：技术设计

## Boundaries

`hr_personal_address_book` 是 HR 领域的个人办公能力，不与园区租户联系人、安全应急联系人或共享通讯录表混用。共享身份、组织、RBAC、审计和文件服务仅按目标范围重新绑定；不得将旧系统共享账本或原表整表复制到目标库。

## Evidence-first discovery

在实现字段前，通过受控只读源分别提取客户端与 Group Web 的结构、页面和动作证据。每次采集绑定：当前候选代码（C）、受控恢复回执/快照（S）、版本化字段字典与动作映射（M）。产物仅保存哈希、相对来源标识、字段语义、枚举和脱敏的行为结论；不得保存联系人、私有路径或凭据。

Group Web 的 `legacyId=301` 为已知独立入口。客户端的“工作助手 → 通讯录”亦必须独立采集。两端字段或行为不一致时，以显式差异矩阵表达，不能互相推断。

## Target model and lifecycle

实现前由字典采集确定最终字段集合。原则模型为：

- 个人通讯录本体具有 tenant/park、owner employee/user、分类、状态、来源批次和审计归属；
- 联系人记录与分类/所有者关联，敏感联系字段走目标字段策略；
- 删除采用可审计归档/软删除，历史迁移回滚仅删除当前批次 active record map 可证明拥有的记录；
- 读/写均在 service 层进行 tenant/park、owner/data scope、状态及字段策略判定。

在线写操作使用幂等键和乐观/条件更新冲突语义。导出只有在旧规则确有对应动作且独立权限、审计和字段投影齐备时才开放。

## API and UI

提供 HR 命名空间下的查询、详情、创建、更新和归档端点。控制器声明页面/动作权限与审计元数据；服务端承担数据范围、字段策略、状态和冲突控制。Web 通过真实菜单项和受保护路由进入，使用共享设计系统表面，并提供桌面表格与 390px 记录卡、空态、加载、403/404/409、深链和恢复行为。

## Migration and rollback

历史载入不使用普通部署、seed 或数据库迁移入口。使用受控 loader：字段映射显式版本化、稳定源排序、批次记录映射、重复拒绝、事务化写入和来源=装载+隔离+批准忽略的守恒。A 与 B 串行使用不同隔离资源；每次都做技术 UAT、child-before-parent 逆序回滚和零残留检查。`productionImport=HOLD` 直到独立生产门禁满足。

## Security and rollback

不在日志、测试夹具、Git 或文档中保存原始联系人/薪资/凭据。字段白名单、最小投影、访问审计和导出审计必须由服务端强制。代码回退使用新的前向迁移或功能开关式禁用，不编辑已应用迁移；数据回退限于批次 record map 所有的目标记录。
