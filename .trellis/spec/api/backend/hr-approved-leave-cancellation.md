# Approved leave cancellation continuity

Use the dedicated `/hr/attendance/leave-cancellations` workflow, not mutation of the original approved leave. The current fact binds tenant, park, employee, original approved leave and its version, and one approval projection. Source must have explicit timestamps; historical undated leave cannot be guessed. Full/partial intervals are positive whole minutes, contained within the original, at most31days. No source retargeting.

Creation/edit/submit/resubmit/withdraw require self REQUEST or park OPERATE. Reviewer requires APPROVE plus park/team attendance read scope, with actual managed organization tree; no employee self review or creator review. Operation source paging uses these write authorities rather than broadly authorizing the read ledger. Scope mismatch, inaccessible sources and histories fail. Generic approval actions direct this payload kind to the dedicated entrance; a deferred database constraint also prevents committing an approval-only change.

All writes atomically append immutable history and required operation audit. Commands append approval actions and preserve return comments. Stable HTTP idempotency plus current version CAS, employee/source/current/approval locks and an exclusion constraint prevent duplicate effects. Review period months are locked before employee/source/current rows, conservatively including the preceding day month. Revalidate the current version after locking. Calculating months reject; affected review months reopen; closed input rows remain unchanged until an explicit correction.

Subtract only approved cuts bound to each original leave, then union remaining intervals against the saved scheduled window. Preserve existing fixed-day reference helper. Daily traces retain original sources and approved cancellation IDs/parents with source-bound-v1. Current implementation conservatively traces each bound cancellation on every daily fact touched by that original, so other days of the same leave can also require a refresh. Month freshness compares both complete source sets before calculation/close/correction; missing old cancellation trace is allowed only when no approved cancellation applies. Cross-month night shifts use actual saved schedules and the preceding work date.

Validation: actual ValidationPipe, real PostgreSQL lifecycle/history/source retention/self+creator+managed authorization/audit rollback/concurrent overlap/month advisory lock/review reopening/closed correction/cross-month night shift. Owned isolated DB only, all triggers enabled, no production synthetic rows. This modern workflow does not establish exact original GroupWeb field/rule equivalence or real-role production UAT.
