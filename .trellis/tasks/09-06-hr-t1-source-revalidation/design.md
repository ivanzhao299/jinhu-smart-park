# Design

Optional input.sourceManifestPath / --source-manifest is opt-in source semantic revalidation. Alternative input.targetInventoryPath / --target-inventory replaces --target-snapshot; exactly one target input, full inventory requires manifest. Current C/S/M validates full source manifest; all3T1stage files and manifest bound exactly, current event type and state usage recomputed from actual staged events. Existing committed event-type contract is semantic authority (sourceValue to targetValue etc, not merely the set of target enums); existing core eventStateTargets supplies shared current policy via tiny export. Original state package sourceSnapshot and actual type/state bytes must agree. Original state dictionary row hashes/aggregate/machine hash verified against ORIGINAL triple, then item semantics independently match current policy; original bytes untouched. Existing default path stays strict, not silently upgraded evidence.

Reuse full inventory validator and export existing validateT0 in production-t2-decision-candidates.mjs under an explicit reusable name without changing its implementation. Current T0 inventory SHA, source manifest canonical SHA, scope and code all bound. Reuse verified T0 employee IDs. For T1 target matching compute candidate business/canonical hashes against current inventory; all source duplicate business keys/derived IDs flagged before output. No first-match insertion. Exact target match retains real ID/version; mismatch review and no mutation. Existing output envelope retains targetSnapshotArtifactSha256 as target-evidence byte hash for compatibility; document full-inventory provenance and do not claim it is a legacy snapshot.

Bound private reads32MiB/file128MiB per invocation using existing bounded reader (allow manifest-declared zero safely); capture each input bytes once for parse/hash, owned single-link/no-follow0600 and dirs0700, mac path aliases canonicalized after lstat. CLI requires clean current migration code. Pure source verifier API confirmed with implementer so root can test directly. No SQL/source raw values/paths in reports.

Review found an actual T1 cross-layer mismatch: variable-fraction candidate, six-digit inventory, and millisecond/no-offset Date readback hashed differently. The new full-inventory path must use strict calendar-valid six-digit local wall-clock +08:00, matching existing inventory SQL. Writer T1 SELECT projects timestamp as an exact microsecond string, never a lossy JS Date; other offsets are not silently converted. Legacy default and T2 formats remain unchanged. Tests must produce inventory with its real materializer (not copy expected hashes), exercise writer readback, invalid timestamps and fixed-literal read-only PostgreSQL casts.
