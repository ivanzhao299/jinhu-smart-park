# Design

New pure module production-t3-policy-recovery.mjs exports recoverProductionT3LegacyPolicy(record). Reuse verifyProductionT3StagedRecord for wrapper/identity checks and existing buildLegacyInsurancePolicyItems for reviewed decimal semantics. Additional exact old shape and complete six-kind x two-variant checks are required. Raw reconstruct fields are id/des/rightscope from reduced source; variant1 four values map kind, kind_e, kind_p, kind_pc; variant2 maps those names suffixed2. Require strings or null for numeric source fields, reject unsupported blanks/numeric numbers, match canonical reconstructed 51-field object SHA to sourceRowSha256 before conversion. Never return reconstructed raw object in the public proof; normalizedRecord still remains private data.

Return { normalizedRecord, lineage, proof }. normalizedRecord keeps exact source wrapper, identity and raw row SHA, has detached source and six normalized current-layout items. lineage has six entries {insuranceKind, sourceProjections:[variant1,variant2 provenance], targetProjection:variant1 provenance}. All provenance uses shared phase helper exports and exact existing child discriminators. proof contains only version/status/source identity/source raw SHA/counts and normalized-content SHA, with productionImport HOLD; no source names/values/paths. Proof is integrity evidence, not external authorization.

The adapter has no file/SQL/network API. Do not auto-call it from existing default projector (old source stays visibly unresolved by default), and do not edit phase producer now: final candidate/phase assembly must consume normalizedRecords together, not accidentally mix old144 and new72 identities. Integration tests call recovery then projector and verify full field/dependency correctness and lineage. Parent sourceRowSHA remains truthful because all 51 original fields can be reconstructed for this domain, unlike other reduced T3 records.
