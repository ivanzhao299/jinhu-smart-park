# 资产单元字段语义与房源接入调查

## Goal

以可追溯的代码、数据库、文档、测试与 Git/PR 证据，核清资产单元“房间/房源信息”字段语义、民宿与长租房源资格链及其演进，并形成支持住宅与办公室长租的新接入方案决策报告。

## Requirements

- 仅调查、分析和撰写报告；不得修改产品代码、数据库、配置、运行环境或生产数据。
- 逐字段梳理资产单元业务字段，至少覆盖用途、出租状态、单元状态，并对照实体/DTO、数据库列、shared 契约与 Web 表单/展示/统计消费点。
- 核清 `property-operation-config` 的 mode、enabled/disabled、version、审批与运行时状态机。
- 全仓核查用途字段的所有业务消费者，判断其属于描述属性还是资格条件。
- 核清出租状态、资产单元状态、经营模式及租约/入住状态之间的驱动关系、冗余与冲突风险。
- 追溯“用途=住房”原始方案到 mode 驱动资格链的 Git/PR/Issue 演进，记录可验证时间线，不作臆测或价值判断。
- 明确民宿与长租 picker 的过滤条件全集、互斥机制，以及办公室用途单元当前能否进入长租候选。
- 分析新需求差距：长租覆盖住宅与办公室；民宿用途边界；用途与经营模式职责；出租状态维护语义；“住房出租”命名准确性。
- 比较 A（mode 驱动、用途纯属性）、B（mode+用途双条件）、C（用途驱动资格）及必要的改良/组合方案；逐项覆盖数据模型/迁移、shared 双端契约、picker 合同、UI/文案、审批链、风险与验证。
- 报告中明确列出需要用户/产品决定的事项并给出推荐。
- 交付报告路径为 `docs/reviews/asset-unit-field-semantics-and-intake-plan-2026-08-29.md`。
- 走独立报告分支、PR、至少一轮独立 review、CI、合并及 main 双绿闭环；不开实施 Issue。
- 不碰 HR 系列、不操作生产、不动他人容器或主 Chrome、不 force push、不伪造证据、不写入敏感信息。

## Acceptance Criteria

- [x] 报告包含字段现状矩阵，并为关键结论提供 `file:line`、commit、PR/Issue 或测试证据。
- [x] 报告包含经营配置状态机、两业务资格链、用途消费点、出租状态关系和冲突分析。
- [x] 报告包含按时间排序、证据可复核的语义演进史，并区分“代码事实”“文档承诺”“历史意图”。
- [x] 报告确认办公室用途当前的长租候选行为，并指出链路中所有住宅假设。
- [x] A/B/C 方案均覆盖用户要求的七类影响，并提供横向对比、推荐方案及决策清单。
- [x] Git diff 只含该 investigation 任务材料、报告及必要的 Trellis 收尾记录；无产品代码改动。
- [x] Markdown/链接/引用与相关只读验证通过，独立 review 结论已处理或记录。
- [ ] 报告 PR 合并，main 分支所需 CI checks 双绿；未创建实施 Issue。
