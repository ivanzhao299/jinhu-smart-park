# 修复 Issue 267 资产编码留空自动生成

## Goal

修复楼栋、楼层、房源新建表单编码留空时被浏览器 required 阻止提交，恢复后端既有自动编码能力，并完成测试、PR、Codex Review、自动合并和部署监控闭环。

## Requirements

- GitHub Issue: https://github.com/ivanzhao299/jinhu-smart-park/issues/267
- 楼栋、楼层、房源创建表单的编码字段允许留空，不得被浏览器原生必填校验阻止提交。
- 编码填写非空值时，继续提交 trim 后的手填值；编码为空或仅空白时，沿用后端现有 `CodeRulesService` 自动生成能力。
- 保留现有编码格式校验、租户/园区作用域唯一性检查和数据库约束；不得在前端复制编码生成算法。
- 仅调整创建场景的编码可选性，不放宽名称、父级楼栋/楼层、用途、面积等其他字段，也不改变编辑场景语义。
- 楼栋、楼层、房源三条链路必须行为一致，并补足能防止 `required` 回归的自动化合同验证。
- 用户界面在桌面和 390px 手机宽度下均可完成空编码保存，无横向溢出或不可见错误。
- 完成本地质量门后提交、推送并创建关联 Issue #267 的 Draft PR；最新 head 的 CI 和 Codex Review 无可操作问题后自动合并，并监控 Deploy 直至成功。

## Acceptance Criteria

- [ ] 新建楼栋不填写编码可保存，返回并展示非空生成编码。
- [ ] 新建楼层不填写编码可保存，返回并展示非空生成编码。
- [ ] 新建房源不填写编码可保存，返回并展示非空生成编码。
- [ ] 三类填写合法编码时均使用 trim 后的手填编码。
- [ ] 三类非法或重复手填编码仍按现有 API 规则拒绝。
- [ ] 其他必填字段仍由表单和 API 正常校验。
- [ ] 自动化回归能证明三处编码输入不再绑定 `required`，且提交 payload 仍保留现有 trim/空值契约。
- [ ] Web lint、typecheck/build 或等价相关质量门通过；桌面与 390px 真实页面检查通过。
- [ ] PR CI 和最新 head 的 Codex Review 均无可操作反馈，PR 已合并。
- [ ] 合并后的 Deploy 成功，健康检查与部署后 Docker cleanup 通过；若未触发部署则明确报告。

## Confirmed Root Cause

- 三类页面实际调用独立的 `buildings`、`floors`、`units` 创建 API；这些 DTO 与 Service 已支持空编码并通过统一编码规则服务生成。
- 三处 Web 编码输入却标记 `required`，DrawerForm 使用原生 `<form>`，浏览器在 submit 前直接拦截空值，因此 API 自动生成路径永远无法到达。
- 本次不修改未被上述页面调用的 `assets` 聚合创建 API，避免扩大契约范围。

## Out of Scope

- 不新增前端“生成编码”算法或按钮。
- 不修改编码规则、数据库结构、迁移、导入流程或编辑流程。
- 不顺带重构页面、设计系统或其他 UAT 反馈任务。

## Notes

- 本任务为跨三个同构页面的轻量契约修复，采用 PRD-only；实现应保持最小差异。
