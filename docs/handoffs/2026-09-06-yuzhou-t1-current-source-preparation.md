# T1 人员异动当前源准备

本切片修复生产候选准备不能复用已核实旧字典证据、且只能接受旧空库快照的问题。它不执行生产写入，不重新抽取数据，也不重复全量 A/B。

## 已验证事实

- 真实受控 T1 源的 6,887 条异动、四种类型、两种状态通过当前纯验证函数；实际事件使用数量与字典数量一致。
- 原状态包字节 SHA 为 `76acab713a33a47798734e89ded61eb11fdaa3b70da758318a2262661d23226c`，核验前后不变。旧 C/M 与当前不同，原机器证明按原 C/M 验证，当前规则另行验证；没有改写历史证明。
- 当前源清单字节 SHA 为 `f73e1caa87068b49c3679f2ce80f152046e524a3f7059e89c5cfda48f6f81b03`。
- 真实 6,887 条异动时间全部符合新规范；时间格式待隔离数为 0。另用本地 PostgreSQL 固定合成字面值在只读事务中验证无小数与六位微秒的表示一致，未查询或写入业务表。
- 上述真实核验针对本地纯函数，不是已发布 CLI、生产候选或成功导入的证明。

## 使用与兼容

原 T1 候选生成命令保持严格旧行为。显式增加 `--source-manifest` 才启用当前源语义复核；使用 `--target-inventory` 代替 `--target-snapshot` 时必须提供它，两种目标输入不能同时出现。其他既有参数不变。

完整库存模式保留全部 16 张表，校验当前来源、目标范围与 T0 依赖。相同目标记录跳过；不同内容、ID 冲突、源业务重复进入待审；非生效状态或未建立员工关系的事件保留隔离，不丢弃也不伪造关联。

独立审查发现并修复时间表示不一致：完整库存候选与 T1 数据库回读统一为六位小数的本地时间及既有 `+08:00` 标签，保留微秒，不作 UTC 换算。数据库查询直接返回文本，不能用丢失微秒的 JavaScript Date 代替。旧入口格式保留兼容，但不作为当前完整库存与写入链的匹配证明；生产准备必须走显式当前路径。T2 时间规则未更改。

输出仍为私有候选工件。为兼容下游，`targetSnapshotArtifactSha256` 在完整库存模式指向实际库存文件字节 SHA；不是把库存伪装为空库快照。冻结时必须保留并验证实际工件类型与引用。
