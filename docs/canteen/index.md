## 1. 背景与目标

金湖 Smart Park 是多园区、多租户的产业园区数字化平台。园区内设有自建员工餐厅/档口，采取**公司自建资产、对外承包经营**的模式：公司统一经营管理、统一收款、统一结算；承包方按约负责出品与现场运营。

本模块（`canteen`）要解决三件事：

1. **现场收银**：POS 触摸屏完成餐品点单与收款，支持「顾客扫码真实收款」与「员工餐补虚拟核销」两种结账方式，并支持二者混合。
2. **员工餐补台账**：员工午餐补贴以**虚拟钱包**按月发放，吃则当场扣、不吃月末过期清零，不累积、不兑现、不找零；全程只在虚拟账户内核销，不发生真实资金。
3. **承包方月末结算**：按园区/承包方/账期聚合真实收款与员工消费，生成月度结算单，财务复核、差异处理、审批付款、归档凭证。

设计目标：复用平台已有的多租户 / RBAC / 员工 / party / 文件 / 编号 / 字典底座，作为又一「业态」接入；补贴虚拟台账与真实资金严格分账；不内置任何真实支付商户号与密钥。

## 2. 范围

- **在范围内（In Scope）**：餐厅/档口与承包方档案、品类与餐品管理、POS 收银（二维码收款 + 员工餐补 + 混合）、收银班次日结、员工补贴钱包与月度发放/清零、员工用餐记录、退款撤单、承包方月度对账结算、销售/日结/餐品排行/补贴使用报表、管理端/财务端/承包方视图/员工个人中心。
- **不在范围内（Out of Scope，本期）**：真实微信/支付宝商户号与密钥的生产对接（仅定义端口与适配器，生产由密钥管理注入）；自营堂食外卖配送供应链；复杂排班；与第三方点餐小程序/外卖平台打通；跨园区补贴互转。

## 3. 术语（全文统一，取自基线第 2 节）

| 术语 | 说明 |
|---|---|
| Outlet 餐厅/档口 | 一个物理就餐点（可多档口），归属一个承包方 |
| Contractor 承包方 | 承包经营的外部商户（party/商户实体） |
| Dish 餐品 / Category 品类 | 售卖商品与分类 |
| Order 订单 | 一次结账交易（含明细），含 business_date、meal_period |
| 真实收款 | 顾客扫码（微信/支付宝等），发生真实资金 |
| 虚拟结账 | 员工用餐补支付，不走真实支付，仅在补贴虚拟账户内核销 |
| Wallet 补贴钱包 | 员工个人午餐补贴虚拟账户，按月发放，吃则扣/不吃月末清零 |
| Grant 发放单 / WalletTxn 补贴流水 | 月度发放记录；流水类型 grant/consume/refund/expire |
| MealRecord 员工用餐记录 | 员工每次就餐事实，结算与对账依据 |
| Settlement 结算单 / SettlementItem 结算明细 | 承包方与公司财务按月对账结账单据 |
| CashierSession 收银班次 | POS 开班/结班（日结） |

> 共用账号口径（冻结）：POS 终端以一个共享的「餐厅收银/员工餐」设备账号登录；员工补贴钱包按人隔离。收银员在 POS 选「员工餐补」后，通过扫描员工个人码 / 刷员工卡 / 输工号或手机号识别具体员工，展示其当月补贴余额后核销。即「**终端账号共用、补贴账户到人**」。

## 5. 端清单（基线第 8 节）

1. **餐厅 POS 终端** `/canteen/pos`：全屏横屏（16:9，10.1"~15.6" 电容触摸），分类页签 + 餐品大按钮网格 + 右侧购物车 + 底部两大收款按钮（扫码收款 / 员工餐补）；点餐→收款 ≤3 步；收款结果全屏反馈；开班/结班、断网容错提示、（可选）小票打印/客显。
2. **员工个人中心**：`account` 新增「我的餐补」——当月额度/已用/剩余/到期提示、发放与消费明细分页、出示个人码；移动端可用。
3. **管理端** `/canteen`：餐品/品类上架、订单与流水、退款/撤单、班次日结、报表。
4. **财务端**（finance 下嵌入）：结算单列表、对账明细、差异处理、审批与付款、凭证归档。
5. **承包方视图**：本餐厅经营看板与对账确认（数据范围限定到本承包方/outlet）。

## 8. 关键业务规则校验点（验收必查，基线第 11 节）

- 补贴按月发放；吃则当场扣；不吃月末清零；不累积、不兑现、不找零；余额不可为负；并发不超扣。
- 虚拟结账与真实收款严格分账、可区分（channel、subsidy_amount vs qr_pay_amount）。
- 承包方月末凭员工消费结果（meal_record/补贴核销）与公司财务对账；真实收款资金归集口径清晰、不重复支付。
- 退款/撤单：paid 前可撤单；paid 后原路退（二维码退支付平台、餐补退回虚拟账户并写反向流水）。
- 全程多租户隔离、权限最小化、操作留痕；不内置真实支付密钥。
