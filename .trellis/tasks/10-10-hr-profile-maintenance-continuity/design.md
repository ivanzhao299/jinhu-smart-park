# Design
Keep the existing employee profile API/version locking and complete payload semantics. Permit the updateProfile adapter to accept an optional caller-owned idempotency key while preserving old callers. Prefer the smallest route-local extraction only if needed for meaningful tests; avoid broad refactors of the large employee page. One bounded in-memory pending attempt binds employee/version/body/token/key; unknown outcomes freeze mutable input and navigation and allow only exact retry. Validate the write response against expected employee and version before updating the profile. Persist known save receipt before independent reads. Preserve all field inputs and enforce existing permission/readiness. Reuse established contract/approval continuity patterns after exact source reads. Root separately corrects the source approval audit metadata in the existing controller; no service changes.
