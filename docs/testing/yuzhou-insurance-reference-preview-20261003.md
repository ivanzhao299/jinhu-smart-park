# 社保参考试算 API 进展

已把精确金额内核接入独立 `POST /hr/insurance/reference-preview` 控制器与服务，并注册至 HR 模块。输入为员工、政策/预期版本、政策变体、期间、六险种基数和明确的公积金汇总选择；费率与固定附加额仅从服务端政策读取。

必须同时具备园区社保读取、社保金额读取和园区员工读取权限。来源查询绑定租户、园区、ID及未删除状态；团队/本人读权限不能调用。每次结果绑定精确输入 hash，并明确为参考结果、不可确认。它没有政策生效维护或持久冻结，不是完整社保运营闭环。没有新增权限或自动给账号扩权，没有修改 DDL、历史政策/期间、导入回执或正式工资。

聚焦测试19/19通过：8个原台账权限/脱敏回归、6个精确计算测试、5个 API/DTO/权限/审计测试。首次API测试因测试替身错误要求 scope 与删除条件紧邻而失败；按实际查询分别核对这两个必要谓词并保留参数检查后通过。相关 ESLint、API 类型检查通过。真实 PostgreSQL 使用独立 Compose 实验库，从原始迁移建立模式；首次默认Compose目标和第二次初始化临时服务探测错误均发生在迁移开始前，已清理。改用私有 Compose 配置及最终 TCP 就绪探测后重新执行，实际结果记录在私有回执，不预先写 PASS。

真实 PostgreSQL 最终结果：原始迁移通过321号，两个服务集成测试通过、无跳过。与 PostgreSQL numeric 的加法后舍入结果一致，跨租户来源和过期政策版本拒绝，审计失败不返回金额，引用源整行 hash 未改变。测试后的代码 hash 与测试前快照一致，独立容器已删除；没有复制真实源业务行。初始化错误的根因经镜像入口代码确认：临时 PostgreSQL 服务以 listen_addresses='' 启动，socket探测不能证明最终TCP就绪。API构建亦通过。这些是合成主体/审计替身的服务测试，尚未验证实际 HTTP 登录链或真实岗位。

后续：补页面政策/人员选择和参考结果；增加不可变政策版本/生效期、保存预览/确认/关账/更正及工资引用。还需将历史期间汇总与原过程的四类汇总核对，特别是原过程已证实的公积金汇总开关；不能仅按现代分项求和就认定原期间业务等价。工资实际月份/账套与岗位签署继续独立待办。当前没有发布本切片，不能计为前端承载或生产业务验收完成。
