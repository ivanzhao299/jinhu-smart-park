# 导入前已验证备份留存

## 解决的问题

Gate-19 默认验证 PostgreSQL dump 和文件归档可恢复，然后清除临时恢复库与临时归档。
成功报告证明恢复演练通过，但不证明之后还存在可用的恢复材料。
新增显式留存选项，保留默认演练行为，不启动历史导入或数据库恢复。

## 使用与边界

- 在已批准的维护窗口，运行 `Production Backup Restore Gate`，显式勾选
  `retain_verified_backup`。默认 `false`，普通部署不会自动开启。
- 直接调用 Gate-19 的对应单次控制为 `RETAIN_VERIFIED_BACKUP=yes`；只接受 `yes/no`，
  显式调用值优先于应用环境文件。不要把此开关长期放进应用 `.env`。
- 只接受固定独立挂载点 `/srv/jinhu-production-data`，必须与根文件系统不同设备；
  不会格式化、挂载磁盘或回退写系统盘。备份子目录固定为 `hr-preimport-backups`。
- 目录权限 `0700`、文件权限 `0600`，目录和祖先不可为符号链接或不可信可写目录。
  每次生成新的 `backupId`，即使 `runId` 相同也不会覆盖旧文件。
- 保留本次恢复检查通过的 `database.dump` 和 `files.tgz`，每件不超过 20 GiB。
  留存前要求目的卷可用空间至少为两件文件大小之和加 20 GiB 余量；原恢复演练的
  宿主/容器容量检查继续生效。失败不自动清理历史备份。
- 流式复制时核对长度及 SHA-256，再回读目的文件核对；每件复制、子进程完成和回读
  共享 120 秒 deadline。缺失、截断、超长、内容漂移、子进程错误或超时均失败关闭。
- 先 fsync 文件及私有暂存回执，再以排他硬链接原子发布 `receipt.json` 并同步目录。
  失败副本保持私有；不能因有文件或 `receipt.pending.json` 就认定成功。
  发布撤回失败会明确报告 `BACKUP_RETENTION_RECEIPT_PUBLICATION_UNCERTAIN`。
- 成功 Gate 报告的 `retained_backup` 含不透明备份 ID、run ID、时间、字节数和哈希；
  不含生产连接、账号、原始行、备份内容或私有运行路径。凭此 ID 在受控主机定位恢复材料。
  临时演练清理不涉及留存目录。恢复必须使用单独批准的恢复操作，不能把此脚本当恢复入口。

## 不代表什么

这不是异地灾备或加密备份方案，不保护整台主机/整块数据盘丢失。目录私有权限不是加密。
PostgreSQL 和文件归档仍应在协调好的同一维护窗口取得；现有 Gate 不提供跨数据库与文件的
原子快照，也不会自动冻结业务写入。生产导入前还需确认无并发部署/数据写入造成快照漂移，
并绑定当前目标、范围化 before-image、记录映射和恢复职责。

JS deadline 不能打断内核卡住的同步文件系统调用（例如 fsync）；流程超时或连接中断不等于
远端已停止，必须检查同一运行的进程状态再处置，不能直接重启另一轮。
