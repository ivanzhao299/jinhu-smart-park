# Technical Design

## Boundary

用户管理的显示修复限定在 Web；API 继续返回租户范围内的完整园区业务对象，写入端的租户归属校验不变。为阻止同类脏数据继续产生，租户创建 DTO 对初始园区名称补充规范化后的业务名称校验。

## Label Resolution

在现有 `user-park-options.logic.ts` 中增加纯函数：

1. 修剪 `parkName`。
2. 名称包含 Unicode 数字与空白以外的字符时直接作为业务标签。
3. 否则修剪当前 `tenantName`，返回 `${tenantName}默认园区`。
4. 若租户名称也不可用，返回通用 `默认园区`。

批量解析所有候选项的基础标签；基础标签重复时，仅为冲突项追加全局唯一的 `parkCode`。表单的默认园区 `<option>` 与可访问园区 checkbox 统一读取该映射。`parkId` 仅保留为表单 value/key，不进入可见标签。

## Compatibility

- 无 API 响应、数据库或迁移变更。
- API 响应与数据库无变更；租户创建请求中的纯数字/空白 `parkName` 从接受改为 400。
- 历史纯数字园区名称即时获得可读兜底显示。
- 正常业务名称按原值展示，仅移除内部 ID 后缀。
- 同名园区仍由隐藏的唯一 `parkId` 绑定；本次不改变选择协议。

## Risk Control

- 单元测试覆盖正常、空白、纯数字、租户兜底和内部 ID 不泄露。
- DTO 测试覆盖省略、ASCII/全角/阿拉伯数字、数字加空白、空白拒绝及含数字的可读名称接受。
- Web 测试覆盖 Unicode 数字兜底及正常/异常标签碰撞时的园区编码区分。
- 源码断言确保两个控件都使用统一 helper，防止后续一处回退为字符串拼接。
