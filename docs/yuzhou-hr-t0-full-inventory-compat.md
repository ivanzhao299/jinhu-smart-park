# T0 候选映射接收当前全域目标回执

## 已证明的接口断点

当前 `diagnose-yuzhou-hr-production-target-inventory` 工作流产出 16 表 T0–T3 的
`yuzhou_hr_production_target_inventory_readonly`，并添加 `sourceManifestSha256` 和 C/S/M。
原 T0 候选器只接受三表 `yuzhou_hr_production_t0_target_inventory_readonly` 的精确键集。
所以当前全域回执不能直接进入原 T0 候选器。不得手工删去来源字段或伪装成旧回执。

## 实现

- 仍接收历史三表格式；它没有的新来源证明不由程序补造。
- 当前全域格式必须具有完整来源清单哈希和与本次准备一致的 C/S/M。
- 校验完整 16 表精确键集、每表数量、所有记录哈希/版本/ID及重复身份，再取三表 T0 lookup。
  合同类型等非 T0 记录即使不参与当前候选生成，也不得跳过验证。
- 候选工件绑定原始完整目标回执的文件 SHA-256，不绑定删减投影的另一个哈希。
- 原组织层级、岗位归属、员工状态映射和碰撞处置逻辑未改变：精确匹配仍 `skip_exact`，
  非一致目标仍 `review_target_collision`，不可凭本片认定 16 条组织应该全部合并。
- 本片没有提供 T2 的真实合同类型匹配结果；3 条已有合同类型仍须进入 T2 的独立决策。

该检查只验证真实回执的格式/绑定和投影，不读取源人员行，不执行实际源候选生成、碰撞审批
或生产写入。来源清单哈希在本入口验证格式并原样保留；来源文件字节核验仍由原封存链负责。
新提交不能冒用这份旧代码绑定作为当前执行回执；准备窗口仍需代码和实际生产运行身份一致。
