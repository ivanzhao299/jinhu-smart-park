# 玉舟客户端版与集团 Web 版双端差距矩阵

日期：2026-08-28
审查方式：只读复核仓库中已固化的客户端现场台账、集团 Web 源码/数据库运行合同、231 项菜单映射、15 个 Web 入口目标绑定和 Smart Park 源码覆盖报告。
结论：两端均未形成页面级 L4 闭环，任何一端的证据不得替代另一端；生产历史导入继续 `HOLD`。

## 1. 证据边界与完成度口径

本矩阵使用以下六个旧系统维度：

- `P`：页面或入口；`M3`：三级菜单/页内原子入口；`F`：字段、过滤器、列表列和默认值；`A`：动作及其前置条件；`S`：状态与转换；`B`：业务规则、编号、计算、提醒和审批语义。
- `✓`：有稳定、可复核的逐项证据；`△`：只有部分页面、人工观察、帮助/源码/数据库结构证据；`—`：尚无证据。
- Smart Park 目标用 `R/A/E/P/T` 表示 route/API/entity/permission/test。只有五类证据逐原子存在且运行角色矩阵通过，才可称为 L4 绑定；仅有 route 或源码符号不等于业务兼容完成。

## 3. 不能合并计算的证据

1. 客户端的 93 条授权目录不能证明集团 Web 的 `Web_GetUserRight` 或 15 个入口可见性；Web 的 181 个角色分配和 694 条部门范围记录也不能证明客户端内置管理员判断。
2. Web 源码中 231 个 `legacyId`、186 个路径和字段/动作解析结果，不能替代真实 Web 会话中的 DOM、字段投影、按钮可见性、403/not-found 和错误恢复。
3. 客户端人工观察的字段和按钮没有稳定页面 ID、脱敏截图 hash 或逐项角色，因此不能由 Web 的稳定 ASP 路径补齐。
4. 15 个 Web 入口已映射到 Smart Park 的 route/API/permission/test，只说明目标源码锚点存在；其合同明确 `roleMatrixVerified=false`、`compatibilityScoreContribution=0`。
5. 集团 Web 231 项覆盖报告的 `averageScore=64.94` 是源码覆盖度，不是业务兼容分；`implemented=0`、`score100=0` 才是当前完成状态。

## 4. 跨端公共硬缺口

| 缺口 | 客户端版 | 集团 Web 版 | 闭环要求 |
|---|---|---|---|
| 稳定页面 ID | 缺；只有入口名称和语义化 page-check slug | 结构层已有 legacyId/path；运行 DOM/page ID 缺 | 每个页面、页签、弹窗、报表、提醒建立 surface-scoped stable ID，禁止跨端复用 |
| 截图证据 | 未提交，现场仅人工脱敏记录 | 未提交；运行合同明确 `screenshotsCommitted=false` | 只在 0700 evidence root 生成 0600 脱敏截图及 hash，仓库只存脱敏索引；不得含 PII/工资/凭据 |
| 管理员覆盖 | 数据库管理员可登录但用户管理/提醒被内置判断拒绝 | 有角色模板和部署聚合，无有效 Web 管理员页面遍历 | 分别验证客户端管理员、Web admin、HR、manager、employee；记录允许/拒绝及原因，不用一端账号代替另一端 |
| 字段与动作 | 只覆盖少数空白页/设置页 | 源码可解析但未以真实角色运行 | 对每页逐字段、按钮、默认值、必填、校验、状态前置条件和输出建立原子记录 |
| 状态与业务规则 | 编号、续签、月结等仅部分双证据 | 源码/过程目录存在，页面运行语义未确认 | 旧客户端现场 + Web 运行 + 数据库/源码至少对应适用的双证据，并绑定 Smart Park 状态机和负向测试 |
| L4 目标绑定 | 0；v1 强制 L3/score 0 | 运行源/数据库 L4 不等于页面 L4；15 入口 score 0 | 每一 surface item 绑定 R/A/E/P/T，完成三角色 runtime matrix 和 required-audit 失败验证 |

## 5. 可执行闭环顺序

1. 冻结双端各自的 surface ID 命名空间：`client:*` 与 `group-web:*`，从源头防止同名页面相互抵扣。
2. 客户端按 13 族完成全部入口和三级动作的只读遍历；只打开空白/设置/脱敏页，不保存、审核、反审核、结账、发薪或导出。
3. 集团 Web 使用合规测试身份分别完成 employee、manager、Web admin 登录后遍历；15 个简化入口和 231 项集团菜单分别对账，不能把 15 项当成完整 231 项。
4. 对每个 surface item 固化 `page/menu3/field/action/state/businessRule`，并记录 allow/deny、角色、数据范围、脱敏、required audit 和错误恢复。
5. 将每项分别绑定 Smart Park `route/API/entity/atomic permission/test`；缺任何一项保持 gap，归档/拒绝需稳定 reason 和业务审批。
6. 运行 desktop/390 三角色矩阵并生成 hash 固定、脱敏的证据索引；客户端和集团 Web 各自达到 L4 后才允许形成双端合并覆盖结论。
7. L4 只解决技术/行为兼容；HR、薪酬、财务 L5 签署、A/B 连续演练和单独生产授权仍是独立门禁，当前 `NO_GO / productionImport=HOLD`。
