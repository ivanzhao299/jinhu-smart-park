# Design

Use additive opt-in includeSourceValues query on existing preparation endpoint, retaining default roster-only response. DTO strictboolean; opt-in additionally requires existing resolveHrPayrollHistoryAccessScope(actor)===park before any DB probe (super/* valid); self-only and team summary are insufficient. UI gates same existing full historical amount read capability; default roster keeps current permissions. reject opt-in without reconciliationSourceId or with correction. Shared typed optional per-row values/issues plus binding metadata as needed; existing callers unaffected. Reuse lockCurrentPayrollSource, effective version and preparation roster checks. Read only selected page employee snapshots under same transaction; SQL joins exact scoped definitions and versions, projects decimal_value::text (or frozen JSON->> projection in PostgreSQL after currenthash verification). Do not parse raw numeric JSON. Classify missing/null/nondecimal/duplicate candidate without guessing; expose only direct codes from approved rule. Add financial to required audit fieldgroups when opt-in; body-free/no amounts in logs. Existing immutable hash/current-source checks remain authoritative.

Route-local preview component/helper can reuse CSV preview/apply approach and collectScopedExport; no duplicate generic money parser. Capture owner source+period+effective version+roster/head+selection/draft+token; compare every page and before apply; immediately before apply perform one small metadata-only preparation read (same source/period/rule, no monetary opt-in) to revalidate live source/hash/roster/effective version/head, then compare local owner again after await; abort superseded reads. Default fill blanks only; any replacement requires explicit preview/selection. Missing candidates never erase existing entries. Source/correction and save locks disable read/apply; existing drafts and settlement metadata retained. Actual creation uses unchanged formal input payload and idempotent endpoint.

No schema/auth/release changes; additive API/shared/Web requires full release. API first and backward-compatible fields; rollback Web ignores additive fields. Use real frozen-source SQL PG fixture (existing empty disposable migrated localPG) and existing composed test patterns. Source tuple validation failures stop preview, never silently fallback to another source.
