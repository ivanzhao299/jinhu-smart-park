# 绩效记录与评分标准业务入口

## Goal
用户要求导入后作为持续运营的正式业务资料使用，普通页面不再以旧/新数据或迁移技术信息划界。当前绩效资料面板仍显示“玉舟V10兼容层”“旧过程u_printassessment”“现代关系”，查看评分标准须手抄考核表编号。本片让现有授权模板记录直接到达评分标准，使用业务语言与共享DS；不伪造已有快照可原地编辑或全部源计算已等价。

## Requirements
- 普通标题、字段标签、提示和空态使用绩效资料、考核表、项目、评分标准、记录及关联等业务词语，去掉内部过程名、兼容层和旧/新前缀。原始业务值、API字段、来源ID/证据和权限保持原样，缺件/未关联仍如实说明，不擦除来源证据或猜零。
- 有既有定义读取权限的用户，在模板记录中直接“查看评分标准”，捕获该条精确sourceAssessment编号调用既有performanceLegacyRubric。页面显示所选考核表名称和编号，无需手抄。不得setState后从旧闭包读取编号；无效/缺失编号不给错误模板或默认为0。
- 保留可选编号查询，使用“考核表编号”业务标签和现有严格编号校验，不改变后端查询语义/范围。没有定义读取权限时不显示操作、不发出请求。
- 快速切换模板、分页/筛选或身份/园区变更时取消/丢弃旧响应；选择及错误归属正确，失败可按当前目标重试。不能扩大读取、原地改写历史证据或改变绩效计算规则。
- 使用现有DS表面/按钮，44px触控、桌面与390px可达、无横向溢出。只调整必要领域布局与留白，不新建颜色/边框体系。
- 复用现有接口及关系；原u_printassessment业务投影已在合同中verified，不重新解析/导入历史数据，不扩大bs_ass_compute尚pending的等价信用。

## Acceptance
- [ ] 实际模板记录直接进入正确评分标准，选择名称/编号可核对，普通UI不暴露过程/兼容层术语。
- [ ] 实际组件用例覆盖权限负例、精确选中编号/0与缺失区分、快速切换/旧响应、失败恢复、既有字段与敏感读取边界；相关绩效套件通过。
- [ ] Web lint/typecheck/build及相关HR合同通过；独立检查、最终源实际组件桌面/390px验收。
- [ ] 新鲜基线集成、PR/既有范围CI、合并、Web发布/清理/实际运行分开核验；真实岗位UAT和整个HR长目标不冒充完成。
