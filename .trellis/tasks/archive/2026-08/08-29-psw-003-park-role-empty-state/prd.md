# PSW-003 园区未配置角色专用可恢复空态

## Goal

让已经获得目标园区访问权、但尚未配置该园区业务角色的用户，在切换后进入明确、可恢复的专用空态，而不是通用 403；同时交付历史 access-only 用户的最小化只读审计清单。

## Requirements

- access-only 继续是合法持久状态，不自动猜测、复制或补齐角色。
- 当前园区 `role_summary.has_business_role === false` 时，在认证布局内显示专用空态，精确主文案为“已获得园区访问权，但尚未配置园区角色”。
- 空态保留桌面/移动园区选择器与登出能力，并在有可靠来源园区时提供“返回原园区”动作。
- 提供管理员配置指引，但不向 access-only 用户泄露角色候选、权限、数据范围或其他用户诊断。
- 普通权限拒绝和模块拒绝继续使用现有通用 403，不得被 access-only 空态吞并。
- 桌面与 390px 级手机宽度均无横向溢出，主要操作触控友好。
- D5 采用显式 tenant、可选 park 范围的只读审计脚本；仅输出最小化标识与状态，不写数据库、不输出联系方式、凭据或权限明细。
- 不进行生产直操作；UAT 在后续队列阶段按既定 S1-S3/G1-G7 矩阵执行。

## Acceptance Criteria

- [ ] access-only 用户切换后看见专用空态和精确文案，不跳转到通用 `/403`。
- [ ] 专用空态内仍可使用园区选择器和登出；有可靠来源园区时可一键返回并恢复正常路由。
- [ ] 没有可靠来源园区时不伪造返回目标，仍保留选择器和配置指引。
- [ ] 显式配置目标园区角色后，重新进入该园区不再显示专用空态。
- [ ] 非 access-only 的 permission/module denial 保持现有 403 URL 与文案。
- [ ] Web 单元/契约测试覆盖状态识别、来源园区生命周期、恢复动作、403 防回退以及桌面/移动布局契约。
- [ ] D5 脚本语法与 SQL 契约测试通过，查询只读且正确排除有效目标园区角色与受保护 tenant-super。
- [ ] 相关 typecheck、lint、build 与回归门通过；真实浏览器桌面/390px 检查若环境不可用须明确记录为跳过。
