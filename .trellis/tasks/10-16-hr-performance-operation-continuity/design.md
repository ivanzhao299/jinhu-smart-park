# 设计

沿用现有 performance-v2 API 及 IdempotencyInterceptor。HrPerformanceClient.tsx 当前 run 仅锁定进行中的请求，失败后丢失 attempt；hr-api.ts 每次生成新 key。为本页相关接口增加兼容的可选 key 参数，默认行为保持。页面使用一个有类型的原请求 attempt，绑定当次 token、key、闭包中的固定 payload、目标和成功文字，结果不确定时冻结其他办理动作并提供原请求重试。

先查找并复用现有 HR 请求连续性模式，避免跨模块重构。成功回应校验以现有各方法实际响应形状为准，不臆造版本字段；失败的刷新不可将已成功写入改判失败。明确4xx业务拒绝释放 attempt，超时/传输/5xx/幂等处理中或无法确认的409保留。权限身份 key 变更卸载时忽略旧完成结果。原请求仅存内存，不持久化个人数据和 token。

不新增迁移、认证、生产数据写入、公式或自动业务决定。回退为应用版本回退，既有业务记录保持。
