# 候选人转预入职办理回执与重试连续性

## Goal
录用办理结果可确认、可继续入职，网络不明确时不丢原请求，不把列表读取失败当作需重新录用。

## Requirements
- 复用既有幂等convert接口，不改业务状态、权限、员工匹配或发薪逻辑。
- 未知结果冻结精确请求体及key，允许同请求重试；明确业务拒绝才解锁编辑。
- 请求中及未知结果同步锁住父级刷新、切换、关闭和其他写操作。
- 成功校验candidateId、employeeId、checklistId和预入职状态；保存独立回执并更新公开候选状态。
- 有权限时预选已转换人员以继续入职申请，员工查看链接遵循实际读取权限；不显示敏感正文。
- 复用DS留白及44px控件，桌面与390px实际组件验证。

## Acceptance Criteria
- [x] 原请求/key重试，畸形回执不假称成功，明确403/409保留草稿并允许修正。
- [x] 同步父级互锁；成功回执不随刷新失败丢失，不重复调用转换。
- [x] 已确认员工被精确预选进后续申请，身份切换清空旧回执。
- [x] 定向交互、类型/lint及桌面手机浏览器通过；真实岗位验收另列。
