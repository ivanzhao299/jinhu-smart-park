# 补齐 PR192 民宿与住房出租菜单接入

## Goal

补齐 PR #192 已交付的民宿与住房出租模块在运行时菜单、页面授权和模块识别链路中的缺口，使已启用模块且持有相应角色权限的用户可以从左侧导航进入真实运营页面，同时缺少菜单权限或模块授权的用户仍被拒绝。

用户已确认“两个模块各一个菜单组、一个运营页面”的方案，任务已进入实现与验证阶段。

## Confirmed Facts

- PR #192 已提供两个真实前端入口：`/homestay` 与 `/housing`。
- PR #192 已注册 `homestay`、`housing_rental` 模块，并为默认 UAT 租户/园区写入 API 权限和既有角色授权。
- 运行时模块授权的唯一判定链路是有效 `rel_tenant_module` 关联有效 `sys_module`；
  `sys_module_registry` 不参与 `/users/me.enabled_modules` 或 `ModuleGuard` 判定。
- PR #192 写入的业务权限均为 `perm_type = 40`（API 权限）；用户菜单树只消费 `perm_type = 10`（菜单）和 `20`（页面）。
- 后端 `USER_MENU_TREE`、前端 `dashboardMenus`、前端模块推断和历史首发菜单路径均未包含民宿与住房出租。
- 前端菜单合并以静态 `dashboardMenus` 为规范骨架；只有后端动态菜单而没有静态模块组时，新的顶层模块不能稳定进入最终侧栏。
- PR #192 在权限记录中写入的 `/homestay/rates`、`/homestay/bookings`、`/homestay/operations` 等 `frontend_route` 并不存在对应的 Next.js 页面；当前不能把它们作为导航项。
- 共享房产底座当前没有独立前端页面，主要通过房源、民宿、住房出租及后端共享能力发挥作用。
- 已应用迁移不可修改，因此修复必须使用新的前向迁移；当前最新迁移号为 `000181`。

## Requirements

- 使用新的前向迁移补充两个模块的菜单/页面权限树，不修改 `000176`、`000177`、`000178`。
- 每个模块只提供一个可达、真实的运营入口：
  - `民宿管理` → `民宿运营` → `/homestay`
  - `住房出租` → `住房运营` → `/housing`
- 菜单权限、页面权限、API 操作权限保持分层：
  - 菜单节点使用 `perm_type = 10`
  - 页面节点使用 `perm_type = 20`
  - PR #192 已有操作权限继续使用 `perm_type = 40`
- 页面节点必须挂在对应菜单父节点下；迁移应幂等，并修复已存在但字段或父子关系不完整的同码记录。
- 对已经拥有相应模块任一 API 权限的角色，补授该模块的菜单和页面权限，避免现有合法角色升级后仍看不到入口。
- 不因菜单修复扩大任何 API 操作权限、数据权限或模块授权范围。
- 后端菜单回退树、模块推断，前端规范菜单、模块推断、图标映射和兼容菜单路径必须同步。
- 页面直接访问必须同时受页面菜单权限和模块启用状态约束；API 仍以既有 API 权限和数据范围为最终安全边界。
- 超级管理员只旁路权限码检查，不旁路租户模块开通；模块未启用、已禁用或已过期时，菜单、
  登录落点、页面路由和 API 均不可进入该模块。
- 保持超级管理员、默认 UAT 角色和细粒度自定义角色的行为一致：
  - 有模块 + 页面权限：菜单可见且路由可进入
  - 有模块 API 权限但迁移前缺页面权限：迁移后自动补齐菜单可达性
  - 无页面权限：菜单不可见，直接路由跳转 403
  - 模块禁用：菜单不可用，直接路由跳转模块 403
- 同步运行时菜单验收文档和 UAT 验收矩阵；历史首发白名单只作为兼容检查，不将其描述为现行发布权限边界。

## Acceptance Criteria

- [ ] 新迁移号唯一且大于 `000181`，迁移可重复执行而不产生重复权限或重复角色关系。
- [ ] `sys_permission` 中存在两个菜单父节点和两个页面子节点，类型、层级、父子关系、路由、图标及启用状态正确。
- [ ] 已持有 `homestay:*` API 权限的角色同时获得民宿菜单与页面权限；住房出租规则等价。
- [ ] 不新增或扩大任何民宿/住房 API 权限、数据权限、字段权限和模块授权。
- [ ] `/users/me` 对目标角色返回可导航的民宿/住房菜单树，节点携带正确 `module` 值。
- [ ] 只通过标准租户模块接口写入 `rel_tenant_module`、没有 `sys_module_registry` 记录的范围，
  仍能由迁移生成菜单权限及角色桥接。
- [ ] Web 左侧栏能显示“民宿管理 / 民宿运营”和“住房出租 / 住房运营”，点击分别进入真实页面。
- [ ] Web 的页面授权查找能识别 `/homestay`、`/housing`，缺页面权限和模块禁用两种情况均按现有机制拒绝。
- [ ] 超级管理员在模块禁用时不显示对应菜单、不落入对应移动终端，直达页面得到模块 403。
- [ ] 静态回退菜单与后端动态菜单合并后不重复、不丢失，不出现不存在的子路由。
- [ ] 桌面和 390px 视口均能看到并使用新增入口，不产生侧栏溢出或布局退化。
- [ ] 目标结构测试、API/Web 类型检查、构建、菜单兼容脚本和运行时角色抽样通过。
- [ ] 发布/UAT 文档明确区分菜单权限、模块授权、API 权限和数据范围。

## Out of Scope

- 不重构 PR #192 的民宿、住房出租业务页面。
- 不新增 `/homestay/rates`、`/homestay/bookings`、`/homestay/operations` 或住房子页面。
- 不为共享房产底座新增没有实际页面承载的独立菜单。
- 不新增专用业务角色，也不调整现有角色的数据范围。
- 不把本任务扩展为通用的全租户模块开通/权限物化平台改造。
- 不修改已成功迁移的 `000176`～`000181`。
