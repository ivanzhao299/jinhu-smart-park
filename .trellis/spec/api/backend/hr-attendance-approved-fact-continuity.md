# Approved attendance fact continuity

Approve retains the existing request/approval/action/notification transaction and scope rules. Derive calendar dates with an exclusive end instant and union actual overlapping employee schedule work dates. Conservatively lock calendar months plus the preceding day month in chronological order before request/employee locks; under those held locks resolve the actual affected months. Only actual affected periods reject calculating or reopen review. Recheck the locked request version and month span against the preflight read. Reject calculating months; atomically reopen review months. Return/reject does not invalidate the month. Notification failure rolls all approval and month changes back.

Closed months permit late approval and remain closed. Their old daily facts, summaries and payroll-input quantities are immutable. Require day recalculation followed by the explicit correction operation to produce a new summary/input batch; supersede the old batch through the existing version chain.

Month calculation/correction compares each current approved request's date and type/ID source set against the latest daily fact. Approved dates without schedules must still have a current daily result. Missing/empty historical source traces are compatible only when the expected source set is empty. An actual matching nonempty trace must pass, not merely make negative fixtures fail. SQL date keys used in these maps are `work_date::text`, avoiding driver Date-object/string mismatches. Keep calendar-day request source coverage and extend it through the actual saved shift window; correction remains an exact work date. Month reads include the first day after the month and batch scoped request/schedule overlap mapping. Scheduled leave intersects the saved shift, merges overlapping intervals, and records attendance-v2 plus leaveBasis; require recalculation of attendance-v1 scheduled leave before month calculation/close. Unscheduled days retain the original standard-day reference. Preserve the original source-routine equivalence helper unchanged. do not invent dates for undated historical requests.

Close also compares the complete employee set and latest daily-result IDs with the active summary. A newly present employee or changed daily result makes an old review summary stale, even if its existing rows are internally consistent.
