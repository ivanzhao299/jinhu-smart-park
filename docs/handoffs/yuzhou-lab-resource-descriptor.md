# Dedicated retained-bundle lab resources

The optional `resourceDescriptor` is accepted by the config preparation request and carried into the real-bundle CLI and HTTP runtime. It contains exact `database`, `container`, `containerId`, `imageId`, `port`, `composeProject`, `volume: { name, createdAt }`, and `network: { name, id }` bindings. Names must use `jinhu_hr_migration_lab_` followed by 6–40 lowercase letters, digits or underscores. The port is loopback-only. The CLI and HTTP runtime independently inspect the container, volume and network before accessing the database.

Only a local volume without driver options, the default PostgreSQL data directory, and a single dedicated bridge network are accepted. Different names cannot hide a bind-mounted shared data directory. Preparation does not create or inspect Docker resources: the descriptor must be produced and observed separately. Its hash is retained in the preparation receipt; the full config hash binds the actual descriptor. The original prepared C/S/M, operation, encrypted artifacts and shared exclusive state root remain unchanged. An existing descriptor cannot silently follow a changed database.

Without the descriptor the existing `jinhu_hr_migration_lab` Compose single-run restriction remains. `assertYuzhouLabResourcePair(a, b)` rejects shared database, container, port, Compose project, volume or network identities, but is only a descriptor comparison. It does not establish live resource provenance, independent crypto trust roots or formal A/B evidence. Descriptor production, independent quarantine re-sealing and two-run orchestration remain separate work. No existing receipt is upgraded to pair evidence.
