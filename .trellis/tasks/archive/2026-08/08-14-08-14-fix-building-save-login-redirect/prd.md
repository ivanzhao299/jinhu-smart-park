# 修复楼栋保存切园区时跳登录

## 背景

生产人工测试发现：在资产管理的新增楼栋界面点击保存后，页面直接跳转系统登录页，楼栋保存请求尚未执行。

该流程在新增楼栋时允许选择所属园区。若选择的园区不是当前 JWT 所在园区，前端会先调用 `/auth/switch-context` 切换园区上下文，再提交 `POST /buildings`。

## 目标

- 新增楼栋时，切换目标园区失败不得无条件清空当前登录态并跳登录页。
- 若当前会话仍可用，应在抽屉内展示明确错误，保留用户输入，避免保存请求被“静默吞掉”。
- 兼容旧会话的 body refresh token fallback，减少 refresh cookie 未携带时的误失败。
- 补充回归测试，防止后续切园区、楼栋保存、会话重置逻辑再次回退。

## 验收标准

- `/auth/switch-context` 在拿到新 access token 之前失败时，前端保留当前 session，不跳登录页。
- legacy refresh token 存在时，切园区请求 body 携带 `refreshToken`，继续使用后端兼容通道。
- 切园区成功后仍使用新 token 执行楼栋创建。
- 切园区失败时不执行楼栋创建，并在表单内显示错误。
- 本地单元测试、类型检查、真实浏览器桌面与 390px 验证通过。
- 不手动连接生产环境；生产发布只通过 PR、CI、自动合并和 GitHub Actions 部署监控闭环。
