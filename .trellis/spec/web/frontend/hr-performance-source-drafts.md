# Performance source draft maintenance

The normal performance workbench opens “资料维护” independently of the optional source-record disclosure. Read/manage authorization is selected-kind specific; template-only users never probe review routes. Read-only users load saved drafts/detail/history only. Candidates and kind-manage binding options are lazy. Empty candidates mean no currently available material; keep normal template and cycle workflows usable and do not infer a missing import.

Use the source-drafts shared catalog for all six source families and all 62 fields. Group/paginate presentation without truncating stored records or mutation sets. Fields outside the closed editable catalog, original actors/timestamps, grades and computed aggregates remain traceable read-only. Percent/integer/decimal and salary values remain exact strings; explicit null differs from empty text and zero. Appraisal/description fields and existing newline-bearing text use multiline controls, preserving literal line breaks. Varchar limits count Unicode codepoints: allow up to twice the character limit at the HTML UTF-16 boundary, show the actual count/aria-invalid, and reject over-limit changes through the shared validator without trimming. Detail appraisal remains200 codepoints and master narratives500. Boolean controls represent true/false/null. Existing configured channel names override neutral source labels; do not infer business responsibilities from channel letters.

PATCH sends only changed closed catalog fields plus explicitly edited binding/definition/workflow, never a replacement snapshot. Omitted salary is absent from both UI and changes. Visible salary is editable only with current performance read/manage and compensation manage; backend remains authoritative for live permissions. Salary returned read-only must survive unrelated revisions. Full binding uses explicit employee/org/date/period values and nulls; employee/org options use `/source-drafts/options` with exact selected kind, resource, page and search. Do not depend on unrelated HR read permission. Current and historical binding names come from response `bindingLabels`; names are a current display projection, not frozen historical evidence or a lookup in whichever option page happens to be loaded.

Reuse actual strict `PerformanceChannelDefinitionFields` and `PerformanceWorkflowPolicyFields`. Validate the final definition/workflow pair with `applyHrPerformanceSourcePatch`; deleting an item must explicitly repair/remove referenced details in that same revision. Source record edits do not silently rewrite either configuration. Clear configuration only by an explicit action. Saving a draft does not imply publication, activation, approval or completed evaluation.

Each target/auth identity owns requests, forms, history and errors. Abort target-bound requests and suppress late completions on replacement. Share the parent workspace synchronous writer lock. Capture token/key/body once; uncertain transport, processing or malformed receipts retain that attempt and freeze competing writes. Definite rejection releases the attempt and preserves editable values. CAS/source/human-refresh conflicts use Chinese business descriptions, preserving manual changes. A successful receipt must have exact draft/revision/outcome fields and match the requested identity, revision increment and operation; create requires first revision, reuse may retain current human head. Read current authorized GET after accepting the receipt. Failed read recovery never repeats a known successful write. GET may return a later current head but cannot be older than the accepted receipt. History has independent paging and retry without discarding current edits.

Use shared DS surfaces with a layout-only module. Saved records use `ds-scene-grid`, which remains visible on desktop and phone; `ds-mobile-record-list` is hidden on desktop and must not contain the only saved-record list. Scoped panel/record padding provides form whitespace without redefining shared colors, borders or buttons. Group forms adapt to phone width, long trace hashes wrap, buttons have stable 44px touch height and keep words intact. Verify the actual component desktop and 390px after final review. The private synthetic preview must retain source/fixture hashes and clearly identify all data and transport as synthetic; it is distinct from API/PG, production and real-role acceptance.

Focused actual interaction suites: `hr-performance-source-drafts.test.tsx`, `hr-performance-source-drafts-api.test.tsx`, and the existing `hr-performance-source-disclosure.test.tsx`. They cover reader/kind reachability, independent pages, all catalog fields, exact strings/null/omitted salary, action-scoped selectors, final configuration pair, CAS/manual refresh conflicts, same-request retry, strict receipt/read recovery, context replacement and empty candidates. Run shared producer build first, then Web lint/typecheck. Root owns serial full integration/build and native browser evidence.

Incremental refresh includes an explicit paged source picker using candidate draftId filtering; retain the selected sourceId and its matched preview hash in the original retry payload. Never fix refresh to the previous revision sourceId across imports. Verify preview kind/sourceId before mutation. A known create receipt survives detail-read failure: reload reads that receipt draftId and validates its minimum revision, never returns to a fresh candidate create action.
