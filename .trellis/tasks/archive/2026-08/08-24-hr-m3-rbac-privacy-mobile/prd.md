# HR M3 权限隐私与移动端生产基线

## Goal

在现有独立 HR 模块和生产数据库基线上，建立可由后端强制执行的三类角色权限、数据范围和敏感字段保护，并使 HR 高频页面达到桌面与 390px 手机端可用标准。

## Requirements

- 明确 HR 管理员、部门负责人、员工本人三类角色的页面、动作、数据范围和敏感字段权限矩阵。
- API 必须按租户、园区、本人、负责人组织子树或全园区范围过滤；前端隐藏不得作为授权依据。
- 身份证、银行卡、私人联系方式、工资明细和员工附件默认最小化返回；仅细粒度授权可读取，并对展示值实施一致脱敏。
- 高敏感读取和关键变更写入审计元数据，日志、错误和审计摘要不得包含敏感原文。
- 保持现有员工、目标、工作汇报、绩效、360、薪酬、工资和审批契约兼容，不修改已部署迁移。
- HR 高频页面使用共享 Design System，桌面与 390px 均无横向溢出；移动端以卡片/任务流替代不可操作的宽表。
- 所有修改必须在独立分支完成；开始开发、提交、合并和部署前重新执行本地/远程/运行端安全检查。

## Acceptance Criteria

- [ ] 权限矩阵文档和共享权限常量一致，三类角色的允许/拒绝边界可审计。
- [ ] API 自动测试覆盖本人、直属团队或组织子树、跨组织、跨园区和全园区查询。
- [ ] 未授权调用不能获得工资、证件、银行卡、私人联系方式或附件原文。
- [ ] 获授权的敏感读取和关键变更产生不含敏感正文的审计证据。
- [ ] 既有 HR、工资并发、迁移契约测试全部保持通过。
- [ ] HR 首页、员工、工作汇报、绩效、360、工资与审批关键页面完成桌面和 390px 浏览器检查。
- [ ] shared build、lint、typecheck、API/Web build 通过，数据库相关验证使用隔离目标库。

## Notes

- 本阶段不导入玉舟 T4 历史工资，不启用正式发薪，不写生产业务数据。
- 如现有用户模型无法可靠表达“负责人组织子树”，先补充服务端可测试的范围解析边界，不通过前端参数扩大权限。
