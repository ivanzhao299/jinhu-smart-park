# 玉舟个人通讯录兼容闭环

## Goal

将玉舟 HR V10 客户端“工作助手 → 通讯录”和集团 Web“个人办公 → 通讯录”闭环为金湖 Smart Park 中由 HR 领域拥有的个人通讯录能力。它必须是可审计、可迁移、可撤销的真实业务能力，而不是指向泛化工作流或其他业务域联系人页面的占位映射。

## Confirmed facts

- 只读客户端遍历已确认“工作助手 → 通讯录”为稳定二级入口；其新增、编辑、删除、保存、取消、查询/浏览等操作属于待逐页采集的三级动作。
- 集团 Web 源清单中的 `legacyId=301` 已解析，归属 `personal_office`，所有者为 `hr`；现有映射没有目标路由、API 或角色范围。
- 源代码审计已固定该入口的字段证据哈希；该哈希只能用作 C/S/M 绑定，不能将原始字段、联系人内容或私有源配置写入仓库。
- 当前系统的园区租户联系人、应急联系人等属于其他领域，不能复用为个人通讯录的兼容实现。

## Requirements

1. 建立独立的 HR 个人通讯录聚合及最小必要的分类、联系人和所有权关系；数据必须始终受 tenant/park、所有者和数据范围约束。
2. 用只读受控源恢复和字段字典采集客户端与集团 Web 的真实字段、枚举、校验、三级动作、可见性与删除语义；任何未知字段不得猜测或静默丢弃。
3. 提供原子权限：读取本人、读取被授权范围、创建、修改、删除/归档、导出（如旧规则存在）必须分离；服务端权限和字段策略为权威，前端隐藏不构成授权。
4. 提供实际 API、桌面与 390px 页面、菜单/深链边界、审计、幂等和并发冲突语义；普通员工、部门负责人、HR 管理员三类角色均有明确可验证行为。
5. 历史迁移以 C/S/M 绑定的隔离演练完成：守恒/隔离账本、重复拒绝、目标功能验证、精确逆序回滚和零残留。生产写入保持 `HOLD`。
6. 关联 Group Web `legacyId=301` 与客户端工作助手通讯录的证据、实现、权限、迁移和测试，状态从 `mapped` 升级到可验证的 `implemented` 或明确的 `partial`，不得以泛化 `/workflow` 替代。

## Acceptance Criteria

- [ ] 客户端与 Group Web 各自的页面、字段、三级动作、角色和规则都有独立的脱敏证据记录，且不以任一表面替代另一表面。
- [ ] 数据库迁移、实体/DTO、服务、控制器、菜单/路由、桌面及移动端 UI、共享权限契约和审计均已实现并通过相应测试。
- [ ] 服务端对跨 tenant/park、跨所有者、越权字段、已归档记录、并发更新和重复写入均 fail-closed。
- [ ] 三角色 API 与桌面/390px 验收通过；深链、空态、无权限、冲突和恢复行为可验证。
- [ ] 隔离迁移 A/B、比例/守恒、技术 UAT、逆序回滚和零残留证明完成；任何生产写入仍由独立生产门禁决定。
- [ ] 映射合同、覆盖率统计和兼容计划已更新，明确实现边界与未覆盖项。

## Out of scope

- 员工照片、附件二进制、个人信息原始内容及任何生产历史写入。
- 以通讯录为名重建会议、通知、记事本或其他工作助手能力；这些保留为独立兼容切片。
