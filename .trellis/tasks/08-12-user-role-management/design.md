# Technical Design

## Boundaries

- 用户详情/角色读取：在 Users 模块增加受用户详情或角色分配权限保护的读取契约，按目标用户实际作用域读取有效角色绑定。
- 角色候选：复用 Roles 模块当前作用域查询语义；Web 只消费启用、可分配角色。
- 角色写入：保留 `POST /users/:id/roles` 独立命令，不把授权混入 `PATCH /users/:id`。
- Web：用户抽屉维护 `selectedRoleIds` 与加载态；新增先创建用户，再用独立幂等键分配角色；编辑仅在集合变化时提交。

## Data Flow

1. 打开新增抽屉：根据目标租户/默认园区登录上下文加载角色候选。
2. 打开编辑抽屉：并行加载组织候选、现有组织关系、角色候选和当前角色绑定。
3. 保存账号资料，取得用户 ID。
4. 若操作者有分配角色权限且角色集合需要写入，调用独立分配接口。
5. 刷新用户列表及角色摘要。

## Compatibility And Security

- 后端始终重新校验角色的 tenant/park/roleScope，不能信任前端候选。
- 平台角色继续排除；租户角色与同园区园区角色可分配。
- 读取和写入均以目标用户作用域为准，超级管理员跨租户操作需沿用现有用户管理的目标作用域解析方式，不能误用当前登录园区。
- 角色替换放入数据库事务；审计和幂等拦截器继续位于独立 endpoint。
- 账号创建成功、角色分配失败属于跨请求部分成功；前端必须保留明确错误并提示用户重新编辑补配，不能宣称整笔回滚。

## Testing

- Service：读取范围、候选范围、事务回滚、重复 ID、清空集合、跨租户/园区拒绝。
- Controller/权限：读取与写入权限门禁、幂等要求。
- Web：角色加载、回显、新增/编辑提交、无权限隐藏、移动布局。
- E2E：创建用户并分配角色、重新读取、登录授权、替换/清空、幂等回放/冲突。

## Rollback

- Web 入口可独立回滚，不影响已有后端接口。
- 新增读取契约向后兼容。
- 事务化替换不改变成功响应结构；出现异常可回滚服务实现而无需数据迁移。
