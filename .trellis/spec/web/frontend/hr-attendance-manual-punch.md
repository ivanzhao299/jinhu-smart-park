# 人工补打卡操作

## Scope
HR在已有考勤运营权限内为明确选定的员工补录事件。技术eventKey不得成为用户必填字段。

## Contract
复用createIdempotencyKey产生事件键，保留在组件ref中，以员工、ISO时间、类型、manual来源的完整载荷签名绑定。相同载荷失败重试复用原键，提交不同载荷生成新键。后台仍以原唯一约束校验重复事件；全局HTTP请求键不替代事件键。

同步ref锁与busy共同防止重复点击；在途时禁用选人和打卡输入。成功后清空时间和标识，先发布成功，再刷新日结果。日结果刷新失败显示独立读取错误，不能将已提交事件报告为写入失败。补录无需刷新班次目录。

身份/园区上下文通过既有key remount重置草稿及refs，卸载后的旧写入回调不可覆盖新视图。空或非法时间不提交。保留后台时间语义与类型范围。

## Cases
- 同一载荷响应丢失后重试：同一eventKey。
- 修改员工/时间/类型后提交：新eventKey。
- 日结果读取失败：保留已补录成功提示及清空时间状态。
- 身份切换：旧请求完成后不发布新页面成功提示。
- 此合同只涵盖当前页面草稿重试，不能宣称跨页面/跨人员对同一真实事件自然键去重。

## Validation
实际页面交互测试覆盖成功、失败同键重试、载荷变化、重复点击、在途锁定、读取失败及身份切换。使用全局DS及领域布局，日期输入桌面留足空间，390px单列无水平溢出。本地合成UI和测试不替代真实岗位生产验收。
