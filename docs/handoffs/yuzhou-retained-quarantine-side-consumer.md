# Retained quarantine side consumption

`prepareYuzhouRetainedQuarantineSide(config)` is the side-mode artifact adapter used by the existing real-bundle CLI. Optional config `pairMaterials` contains `side` (`A` or `B`) and private `{ path, sha256 }` descriptors for `originalConfig`, overall `receipt`, `sideReceipt`, and `overlays`. Existing `config.envelopes`, `keyFiles`, and `artifacts.operationId` must match the selected side; `resourceDescriptor` is mandatory. Single mode is unchanged.

The consumer verifies the overall ready receipt, source config/manifest/triple/summary pins, side receipt, selected envelope/overlay byte pins and exact operation/key-reference association. Original source/target scope and shared lease root cannot be replaced. It returns deterministic projected phase bytes and SHA-256 descriptors while retaining original payload references and original-file readback pins. Overlay application changes only quarantine crypto bindings. The existing CLI then authenticates the projected records and selected ciphertext with the real crypto provider before any database work. Preparation alone does not read keys or replace this authentication step.

The preparation request accepts optional `pairSide: { materials, operationId, envelopes, keyFiles }` alongside the dedicated resource descriptor. `materials` becomes config `pairMaterials`; original prepared inputs remain untouched. Output reports that crypto descriptors were replaced rather than reused.

Side CLI execution measures clean tracked Git HEAD with the existing candidate-freeze helper. It rechecks that HEAD during binding checks and after rollback/residual completion, and independently rechecks the complete measured executor/runtime-tree fingerprints. Final private receipts retain `sideExecutionProvenance: { executionCodeSha, executorSha256, runtimeTreeSha256, sourceProvenance }`, strictly bound to the existing receipt identity. No caller current-C field is accepted by CLI. A test-only exported capture seam supports drift regression without real execution.

`sourceProvenance.preparedTriple` remains the old preparation identity; `currentCommitVerified: false` describes this source-only provenance, not the separate measured execution commit. Ledger/manifest binding still uses the source preparation C for compatibility. A later formal pair owner must consume the distinct measured execution C rather than relabeling that source C. This slice does not provision resources, establish cross-side trust-root provenance, run two sides or produce formal finalRehearsalPair evidence.
