# Exception preparation design

Two explicit modes in one private-file CLI: prepare and finalize. No shell plugins or arbitrary callback modules may be loaded from config.

Prepare consumes the same authenticated phase/candidate/inventory/scope descriptors as freeze plus explicit quarantine field/ref choices, operationId and external key reference/file descriptor. Reuse the freeze validator in no-review mode to validate candidate integrity before selecting quarantines; avoid retaining redundant whole-file copies. Only quarantine is in this task; reject non-quarantine review requests rather than silently approximate skip/merge. Validate exact selected exception coverage and original reason preservation. Normalize partial fields using the existing target model. Construct the existing crypto context with payload hash before creating AES-GCM envelopes, then construct existing unsigned decision and exact attestation binding. Emit a private unsigned request plus the existing execution crypto-envelope shape; do not generate signatures or identities.

Finalize reads the immutable prepared artifact/envelopes plus externally signed attestation bytes and pinned allowed public keys. Verify signatures cryptographically over the exact canonical binding and match the key to that explicit input allowlist. This proves signature integrity against supplied trusted keys, not the human's authority; final execution approvals remain independent. Assemble the existing reviewed_candidate_resolutions shape without re-encryption, and validate through existing freeze (or the same shared reviewer validation boundary) before declaring the output prepared. Retain exact source/candidate/evidence references. If shared validation needs extraction, keep it narrow and backwards-compatible.

IO follows the existing materializer: owner-only canonical 0700 directories / 0600 single-link no-follow files; config <=1 MiB, key exactly32bytes, bounded review metadata and aggregate budgets no larger than existing freeze limits; exclusive outputs, fsync/hash readback, receipt last; stable aggregates/errors only. Keys are cleared in finally. No production keys/values used during development. Preserve failed outputs and do not overwrite prior preparations.

Implement the shortest usable chain; report any actual schema incompatibility instead of creating an alternate plan model. Do not edit execution contracts, allowlist, database migrations or semantic source evidence. Source preservation is explicit and distinct from normalized encrypted projection; do not claim encrypting {} preserves the legacy row.
