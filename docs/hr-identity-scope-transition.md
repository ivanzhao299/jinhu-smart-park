# HR 身份范围过渡：真实园区回填与双约束

本片属于 M1/P1-P2 的数据库过渡步骤，不是完整独立 HR 登录或生产迁移。
沿用 `hr-standalone-auth-profile-audit-design.md` 第 3.3 节：先加列、回填并验证，
再改写入路径，最后才放宽旧 `park_id` 约束。不得一次性全库改 nullable。

## 本片实现合同

- 显式可选组件 `database/components/business-scope/000003_smart_park_identity_transition.sql`
  依赖同目录的 core 和真实 park binding；不加入默认生产迁移或启动链。
- 用户增加默认业务范围；park 角色、角色授权关系、refresh 会话增加范围引用。
  tenant/platform 角色和权限仍是租户级定义；认证身份不为每个 scope 复制一套。
- 旧 `park_id NOT NULL` 和旧唯一索引保留；NULL 新范围列表示尚未过渡，不代表企业模式。
  一旦填写范围，必须符合真实 `(tenant, scope, park)` 绑定和同租户用户/角色/权限引用。
- 显式函数 `backfill_smart_park_identity_scopes(text)` 只修改指定租户的新增范围字段，
  锁定相关表、检查所有映射，失败全部回滚；只返回数量，不返回账号或会话内容。
  不改密码、token、状态，不增加成员资格、模块授权或角色权限。
- 缺失/歧义/删除的园区映射、跨租户关联、已填范围漂移、未来租户级身份唯一性冲突
  必须拒绝；不得猜测、合并用户或静默覆盖。重复调用不得重复改写。

## 验证计划

测试使用独立 PostgreSQL 容器，在合成租户、园区和用户上执行仓库实际身份/RBAC/Auth
迁移文件及可选组件。验证首次回填、重入、外租户不变、状态与授权不变、失败原子性、
复合外键及反向漂移拒绝，以及只读账号无执行/写入权限。
现有 runner 的磁盘门禁、512 MiB tmpfs、loopback 随机端口和精确清理继续复用。
所选迁移子集证明本片依赖闭包，不替代完整生产迁移史、真实数据冲突盘点或 HTTP 登录。
