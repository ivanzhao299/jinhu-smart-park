# 三模块现代化只读审查

## Goal

对共享房产控制面、民宿管理、长租经营三个模块开展零产品代码改动的现代化只读审查，从设计方案、开发实现、测试覆盖率、界面交互四个维度形成可执行的问题清单与修复路线，为后续是否实施提供可靠决策依据。

## Requirements

- 审查基线必须来自 `origin/main`，不得触碰 `codex/hcd-uat-deep-final` 及其 5 个未提交文件。
- 审查范围包括三模块的归档 Trellis PRD/design、当前 API/Web/shared 实现、相关迁移与文档、单元/契约/E2E 测试，以及既有 HCD UAT 证据。
- 设计维度核查设计到实现漂移、Party/单元/经营配置/租约/预订领域一致性和状态机完整性，并覆盖 LEA-003、mode×用途矩阵、IDY 系列同步情况。
- 实现维度抽查 endpoint 的分层、重复、错误处理、事务/幂等、N+1、权限，以及跨模块耦合、共享层膨胀和 TODO/FIXME。
- 测试维度按模块×层输出覆盖矩阵，区分测试存在性与断言深度，重点覆盖资金、审批和状态迁移。
- 界面维度按现代 B 端惯例评估信息架构、列表、表单、反馈、一致性、效率和 390px 移动端；复用 HCD UAT 现有证据，不重复截图或接管 Chrome。
- 报告中问题编号统一为 `PMA-*`，分为 P0/P1/P2，每项必须有可核验证据（`file:line` 或已有截图/报告说明），不得伪造证据或写入敏感信息。
- 修复方案按速赢/中期/大改分组，标明改动面、风险和验证方式；UI 问题优先给组件级统一方案，不做逐页补丁设计。
- 单列需要用户决定的产品/架构问题；不开实施 Issue，不改产品文件，不操作生产。
- 仅提交 Trellis investigation 任务、研究材料（如需）与 `docs/reviews/property-modules-modernization-audit-2026-09-04.md`。
- 完成报告 PR、至少一轮独立 review、CI、合并，并确认 main 双绿后收尾。

## Acceptance Criteria

- [ ] 报告覆盖四维标尺并明确三模块总体与分模块结论。
- [ ] 所有 PMA 发现具有严重级别、影响、证据和建议，分级统计与正文一致。
- [ ] 测试覆盖矩阵按共享房产控制面/民宿/长租 × API service/controller/Web page/契约/E2E 展示现状与空白。
- [ ] 修复方案包含速赢/中期/大改、改动面、风险、验证方式和组件级 UI 方案。
- [ ] 报告包含需用户决策点，且不创建任何实施 Issue。
- [ ] `git diff` 证明无产品代码改动，原 HCD 工作树 5 个未提交文件保持原样。
- [ ] 报告分支基于 `origin/main`，无 force push，仅该分支被 push。
- [ ] PR 完成独立 review、CI 通过并合并；合并后的 main 所需检查双绿。
