# 调查设计

## 边界

本任务是只读产品语义审计。允许读取代码、迁移、文档、测试、Git 历史、GitHub PR/Issue/checks；允许写调查任务材料、报告与收尾记录。禁止产品代码、数据库、配置和生产环境变更。

## 证据模型

1. 当前事实以 `origin/main` 上实体、DTO、service/controller、shared 类型、Web 表单/picker/看板、迁移与测试为准。
2. 演进事实以 commit diff、PR/Issue 元数据和同期任务/文档为准；会话史只作为定位线索。
3. 每个关键结论区分：当前代码事实、文档/测试合同、历史意图、推论。
4. 引用优先记录稳定符号、文件路径与行号；历史结论记录 commit SHA 与 PR/Issue。

## 调查切面

- 数据面：资产单元列、枚举/校验、operation config 表及状态机。
- 契约面：shared/API DTO、查询参数、picker 返回与双端消费。
- UI 面：资产表单与展示、民宿/长租 picker、统计/状态看板、领域文案。
- 业务面：用途、出租状态、单元状态、operation mode、租约/入住状态的职责与驱动关系。
- 历史面：用途标记方案、民宿 MVP、住房 MVP、#408/#414 及相关修复战役。

## 方案评价框架

对 A/B/C 与可选组合方案统一评估：数据模型/迁移、shared 双端契约、picker 合同、UI/文案、审批链关系、风险、验证方式；另比较语义清晰度、误配置风险、存量兼容、实施复杂度与可运营性。

## 兼容与回滚

本任务不产生运行时变更，无产品回滚。报告若被否决，仅关闭/修订 PR；任何后续实施必须另行批准并新建实施任务。
