# 修复 Issue 216 新增用户园区显示异常

## Goal

修复系统管理用户新增/编辑抽屉中的园区选项展示：用户应看到可理解的园区名称，而不是内部园区 ID 或纯数字历史名称，同时保持园区候选项严格按所属租户隔离。

## Confirmed Facts

- 复测截图中新增用户已加载一个园区，但显示为 `11 / 24077169`；这不是空列表。
- 新增与编辑共用 `/tenants/:tenantId/login-settings` 返回值和同一套 JSX，接口返回 `parkName`、`parkCode`、`parkId`。
- 正常园区也被拼接展示内部 `parkId`；历史数据中的 `parkName=11` 会导致整个标签几乎全是数字。
- 用户写入端会校验园区归属，因此不能通过加载其他租户园区来修复显示问题。

## Requirements

- 默认园区和可访问园区必须复用同一个展示名解析函数。
- 有可读园区名称时仅展示业务名称，不暴露内部 `parkId`。
- 园区名称缺失、空白或仅由任意 Unicode 数字与空白组成时，使用当前租户名称生成明确的兜底标签。
- 多个园区得到相同可见标签时，仅为冲突项追加唯一园区编码，不能追加内部 ID。
- 追加园区编码后必须再次检测最终标签，避免与真实业务名称形成二次碰撞。
- 园区候选集合、默认选择和可访问园区选择语义保持不变。
- 新增、编辑及切换租户均使用一致的标签规则。
- 租户开通时的初始园区名称必须包含可读的非数字字符，Web 与 API 同时校验。

## Acceptance Criteria

- [x] `金湖科创产业园 / 20000001` 显示为 `金湖科创产业园`。
- [x] `parkName=11`、`parkId=24077169` 且租户为 `测试租户01` 时显示为 `测试租户01默认园区`，界面不再显示纯数字串。
- [x] 默认园区下拉框与可访问园区列表使用相同标签。
- [x] 测试锁定正常名称、纯数字名称、空白名称及不暴露内部 ID 的行为。
- [x] 新租户不能省略初始园区名称，也不能使用 `11`、`１１`、`١١`、数字加空白或纯空白，但 `11号园区` 合法。
- [x] 同名园区和多个异常历史名称用园区编码区分，唯一标签不追加编码。
- [x] 追加编码后与真实园区名称碰撞时继续消歧，最终所有候选标签唯一。
- [x] Web 相关单测、lint、typecheck、build 与 `git diff --check` 通过。

## Out of Scope

- 不跨租户展示或绑定园区。
- 不自动改写数据库中已有园区名称。
- 不改变用户的默认园区和可访问园区保存协议。

## Notes

- 用户已明确要求按既有流程直接修复，无待确认的产品决策。
