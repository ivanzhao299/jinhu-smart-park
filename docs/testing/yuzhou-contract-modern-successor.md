# 历史合同衔接现代办理

生产只读诊断37091605507在上海业务日2026-10-03确认：当前业务范围内98名员工各有一份历史active合同，结束日期均早于观察日。历史状态保留原事实，不批量改为expired。

## 办理规则

创建或编辑现代合同、生效以及非终止变更的创建/应用，均在同一事务持有当前范围员工锁后核对其他draft/active合同。
现代draft/active仍阻止重复办理。历史draft、日期缺失或无效、尚未结束、结束日期与新开始日期重叠或同日均拒绝。
只有历史active合同的明确结束日期严格早于数据库上海业务日，并严格早于新开始日期，才允许作为前序事实继续办理。
多个前序须全部满足，不从开始日或其他字段补猜结束日期。

现代合同source_snapshot及每次合同动作快照记录historicalPredecessorContractIds，供内部追溯；公开投影不增加原始快照。
历史行、来源哈希、原合同号及历史变更不修改。现代编辑切换员工时重验新员工前序，动作快照保留当时引用。
取消和终止沿用原状态链；累计期限、首次/最近签订日期及历史续签次数不由本修复推导。

## 验证边界

纯函数和HR基础契约验证合法前序、未知/无固定期限、日期边界及现代重复。
HR_CONTRACT_SUCCESSOR_PG_REQUIRED=1启用实际服务PostgreSQL测试，只允许现有本地导入实验室55491/55492、postgres数据库，随机schema与合成数据。
测试覆盖创建/编辑/生效/续签应用、重叠与范围拒绝、并发一名员工只产生一个现代草稿、动作失败事务回滚、原历史行不变及薪资权限；结束删除随机schema并断言不存在。
该数据库测试从现有实体生成测试表，不冒充完整生产迁移、历史触发器或真实岗位验收。没有新增数据库迁移。

最终发布仍需CI、合并及运行版本一致、健康和部署清理；真实HR/主管/员工办理验收独立记录。本修复不启用发薪、不重放导入、不改变权限。
