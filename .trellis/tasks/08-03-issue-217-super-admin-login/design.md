# Design

## Boundary

认证服务在密码匹配、锁定刷新与账号启用过滤完成后，对候选执行角色语义选择。超级管理员判定复用签发登录结果时的有效角色规则：关联未删除，角色启用且未删除，并且 `role.isSuper=true` 或有效权限包含 `*`。

## Selection Contract

- 唯一超级管理员候选：只让该候选进入租户有效性检查、成功状态 finalizer 和 token 签发。
- 零个超级管理员候选：保持现有普通候选集合和跨租户/同租户行为。
- 多个超级管理员候选：保持跨租户冲突，避免不确定身份选择。

选择发生在密码验证之后，不能泄漏角色信息或让仅同名账号获得平台权限；选择发生在成功 finalizer 之前，避免清理或更新未被选择的普通账号登录状态。

## Compatibility

不变更数据库、DTO、JWT 字段或前端请求。平台管理员仍以唯一超级用户记录的 tenant/park 作为运行时基准 scope，普通多租户登录行为不变。

## Prevention

以行为测试覆盖唯一超级、零超级、多个超级及同租户多园区矩阵，并在 API 认证规范记录“认证后按有效角色选择，禁止用户名特判”的契约。
