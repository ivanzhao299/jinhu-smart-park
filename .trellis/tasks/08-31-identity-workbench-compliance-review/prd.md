# 身份核验工作台设计实现与大陆合规核查

## Goal

在零产品代码改动、零生产直操作的前提下，对共享房产控制面“身份核验工作台”完成设计方案、当前实现、仓库内使用说明三方闭环核查，并基于中国大陆公开法律与住宿业运营要求完成工程适配评估，形成可审查、可追溯的报告。

## Confirmed Facts

- 核查对象包括 Web 身份工作台与提交详情、property-operations party 身份 API/策略/DTO、access-manifest 权限定义。
- 设计基线是归档任务 `07-30-pr192-b-identity-control-plane` 的 PRD/design/implement，并需结合 `homestay-identity-checkin-atomic` 与 `party:identity_update` 的实际闭环。
- 交付物仅允许新增/更新本调查任务材料和 `docs/reviews/identity-workbench-compliance-review-2026-08-31.md`；不修改产品代码、测试、迁移、配置或生产数据。
- 法规评估是公开法律框架下的工程对照，不构成法律意见；上线前需法务复核。

## Requirements

1. 从设计源提取编号为 `IDY-*` 的可检验要求，每条包含原始出处、判据和设计语义。
2. 对状态机、字段/证据、审批或自动核验、幂等/原子性、权限/数据范围、民宿与住房消费链逐条给出“已实现/部分实现/未实现/实现超出设计”，并提供当前仓库 `file:line` 证据。
3. 核查仓库内使用说明是否存在，并验证菜单入口、操作步骤、字段说明与实现一致性；缺失或漂移均记录为 gap。
4. 以中国大陆官方公开来源为依据，评估实名登记、敏感个人信息、公安治安系统对接、核验方式、未成年人/证件有效期/虚假证件、留存与导出。
5. 对证件号与照片的加密存储、脱敏展示、访问控制、留存、删除/注销、告知同意、日志泄露、文件权限逐项核查。
6. 问题按 P0/P1/P2 分级；每条包含证据、建议改动面、迁移需求、验证方式及待用户决策点。不得创建实施 Issue。
7. 不在报告中写入真实敏感信息；示例也不使用真实个人证件数据。
8. 完成报告 PR、一次 review、CI、merge，并确认 main 双绿；仅推送报告分支，通过 `gh pr merge` 合并 main，不 force push。
9. 不操作生产环境、他人容器、主 Chrome 或 HR 系列范围。

## Acceptance Criteria

- [x] 存在一份日期化报告，包含设计要求矩阵、实现闭环、使用说明核查、大陆场景评估、分级问题、建议、决策点及法律免责声明。
- [x] 每个 `IDY-*` 和每个问题均有可复核的仓库证据；法规主张有大陆官方公开来源链接。
- [x] 对证件类型全集、提交状态全集、核验记录、生效/失效、幂等键、事务原子性、民宿/住房消费链均有明确结论。
- [x] 报告明确区分“代码已证实”“文档设计要求”“工程推断”“需产品确认”“需法务确认”。
- [x] 使用说明存在性与实现一致性结论明确。
- [x] 问题分级统计与终报一致，且不开实施 Issue。
- [x] git diff 不包含产品代码改动；任务材料和报告通过 Markdown/链接/敏感信息检查。
- [ ] PR 至少完成一轮独立 review，CI 通过，合并后 main 所需检查双绿；若外部系统阻断则保留真实证据并持续等待或如实报告。

## Out of Scope

- 修复任何发现的问题。
- 创建实施 Issue、迁移、第三方核验 PoC 或公安接口对接。
- 生产部署、生产数据抽查、真实身份数据采样。
- HR 模块及与本核查无直接关系的重构或文档整理。

## Open Questions

无阻断性开放问题。第三方核验供应商、留存期限、脱敏范围、公安接口路线等作为报告决策点交由用户、产品与法务后续确认。
