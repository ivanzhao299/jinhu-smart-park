# Design

Reuse existing source-preview/freeze operations and ReconciliationSourcePreparation, adding explicit contextual selection props or a small composed flow. Modern Trial book cards expose preparation under existing review authority; callbacks refresh source catalog and retain committed source identity before refresh. The original standalone source preparation remains compatible. Do not copy the legacy dual-track formula or net-policy workflow into formal calculation.

Extend formal preparation query with optional reconciliationSourceId. Resolve a scoped frozen reference under current receipt/control binding and existing source-reader/hash rules, matching period.month and rule_set.source_book_id. Validate complete record ownership/employee availability, duplicate census and bounded roster. Return optional scoped source identity/hash/count metadata and filter employee pages to precisely that set, preserving current employee versions and eligibility advice. A response must never manufacture payroll eligibility from historical presence. Preserve existing normal/correction behavior; source mode is ordinary open-period preparation only, reject incompatible correction mode explicitly.

Connect an explicitly selected/frozen source to PayrollInputPreparation via ModernWorkspace state. Rule and period remain business choices constrained by selected source; no autoapproval. Clear incompatible selections on source/rule/month/auth changes. Bulk roster addition reads all bounded pages100, checks consistent period/rule/source/hash/head/count and unique employee IDs before applying once. Preserve explicit existing values only for identical selected source and versions; otherwise initialize direct projects with empty strings. Keep manual settlement windows/reasons required. Persist via existing draft API, with no new source payroll result write. The selected immutable reference is preparation context; do not claim existing input storage records provenance it does not persist.

Extract a bounded internal read helper only when needed to reuse source guards rather than duplicate or weaken them. Frozen JSON monetary payload must never be JSON.parse into Number; roster read only projects identity/count/hash, not amounts. Use SQL numeric/text rules if any monetary source is touched inadvertently. Keep existing trial engine/formal duplicate protections untouched. No table migration or permission broadening.
