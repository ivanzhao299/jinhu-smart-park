# Technical Design

## Boundary

用户管理的显示修复限定在 Web；API 继续返回租户范围内的完整园区业务对象，写入端的租户归属校验不变。为阻止同类脏数据继续产生，租户创建 DTO 对初始园区名称补充规范化后的业务名称校验。

## Label Resolution

在现有 `user-park-options.logic.ts` 中增加纯函数：

1. 移除 `parkName` 中的 Unicode Default_Ignorable_Code_Point，执行 NFC、修剪并把连续可折叠空白规范为单个空格。
2. 名称包含至少一个 Unicode 字母/表意文字时直接作为业务标签。
3. 否则以同样规则规范当前 `tenantName`，返回 `${tenantName}默认园区`。
4. 若租户名称也不可用，返回通用 `默认园区`。

批量解析所有候选项的规范化基础标签；标签重复时，仅为冲突项追加全局唯一的 `parkCode`。编码中的非 ASCII 代码点和空白均使用 `\\u{CODE_POINT}` 可见转义，反斜杠自身加倍，确保原始唯一编码不会被 NFC 或 HTML 空白折叠合并。每轮先规范化完整生成标签再检测碰撞；若追加结果与真实业务名称再次碰撞，继续为新冲突组追加各自编码，直到所有可见标签唯一。表单的默认园区 `<option>` 与可访问园区 checkbox 统一读取该映射。`parkId` 仅保留为表单 value/key，不进入可见标签。

## Compatibility

- 无 API 响应、数据库或迁移变更。
- API 响应与数据库无变更；租户创建请求中不包含 Unicode 文字的 `parkName` 从接受改为 400。
- 历史纯数字、标点或不可见格式园区名称即时获得可读兜底显示。
- 正常业务名称按原值展示，仅移除内部 ID 后缀。
- 同名园区仍由隐藏的唯一 `parkId` 绑定；本次不改变选择协议。

## Risk Control

- 单元测试覆盖正常、空白、纯数字、租户兜底和内部 ID 不泄露。
- DTO 测试覆盖省略、ASCII/全角/阿拉伯数字、小数、标点、零宽字符和空白拒绝及含数字的可读名称接受。
- Web 测试覆盖 Unicode 数字兜底及正常/异常标签碰撞时的园区编码区分。
- Web 测试覆盖追加编码后与真实业务名称二次碰撞的链式消歧。
- Web 测试覆盖渲染时会折叠的空白等价名称碰撞。
- Web 测试覆盖内部空白数量不同及含反斜杠的园区编码可逆显示。
- Web 测试覆盖 NFC 等价业务名称及组合形式不同的园区编码可逆显示。
- Web 测试覆盖 U+200B 等不可见格式字符造成的视觉等价名称。
- Web 测试覆盖 U+034F 等默认不可见组合标记，并验证重复 `parkId` 候选在渲染前稳定去重。
- API/Web 测试覆盖默认不可见但分类为 Letter 的 U+3164/U+115F，锁定“先移除、后判断”顺序。
- 源码断言确保两个控件都使用统一 helper，防止后续一处回退为字符串拼接。
