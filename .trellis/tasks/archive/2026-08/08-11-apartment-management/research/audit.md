# 公寓管理现状审计（2026-08-11）

## 可复用能力

| 能力 | 现状 | 结论 |
|---|---|---|
| 房源主数据 | `asset_unit` 已含园区、楼栋、楼层、房号、用途、面积、状态 | 复用，公寓只做扩展档案 |
| 房源占用 | `biz_property_occupancy` 已处理民宿/住房出租跨业务占用 | 扩展 `apartment` 域并复用冲突保护 |
| 人员档案 | `biz_party` 与 `sys_user` 并存 | 支持有账号/无账号入住人 |
| 住房交割 | 住房出租已有入住/退房交割、照片、钥匙和物品快照 | 复用交互与校验模式，不复用租约表 |
| 审批 | Property Approval 支持复杂高风险财务效果 | 公寓首期使用领域状态机/决定表，避免不必要耦合；保留适配口 |
| 文件 | `sys_file`、共享上传组件和业务附件校验已存在 | 复用并增加公寓 biz_type 策略 |
| 消息与待办 | `biz_user_message` 和 workflow 收件箱已存在 | 增加公寓来源类型和深链 |
| 移动端 | 共享 DS 和原生 App bootstrap 已存在 | Web 先移动优先，后接原生 capability |

## 不应直接复用的部分

- `biz_housing_lease` 强制租期、月租、押金、首个账单日等商业字段，不适合零租金福利宿舍。
- 住房出租页面包含账单、财务、采购转收费，暴露给 HR 会造成职责和隐私边界混乱。
- Property Approval 当前执行器重点覆盖财务副作用；公寓资格审批无需引入该复杂度。

## 缺口

- 没有独立公寓/宿舍模块、床位粒度、福利入住资格申请和退房闭环。
- 没有承诺书等模板版本与“某次入住冻结文档包”。
- 没有公寓专属权限、菜单、待办和移动操作界面。
- 仓库未提供集团正式入住申请表、安全消防承诺书正文；只能先建设模板机制，正式内容需业务/法务确认。

## 自审结论

- 独立模块避免污染商业住房财务数据，边界正确。
- 复用资产与占用能保证跨业务房源一致性，避免另建房号孤岛。
- 房间+床位模型覆盖单人公寓和多人宿舍，后续无需破坏性改表。
- 角色授权以业务角色为中心，吴恩国权限可审计且可撤销。
- 模板版本冻结和签署件哈希满足档案可追溯要求。
- 方案不存在阻塞开发的产品歧义；正式文书正文和真实房源数据作为上线门禁，不阻塞基础开发。
