# Payroll rule choice local CSV preparation

PayrollRuleSourcePreparation retains the complete source review export and adds a separate complete item-version choice sheet. Each item version appears exactly once, regardless of visible page or current inclusion. Current source-reference rules/books/IDs, item metadata and all formula versions, orphan formulas and raw conditions participate in a SHA-256 drift marker; the marker is never authorization or rule approval. No UUID columns, guessed roles, implicit tax values, latest-version selection or condition removal.

The sheet uses protected text and a fixed header with read-only source metadata plus explicit inclusion/exclusion, Chinese accounting role/source, exact original formula number/version and rewrite. All rows and read-only fields must match the current source. Blank selection preserves only when all editable fields are blank; explicit exclusion carries no effective rule fields. Excluded exports omit dormant role/formula data. Incomplete local inclusions can be exported for completion, but cannot become an applied invalid selection. Same-code duplicate versions, unsupported/disabled/nondecimal selections, ambiguous formulas and conditional originals reject the entire preview. Rewrites retain the existing 2000-character bound.

Reuse LocalFilePicker, strict UTF-8/MIME/32MiB validation, csvDocument and the bounded existing payroll CSV parser. Its configurable cell bound may cover the complete authorized original-formula catalogue while the input sheet default stays1024; row/column/byte bounds remain enforced. Never truncate original formulas or evaluate spreadsheet content.

Reading and preview do not mutate choices. Paginate every changed choice, require explicit confirmation, re-read the scoped source API and require the same loaded token/rule/book/full content before replacement. A denied/failed/drifting re-read preserves choices and blocks final draft application until successful reload. Manual edits, reload, context/permission/disabled changes, token changes, unmount and newer operations invalidate old previews/readers. Keep synchronous locks for export/read/confirmation; the parent clears its original review confirmation when replacing choices. The existing final bring-into-empty-editor, save, parser/financial validation and independent review remain authoritative.

Original-condition eligibility must match the source-reference API: only `condition?.trim()` being nonempty establishes an original condition requiring rewrite. Null, empty and whitespace-only original text remain unchanged in the full SHA/read-only evidence, but do not make an otherwise reusable original formula impossible to select. Cover both manual selection and local CSV through the final draft callback; nonempty conditions still reject even with a contradictory reusable flag.
