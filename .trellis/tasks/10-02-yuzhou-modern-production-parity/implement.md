# 长任务分步实施计划

本文件是长任务执行入口；实施已经启动，S0收口与S1聚合核验已完成，当前按checkpoint.json推进账号关联和角色验收。步骤独立验收，遇局部人工等待继续不依赖它的工作。

## 0. 恢复与基线（每次续接）

- [ ] 读 prd.md、design.md、checkpoint.json、上一个切片回执；读取本阶段规格及精确代码。
- [ ] git fetch --prune origin；记录当前/远端 SHA、dirty/WIP、修改重叠；实现用最新主干的独立 codex/* 候选。计划目录先保护，不覆盖。
- [ ] 核对真实运行版本和相关输入；仅在输入、代码和环境均未变化时复用测试。
- [ ] 活跃生产写入/runner只能一个，先检查旧句柄，禁止重放三批成功导入。

## S0. 历史隔离低成本收口（优先，初始预算两小时）

依赖：实际三批回执与旧归因清单。责任：异常处置材料及确有必要的只读查询；不动生产业务数据。

- [ ] 按本次实际导入批次生成匿名化异常分组，核对1608守恒；与历史台账差异单独列出。
- [ ] 只读关联当前在职/有效合同/开放工资社保期间/账号权限，交叉核对145工资、6照片记录，不重复计算人员。
- [ ] 明确无当前影响的历史记录列为 ARCHIVED_HISTORICAL；无法判断的进入 CURRENT_IMPACT_REVIEW，不猜日期、身份或符号。
- [ ] 缺1003附件原件和794空照片按源缺件收口；只有当前业务必需才追补原件。
- [ ] 输出至多五类人工决定，与 private 明细引用和业务影响关联；等待不阻断其他功能。
- [ ] 保留旧候选口径为历史记录，不修改旧回执；真实守恒使用1608，不从推测推导结果。

出口：分类数量之和1608、个人明细未泄露、活跃修复仅当前影响项、历史项退出修复队列。两小时到达时记录未知项并停止历史考证；不要求隔离清零。回退：只恢复本轮新处置清单，不删原数据。

## S1. 真实数据可用与运营清单（紧接S0）

依赖：已导入数据；不依赖历史隔离全部人工裁决。责任：查询入口、必要API/Web修复及角色验收材料。

- [ ] 建立组织、人员、档案照片、异动、合同、社保、历年工资任务卡；每项列角色、输入、预期、实际、缺陷、证据。
- [ ] HR/负责人/员工分别验证桌面及390px；验证本人/组织树/全域、直接ID越权、敏感字段及文件、分页导出、切换清除旧敏感数据。
- [ ] 验证较早年度工资及档案从页面可达；无当前页面则做最小查询修复。
- [ ] 当前人员主档/岗位/合同/账号关联错误列P0；旧离职资料缺件列归档限制。
- [ ] 同步刷新备份后增量和集团Web来源的只读范围清单，按当前运营影响分级，不直接再次写库。

出口：核心查询任务全部有实际结果；相关P0为0或该模块明确未启用，不能用health代替。回退：切片应用回退，不删除导入历史。

## S2. 当前人事运营与合同等价

依赖：S1人员、权限、组织基座；历史只读不受阻。责任：已有组织、人事、入职、转正、调动、离职、复职、合同及提醒实现。

- [ ] 对照旧客户端和Web各自的动作/字段/状态/编号/审批，复用现有代码，补真实差距。
- [ ] 验证申请→审批→生效/撤回/驳回/作废的合法链、并发、重复请求、前后快照、审计和提醒。
- [ ] 验证主合同、续签、变更、终止、到期边界，敏感附件权限和负责人组织范围。
- [ ] 以当前业务影响为限修复S0人工确认项，新批次精确补导并核对，绝不重跑旧批次。

出口：HR及负责人可完成当前常用任务，关键正向/负向/并发场景通过，人工岗位试用有记录。

## S3. 考勤、社保到工资输入闭环

依赖：S2当前任职和组织已可靠；可先独立验证已有流程，不等全部旧端补证。

- [ ] 排班/打卡→异常→请假/加班/出差审批→日/月结果→月结，逐项比较旧规则和现代规则版本。
- [ ] 社保政策、生效期、基数、个人/单位金额、调整/补缴/更正形成可追溯台账。
- [ ] 将考勤与社保结果绑定工资期间，验证十进制、跨月/跨年/调动边界、关账后更正和访问范围。

出口：一个实际业务期间的输入链可核对；未知旧符号不进入自动核算。

## S4. 工资生产核算与旧规则等价（高优先级金额切片）

依赖：S3所需输入及HR/薪酬实际规则；与历史工资查询分开。

- [ ] 清点工资账套/项目/条件/公式/税率/顺序/精度；登记每个未解析规则的业务影响，禁止执行遗留动态SQL。
- [ ] 重点核对基本工资、岗位工资、考勤扣补、社保、税及企业实际使用的计件规则；不使用的旧规则保留差距，不假称已等价。
- [ ] 只算不发的双轨结果对账，明示容差与差异原因，由薪酬/财务处理当前金额争议。
- [ ] 验证复核→确认→关账→更正批次、终态不可变、幂等/锁/审计、本人已确认工资条。
- [ ] 发薪/报盘/税务接口若需启用，先完成具体结果和验证，再使用对应明确授权；旧导入批准不自动覆盖。

出口：批准的实际业务期间规则和金额核对通过，未解释差异为0；无此证据不得替代正式发薪。

## S5. 玉舟功能复现与高频报表

依赖：各领域基座；HR必用报表可提前插入S1-S4。

- [ ] Windows客户端与集团Web分别登记稳定页面/动作/规则/报表/角色ID，不合并分母。
- [ ] 招聘→入职、培训→记录/费用/结果、奖惩→审批/生效/作废/联动、绩效→方案/项目/权重/汇总及360独立验证。
- [ ] 查询统计、打印/Excel、批量导入校验与权限按业务使用频度排序，先完成当前企业必用项。
- [ ] 对每项记录 source-observed / mapped / implemented / tested / runtime-verified / business-accepted；缺旧证据不得以新页面存在代替。
- [ ] 集团Web独有当前人员/事实、后续增量在范围和来源优先级确认后另建受控批次；低价值历史留归档，不强制修复。

出口：当前必用项全部验收；完整复现范围仍保留剩余缺口，不用历史归档抵扣缺失业务规则。

## S6. 生产运营验收与分模块切换

依赖：准备启用模块对应S1-S5通过；无需等待所有冷门功能。

- [ ] 设置并记录响应、分页、导出、后台任务容量预算；真实数据实测，按结果修复瓶颈。
- [ ] 验证三角色生产任务、权限负例、敏感访问审计、日志脱敏、失败恢复、告警及备份恢复；明示RTO/RPO实测。
- [ ] 明确每模块的新旧权威来源、增量截止点、双写限制、回退责任人；业务签署后按明确范围启用。
- [ ] 每次发布核对候选/合并/实际运行SHA与health/ready/页面行为，完成Docker清理。

出口：启用模块P0=0，角色任务和金额/状态闭环有证据；旧系统按明确模块转只读，不能自动全站停用。

## S7. 独立HR产品最终验收

依赖：集成版运营稳定；P0依赖盘点可提前做但不阻塞集成版首轮运营。

- [ ] 按现有P0-P4拆解依赖、同内核双模式启动、独立HR数据库/文件/身份权限审计。
- [ ] 迁出完整数据、规则字典、历史审计、来源映射和文件到另一隔离企业，回读/重放/恢复/回滚核对。
- [ ] 两种模式完成核心流程、权限、桌面/390px、性能及升级恢复验收。

出口：原M0-M5与P0-P4逐项通过才称完整独立产品；不以平均分抵消缺项。

## 验证命令与证据策略

- 本轮规划：task.py validate、Markdown/JSON引用和数据守恒检查、git diff --check；不启动写库/全量测试。
- 每个实现切片：读取现有package.json与测试入口后选相关单元/API/PostgreSQL/状态机/RBAC/文件测试，禁止猜测命令名。
- 覆盖报告：node scripts/hr-cutover/report-legacy-group-web-implementation-coverage.mjs；node scripts/hr-cutover/verify-legacy-compatibility-coverage.mjs。评分器输出只是对应证据口径，不能作整体功能百分比。
- 跨API/Web/shared变更按范围跑lint/typecheck/build，前端改动实际桌面/390px浏览器检查；DDL触发fresh-schema Release Smoke及升级/校验和验证。
- 工资及关键金额测试用PostgreSQL numeric/十进制，覆盖边界和反例；敏感原始输出仅本地0600，不进入文档。

## 首轮节奏与长任务控制

首轮执行目标：先交付S0收口清单，再交付S1真实可用矩阵，随后选S2最小当前业务缺口。首轮只读核验后才能估算各模块剩余工时；不沿用旧14-40周估算，不承诺未知全量复现日期。

每片结束更新checkpoint与验收矩阵。等待人工时冻结对应动作，继续无依赖工作；状态不变不循环模型轮询。新目标/代码/输入漂移记录增量，不重建所有已通过证据。财务、权限和数据关系缺陷必须验证，历史非运营异常按归档策略关闭。
