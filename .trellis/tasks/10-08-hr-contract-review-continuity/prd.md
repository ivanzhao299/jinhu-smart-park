# 正式合同信息补全与业务延续

属于玉舟 HR 现代化长任务 S2，不替代完整 S0-S7 目标。生产版本 e321e284 已部署；原始档案及别名补充输入已准备，页面提交等待正常 HR 会话。此等待不冻结本切片。

## 已核实问题

合同表支持 needs_review，但 API 编辑仅接受 draft，状态办理仅接受 draft，变更仅接受 active；现代页面也只给草稿编辑入口。待复核合同无法补全资料并进入正常办理流程。当前代码已经取消按导入来源禁止合同办理，旧规格的整行历史不可变描述已过时。

## 行为

- 复用正式合同 ID 和现有字段表单，HR_CONTRACT_MANAGE 用户可补全 needs_review 合同，保存为 draft；确认生效仍是独立操作。
- 请求携带打开表单时的 expectedVersion。园区、合同、员工、类型、编号、待办变更和其他有效合同在事务内核对；过期版本及并发重复不得覆盖。
- 保留原始 source_snapshot 的来源事实；追加办理快照记录补全前后字段与状态，失败回滚。
- 隐藏薪酬字段在请求中省略并保留原值；显式工资修改仍要求 HR_COMPENSATION_MANAGE；返回值遵循薪酬读取权限。
- 来源不改变业务办理权限。明确早于上海业务日及请求开始日的已结束 active 合同可成为后续合同前驱；draft、未知或重叠期限继续冲突，不自动修改前驱状态。
- 复用全局 DS 和现有表单；失败保留输入，切换对象/账号清空过期表单上下文。

## 验收

- DTO 拒绝缺失、零、负、字符串和非整数版本，以及无效日期、空编号。
- 实际 PostgreSQL 服务路径验证资料补全、来源事实保留、同 ID/版本递增、后续正常生效、工资保留及拒绝越权。
- 外园区、错误状态、过期版本、冲突合同/编号、待办变更拒绝；并发只有一个成功；办理快照写入失败回滚全部变更。
- 实际 React 测试验证权限、版本绑定、请求字段、失败保留及 draft 结果，不调用确认生效。
- API/Web 类型检查、修改文件 lint、相关回归及桌面/390px 浏览器检查通过。
- 本切片不写生产真实合同、不决定员工签约，不猜缺失合同信息，不逐条修复冷历史。
