# 修复园区楼栋资产关联闭环（GitHub #277）

## 目标

修复资产管理中新建楼栋只能隐式落入登录态当前园区的问题，让有多园区权限的用户在新建楼栋时显式选择园区，并形成可验证的“园区→楼栋→楼层→房源”链路，同时保持现有 JWT 园区隔离边界。

## 已确认事实

- `biz_building` 已保存 `tenant_id/park_id`，缺口是 UI、接口语义和数据库完整性，而不是完全没有字段。
- 当前 `/buildings` 创建只使用 JWT `scope.parkId`；普通用户 `/parks` 也只能看到当前园区。
- `/auth/me` 已提供经过 `rel_user_park` 授权过滤的 `accessible_parks`，`POST /auth/switch-context` 是现有安全园区切换契约。
- 楼层和房源已经显式保存父级 UUID，API 会验证当前园区内的楼栋→楼层关系。
- 楼栋跨园区移动会要求同步楼层、房源以及大量业务引用的冗余 `park_id`，本任务不提供迁园能力。
- 当前页面使用 legacy `/parks`、`/buildings`、`/floors`、`/park-units`；另一套 `/assets/*` 契约字段不兼容，本任务不混合迁移。

## 需求

1. 楼栋新建表单显示“所属园区”必选下拉框，候选仅来自当前用户 `accessible_parks` 中启用且可访问的园区。
2. 选择非当前园区并提交时，必须复用 `/auth/switch-context` 完成授权校验和 token 轮换，再在新上下文调用 `POST /buildings`；不得把任意 `parkId` 直接信任为写入 scope。
3. 切换成功后前端认证状态、当前园区展示和后续资产查询保持一致；切换或创建失败必须显示清晰错误，禁止静默回退第一园区。
4. 楼栋列表展示当前园区名称；详情展示所属园区。已有楼栋所属园区不可在普通编辑中修改。
5. 楼层继续从当前园区楼栋中选择，房源继续按楼栋过滤楼层；切换父级清理失效子级。
6. 使用新的前向迁移补齐园区/父子 scope 完整性与楼栋、楼层编码的租户园区范围唯一性；迁移必须 preflight 并 fail-fast，不编辑历史迁移。
7. 为上下文切换创建、越权园区、无效园区、父子错配、唯一性和迁移失败补充自动化测试。
8. 桌面与 390px 实际页面无横向溢出，选择、错误、加载和成功状态可操作。

## 验收标准

- 多园区用户能在新建楼栋时选择任一有权园区，保存后楼栋的 `parkId` 与选择一致，并且当前上下文同步切换到该园区。
- 无权限、停用、不存在或其他租户园区不能创建楼栋；伪造请求不能绕过 scope。
- 单园区用户仍能创建楼栋，且下拉明确显示唯一园区，不依赖列表第一项猜测。
- 楼栋列表/详情可确认园区；楼栋编辑不提供危险迁园入口。
- 园区→楼栋→楼层→房源的查询、创建与父子校验通过正向/负向测试。
- migration、lint、typecheck、build、目标 unit/API/PG/E2E、CI verify 和 release-smoke 全绿。
- 最新 PR head 完成 Codex Review，所有可操作线程解决后自动合并；主干生产部署的 migration、health/ready、公开 UAT 与 Docker cleanup 成功。

## 排除范围

- 楼栋及其存量业务数据跨园区迁移。
- 全面统一 legacy 与 `/assets/*` 双套模型。
- 工程、安全隐患等横向位置级联缺陷（另行跟踪）。
- 绕过 branch protection、生产审批或真人 UAT 门禁。
