# 考勤审批与月结连续性验证

批准请假、加班、出差或更正后，日考勤必须包含最新批准来源，月结才能采用该日结果。待核对期间回到待计算；封账期间保持原值，通过日重算和显式更正生成新版本。

CI 的 Release Smoke 在已迁移、已初始化的独占临时数据库中顺序执行以下实际 PostgreSQL 套件：

- `hr-attendance-request.pg.spec.ts`：审批投影、跨月回退、通知失败回滚。
- `hr-attendance-calculation.pg.spec.ts`：日计算及其来源快照。
- `hr-attendance-month-close.pg.spec.ts`：封账、版本链、失败恢复、批准来源缺失和员工遗漏。
- `hr-attendance-approved-facts.pg.spec.ts`：补批后更正保留旧输入、无排班批准日、正确来源恢复、两种审批与计算锁序、请求版本日期漂移、退回及过期汇总。

各套件对应的 `HR_ATTENDANCE_*_PG_REQUIRED` 必须为1，不能以跳过代替通过。新增连续性套件只接受指定的本地临时库或 `APP_ENV=ci` 的 Release Smoke 临时库，连接地址必须为127.0.0.1。CI 使用120秒单测试时限和单文件并发，完整日志进入 Release Smoke 日志包。

页面验收须使用实际组件检查桌面和390px宽度：批准成功提示重算步骤，期间同步回到待计算；刷新失败须保留“已批准”结果，提示刷新核对，不能诱导重复批准。期间状态显示中文业务名称。合成传输层检查只证明页面交互，真实生产角色、真实考勤规则和工资金额验收仍需独立完成。
