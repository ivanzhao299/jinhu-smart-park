# Payroll preparation cohort

- Integrate the all-book preparation list in the existing reconciliation workbench. Require all seven API permissions before exposing the component or requesting its cohort endpoint; preserve server authorization and the existing simulation prerequisites.
- Begin with no batch/month selection. Staged and published setup sources can be chosen explicitly, while the cohort endpoint authoritatively validates source receipts and actual month records. A batch creation/publication date never supplies the payroll month.
- Display record and distinct employee counts separately, per-book record/item/formula-candidate/current-policy metadata, overlapping anomaly counts and each person's complete book membership. Show numerical attendance, historical insurance and modern insurance candidate counts plus missing/review/ambiguity notes. Candidate existence is not amount completeness or approval.
- Key the workspace by identity/scope/permissions. Abort requests on source, month, context changes and unmount; suppress stale replies and recheck the token around export page requests. Permission revocation must hide the list and abort export.
- Validate echoed batch/month/page, page completeness, safe nonnegative counts, mapping-category conservation and sums across all books. Preserve overlapping anomaly semantics; never sum anomalies as disjoint record categories. Check per-person book counts and historical insurance eligibility.
- Reuse ScopedLedgerExport for complete stable-ID paging, limits, duplicate detection and first-page drift verification. Compare source totals/book/policy metadata across export requests, escape spreadsheet formula cells, and export business labels only. Never render or export internal UUIDs, amounts, raw payloads, identity documents, contact or banking details. The downloaded CSV is a live preparation list, not frozen payroll evidence.
- Use DS cards and responsive records. Text-only ds-scene-card content needs a local single-column override; verify desktop and 390px in the browser.
- Regression tests cover every missing permission, explicit input, cross-book records, full pagination/export, invalid receipts/counts, retry, abort and token/permission changes. Actual calculation and business acceptance remain separate.
