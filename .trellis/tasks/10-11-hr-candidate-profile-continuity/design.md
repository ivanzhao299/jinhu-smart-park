## API contract
New HrCandidateProfileService owns GET candidates/:id/profile, GET candidates/:id/profile-history?page&page_size, GET candidates/:id/profile/requisition-options?keyword&page&page_size and PUT candidates/:id/profile. A route-local interceptor stores only encrypted receipt identity/version, and replay reauthorizes, reads the immutable original history version, dynamically projects sensitive fields and requires audit; no plaintext response cache. READ is required throughout; PUT and action options also MANAGE. Service repeats permissions before SQL. Sensitive field presence in PUT additionally requires SENSITIVE_READ. Action options are minimal write-owned context under the same park-wide candidate management authority, returning draft/open scoped nondeleted requirements only; no generic directory grant.

Current public snapshot: id,version,candidateNo,fullName,requisitionId,requisitionTitle,stage,source,expectedOnboardDate,latestEvaluation,convertedEmployeeId,mobileMasked,emailMasked,identityMasked,updatedAt,sensitiveAvailable. When sensitiveAvailable=true include mobile,email,identityNumber (nullable strings); when false omit those three keys entirely. Current dates are YYYY-MM-DD|null (normalize pg Date/string explicitly), updatedAt ISO second precision/fraction allowed with offset. Candidate stage is one of existing7 values.
History page items: id,before (public snapshot),after (public snapshot),changeReason,occurredAt,actorDisplayName. Before/after snapshots freeze business names/state and decrypted/masked projection is based on current reader permission. Profile-only history may have global candidate-version gaps due to other actions; do not require contiguous history versions. Options page items:id,requisitionCode,title,orgName,status; ordinary items/total/page/page_size; no hidden values or person rows.

PUT partial DTO: expectedVersion integer>=1 and changeReason trimmed1..1000 required. Optional provided candidateNo (trimmed1..64),fullName(1..100),requisitionId(UUID nonnull),source(string<=64|null),expectedOnboardDate(strict valid YYYY-MM-DD|null),mobile(existing regex1..24 nullable),email(existing email<=160|null),identityNumber(trimmed<=64|null). Reject extras, explicit undefined impossible JSON, explicit null for required/nonnullable fields rejected. At least one effective business change required; canonical same-value no-op returns400 and no history. Empty optional text normalizes to null; omitted protected fields preserve all existing encrypted/masked/hash representations. New plaintext canonicalization MUST match existing create protect: email trim/lowercase; mobile/identity whitespace removal+uppercase, using PartySensitiveDataService.identityProfile once for encrypted/masked/hash.

## Web
New CandidateProfile component initially collapsed with buttons for maintenance/history, avoiding extra requests on every candidate selection. Open performs independent cancellable current/history reads. Only manage+read renders mutable controls, sensitive inputs only after full runtime projection. Requisition action options lazy on explicit change, own keyword/page state; keep selected off-page and preserve historical current binding without revalidating unchanged value. Converted/hired displays preserved relation and no reassignment picker; other basic fields stay editable. Payload includes changed business fields only, preserves omission/null distinction. Failure keeps exact body/key/version; edits generate new intent. Conflict GET exact profile, server-vs-draft comparison and explicit acknowledgment; partial payload is recomputed against acknowledged server baseline while draft intent retained, requiring changed sensitive availability and lifecycle/requisition restrictions checked again. Strict full receipt association/version/content/state/projection guard. Successful receipt updates parent candidate list/selection/contact projection synchronously via onSaved; separate reload errors cannot repeat a successful write.
Parent integrates synchronous profileBusyRef with all clear/load/select/beginAction guards and existing mutual assessment/interview/document/action disabled state. Candidate changes/unmount abort independent reads and ignore late responses/writes; no browser persistence of private draft. DS surfaces, domain-only responsive layout.
