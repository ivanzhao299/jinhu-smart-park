# Owned insurance periods and payroll inputs

Scope: modern previews, confirmed revisions, close receipts and explicit payroll source selection. This slice is incomplete until its API, Web and payroll consumers pass; schema or DTO tests alone do not accept the business workflow.

- Keep `hr_employee_insurance_period/item` as historical facts. Modern previews and revisions have their own UUIDs; never fabricate a legacy ID or overwrite imported amounts. A historical period and modern revision may coexist for the same employee/month; every payroll request must explicitly select its source, with no silent fallback.
- Use immutable `hr_insurance_policy_version`, its definition hash and an explicitly chosen month. Overlapping policies do not select the latest automatically. Historical `rightscope` remains reference text and does not establish modern applicability.
- Resolve scope and independent capabilities before probing financial identities. Preview input supplies employee version, policy version/hash, six distinct exact bases and an explicit fund toggle. Resolve rates server-side and use the existing precise insurance calculator. A preview belongs to its actor and scope, has bounded expiry, and hashes canonical input plus exact result.
- Preview creation and confirmation revalidate current employee version/eligibility and policy validity. The current draft accepts active/probation only; suspended and departed retrospective correction rules require explicit temporal business treatment before operational acceptance. Do not count that unresolved eligibility boundary as full parity.
- Confirmation inserts revision one; closing appends a receipt; correction inserts the next revision linked to the latest closed revision. Preview, revision and close facts reject UPDATE, DELETE and TRUNCATE. Family advisory locks serialize even the empty-family case; unique request/preview/revision keys remain the database backstop.
- Durable retries are checked before source expiry or employee revalidation, bind the actor and canonical request, and return the original result. Changed actor/content conflicts. HTTP financial writes also use the idempotency interceptor. Required write audit uses the same transaction manager; failure rolls back all inserted facts. Audit excludes bases, rates, amounts and reason text.
- SQL independently recomputes each component with PostgreSQL numeric and rounds once after the fixed addend; totals sum rounded components, excluding fund only when explicitly requested. Bind the input bases to calculated items. Preserve NULL fixed addends; reject missing rates, negative pre-round values and overflow.
- Payroll result `insurance_period_id` retains its historical FK. `insurance_modern_revision_id` has a separate scoped FK; at most one can be nonnull. Modern reference guards check employee, month and current revision. Existing results and historical published-path semantics remain intact.
- Payroll integration must include explicit DTO/UI source selection, locked exact source reads, frozen source version/hash, matching result and item-difference references, and actual insurance monetary inputs in reviewed DSL formulas. Merely storing `insurance-facts-v1` or a hash does not prove money is used in calculation. Never auto-approve formulas, publish history, create payslips or initiate payment.
- Reads expose allowlisted projections and require sensitive-read audits, including authorized empty lists. Real-role scopes and desktop/390px checks are separate from synthetic tests. Do not grant new write capabilities through old role templates or automatic module permissions.

Required evidence: complete original migrations on a disposable localhost PostgreSQL; exact amount/NULL/overflow tests; expiry, scope, employee drift, parallel first confirmation/correction/close and stable retry; same-transaction real audit rollback; historical coexistence and unchanged prior facts; modern payroll monetary effects and frozen-result stability; permissions and actual pages. Actual month/book/rules and real-role acceptance remain pending until provided and verified.
