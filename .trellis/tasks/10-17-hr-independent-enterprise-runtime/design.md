# 技术设计

## 同内核与模式边界

保留 HrModule 及业务服务。启动装配和范围解析是明确适配边界：集成入口继续完整平台；独立入口只装配 HR 及企业基础能力。服务端启动校验模式，客户端只能读取实际配置，不能授权切换。

范围端口覆盖登录候选、主体权限、成员有效性、当前范围、组织/角色数据范围、模块可用性及上下文切换。集成适配器保留现有有效园区条件；独立适配器查真实企业与成员事实，不创建假园区。若旧 tenantId/parkId 列或传输键保留内部兼容，明确其企业范围语义及边界，以缺少园区表的实际环境证明正确性。

优先复用 IdentityDirectoryModule、权限计算、会话/密码原语、DataScopeService、Audit、IdempotencyService 和上传策略。仅分离确实阻碍企业范围的条件和提供者；不得复制两套权限/HR实现。模式令牌隔离、默认集成旧令牌兼容、即时撤权同时验证。

## 独立数据与文件

复用已保存空库结构及依赖证据确定独立DDL与版本升级清单，补足无FK实际SQL/仓库依赖。独立初始化不得运行全部园区DDL。生成式schema或显式新迁移均须可重建、校验并与HR内核变更同步；不得改写已应用集成迁移。数据源身份、精确共享账本、历史审计主体不因拆分丢失。

企业组织、身份/成员、角色/字段、模块、消息、文件、审计、幂等和HR表按真实路径闭合，不能只看外键闭包。新建独立空库、迁出现有HR和生产历史导入是不同操作；本子任务在隔离资源实际运行，不自动复制生产行。

## 前端

复用HR页面和DS。登录落点、范围选择、导航及必需配置采用企业语义，权限来自实际API。不能通过伪造普通员工为HR、隐藏按钮或假响应证明可用；字段、附件、状态、原请求重试及持久化回读延续。

## 收敛与验证

实施前读取受影响现有接口，收敛具体企业schema、端口、配置和命名，在research记录决定。可在需求内更新此设计，不得削弱验收或用stub填缺口。实际双模式PG/HTTP、角色负例、并发/审计/文件及桌面390px验证；集成必要回归和CI。

所有独立资源专属且可清理。独立公开部署目标尚未选择，不自动创建；当前集成发布需新鲜三端同步、健康和Docker清理。代码回退不得删除已有业务事实或修改历史迁移。

## 配对恢复内容核对

`scripts/hr-enterprise/verify-restored-pair.mjs` 仅接受私有配置文件，显式 `mode=check`；没有 apply 分支。manifest 原始字节由独立的 `manifestSha256` 钉住。文件摘要以打开的非链接文件描述符流式计算，检查读取前后身份与大小/时间；文件根必须为真实绝对目录，目录内只允许目录和单链接普通文件，限制深度及文件数量。DB 使用 REPEATABLE READ READ ONLY 与逐查询超时；精确核对 public 普通表集合、模式行、版本历史及当前安装步骤校验和。逐表服务器 C 排序、游标分块读取 JSONB text，按原审计 COPY text 编码累计 SHA-256，不输出个人行。前后两次完整文件清单相同才生成通过回执。

该结果是时点内容观测，不是写入或启动授权。配置身份沿用 RuntimeIsolationService 的 host/port/database tuple，不能证明物理实例不同；目标恢复登记必须另做物理来源/目标约束、完整结构及角色 ACL 核验和并发冻结。正常启动 guard 不修改，不能用本工具的 PASS 绕开它。

## 受控恢复登记

续接分支基于 PR988 的冻结提交，待其完成合并后再同步主干，不更改其提交。新增独立运维入口，默认 check；apply 要求明确目标物理身份摘要及私有配置。冻结恢复目录清单绑定原配对清单、源物理数据库身份、原 schema-only 原始字节摘要及规范化摘要、全部 public 函数定义/ACL、精确能力角色及无成员授权。目录不是现场通过回执，必须由冻结备份材料准备并单独钉住字节摘要。

物理身份由明确拥有查询权限的恢复管理员读取 cluster system_identifier 与数据库 OID，不能以连接字符串差异替代。无权限失败，不回退或作为生产普通诊断。结构通过同一快照的 pg_dump --schema-only --no-owner --no-privileges 核对，只允许已有四处命名 CHECK 的精确反解析重写；固定PG主版本，拒绝其他结构变化。

目标必须离线，无其他数据库客户端；同库事务级维护 advisory lock 和全部 public 表 SHARE ROW EXCLUSIVE 锁保持至登记结束，阻止业务写入和现有表DDL；导出快照供pg_dump，复用同快照逐表内容核对。文件根用排他的同级维护锁串行化登记；再次校验文件及原marker身份/字节后，用根内0600临时文件、fsync及原子替换登记，正常运行guard不改。标记携带原配对清单、恢复目录和源marker摘要，精确相同登记重放重新校验后返回，不覆盖冲突。工具不防护拥有主机或DB管理员权限的恶意并发操作，离线维护期间禁止其他运维修改。

异常清理只释放本次持有的锁/临时文件；原实例、备份和业务行不改。进程被强杀遗留锁需运维核实后处理，不自动删除不明锁。marker已原子替换但尚未返回回执时，再次正常运行以精确新marker识别重放。实际owned新实例覆盖登记前拒绝、check不写、apply、重放/冲突、结构/ACL/文件漂移，以及登记后的真实HTTP/附件业务；完整产品及生产RTO/RPO验收继续保留。
