# 完善角色模板实例化与用户分配闭环

## Goal

角色管理与用户管理形成清晰、可验证的模板角色闭环：模板角色不能直接修改绑定或分配给用户；管理员必须先将模板实例化为当前租户/园区下的普通角色，再配置并分配给用户。模板实例化的最终权威来源为 `packages/shared` 中的物业角色模板定义，而不是数据库中当前园区模板角色的绑定副本。

## Requirements

- 用户管理只展示当前目标租户/园区内可分配的启用普通角色；模板、系统、内置、平台、停用和跨园区角色不得作为新分配候选出现。
- 角色管理必须明确区分“模板角色”“普通可分配角色”“系统/内置/平台受保护角色”。
- 受保护角色的权限、数据范围、字段策略绑定不可直接修改；模板角色应提供清晰的“实例化为普通角色”路径。
- 模板实例化必须以 `packages/shared` 的模板定义、权限包、additional/excluded 权限和默认数据范围规则为准。
- 数据库中的模板角色和绑定仅作为展示、兼容和历史迁移数据；不得在 shared 定义可解析时作为权威实例化来源。
- 实例化后的普通角色必须属于当前租户/园区，启用、非模板、非系统、非内置、可编辑、可删除，并可在用户管理中被搜索和分配。
- 如果 shared 模板定义缺失、模板 metadata 漂移、权限包或权限定义无法解析，实例化必须失败并给出明确错误；不得静默创建空权限角色。
- 前端应把“复制模板”产品化为“实例化为普通角色”，补齐权限不足提示、就地 CTA、成功后的下一步说明和用户管理空候选引导。
- 本任务不改变用户管理候选过滤的设计，不允许直接把模板角色暴露给用户分配。

- [x] 缺少实例化所需权限时，页面展示可见说明，而不是静默隐藏所有入口（PR #305 / `227f7e1d`）。
- [x] 实例化表单替代原生 prompt，至少包含新角色编码、新角色名称、来源模板和实例化后范围说明（PR #305 / `227f7e1d`）。
- [x] 后端 managed 模板实例化优先解析 shared 模板定义并按 shared 计算最终权限集合（PR #305 / `227f7e1d`）。
- [x] 数据库模板权限绑定被篡改或缺失时，shared 可解析的模板实例化结果仍按 shared 定义生成权限（PR #305 / `227f7e1d`）。
- [x] shared metadata 与数据库模板 metadata 不一致时 fail closed，并返回可排查错误（PR #305 / `227f7e1d`）。
- [x] 实例化后的普通角色能继续配置权限、数据范围、字段策略，并出现在用户管理的可分配候选中（PR #305 / `227f7e1d`）。
- [x] 用户管理候选为空时解释“模板不可直接分配”，并引导到角色管理实例化（PR #305 / `227f7e1d`）。
- [x] 补充 shared/API/Web 静态或单元测试，覆盖实例化来源、保护规则和页面引导（PR #305 / `227f7e1d`）。
- [x] 完成 PR、手动触发 `@codex review`、修复 actionable review、CI 绿后合并并记录闭环状态（PR #305 / `227f7e1d`）。
- [ ] 完成角色实例化与用户分配引导的桌面端和移动端真实浏览器验收。
