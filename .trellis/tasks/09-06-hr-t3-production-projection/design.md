# Design

Implement a pure per-parent T3 projector plus small attendance support builder. Main APIs: projectProductionT3Fields(record, {attendanceFileSha256}?) returns one parent and its expanded child projection records; buildProductionT3AttendanceSupport(attendanceRows, attendanceFileSha256) returns the deterministic batch and every observed nonblank symbol projection. Each result row has existing phase provenance, targetFields (all whitelisted fields or null on semantic failure), dependencyRefs and reasonCode (null or stable review code). It is a preparation record, not a signed decision.

Provenance formulas must exactly match materialize-production-t3-phase-artifact.mjs; a tiny export/reuse of existing projection identity helpers is permitted without changing current CLI behavior. Verify exact wrapper/source/item shapes, sourceKey=String(source.id), source table identity and SHA format; raw-row SHA is inherited only after the private owner verifies manifest bytes, not falsely derived from reduced source. Unknown fields fail. Project calendar/day identity even when a semantic date is invalid so caller can quarantine all rows. Distinguish structural coverage errors from semantic target representability.

Attendance uses existing two reviewed symbol mappings (standard/night), observed unknown symbols keep their day value and needs_review; the unknown rule projection has null targetFields and a stable unresolved reason. No unsupported rule is invented. Blank days remain blank. Batch code derives from source attendance file SHA within varchar64, not a random run/time; source_checksum is full SHA, status imported (not verified before actual verification).

Policy rates already fractional; exact scale6. Fixed amounts scale3. Contribution amounts scale2. Use decimal strings only, trim redundant zeroes/pad exact scale, reject nonzero precision loss/overflow or unsupported signs instead of Number casts. Current generic target payload forbids negative decimals even when fixed-amount SQL is signed: classify unsupported negative fixed values rather than silently changing global money behavior. Preserve legacyBaseNegative and legacyFlag in period snapshot keyed by item kind, never use flags to drop rows or claim eligibility. Period needs_review reflects actual negative-base/unresolved flag conditions without fabricated meanings. Dependencies point only to stable source identities, T0 employee resolution happens later.

Output can preserve null source fields; snapshots carry existing source row hash plus source facts omitted elsewhere (legacy flags and source scope as appropriate), not invented values. Keep eight-target coverage and no hidden derived columns in targetFields. Existing shared target normalizer validates representable output. Parent semantic errors propagate to child targetFields/reason while conserving identity; child-only numeric problems do not discard unrelated siblings.

No full35008-row output aggregation in this pure layer: the later private streaming owner will supply one verified parent at a time. Do not add a new production writer or authorization mechanism. Source-specific receipt identities and target/T0 graph checks remain responsibilities of that later assembler.

Real source review found an attested older policy item layout with kind/variant and four rates but no fixed-amount fields. Accept only this exact six-key layout in addition to the current ten-key layout. Preserve each identity with T3_POLICY_FIXED_AMOUNTS_UNATTESTED before interpreting its rates; missing evidence is not null/zero. Partial missing fields or unknown fields remain structural failures. The current transformer is not proof of historical rate units. Later source-bound policy evidence must resolve this gap, without silently rewriting the existing stage or source manifest.
