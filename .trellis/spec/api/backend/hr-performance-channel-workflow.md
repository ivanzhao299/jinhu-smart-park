## 3. Contracts
An existing definition-only draft may acquire its first workflow policy in the same definition revision save; validate the supplied policy, reject a stale nonempty expected workflow pointer, and return the new workflow revision. Workflow revisions bind an exact definition revision on the same version; deferred head/pair guards require both heads to advance atomically. Publication validates complete policies, nonempty details/items/grades and manual adjustment input. Stable detail IDs are independent from item IDs; repeated items never collapse. Cycle freezes both revision IDs and complete definitions/policies.
New five-channel cycles start unpublished in planning; new employee rows start only in planning/self_review with all score, input/result pointers, grade evidence and completion timestamps NULL. INSERT must enforce this explicitly because result transition guards cover UPDATE only. Input is append-only, same-review predecessor chained and CAS protected. Every cell distinguishes UNPROVIDED, EXPLICIT_NULL and VALUE with author/time/evidence; clients cannot provide authors/timestamps or reset UNPROVIDED. API obtains timestamps from the transaction clock. Required narrative/evidence cannot be whitespace. Plain numeric strings preserve18,2 and salary19,4; no Number conversion. Stable IDs and valid source text remain untrimmed.
Stage authority is policy intersected with current database permission, selected-park authorization and employee/manager/active calibration membership. Every current-stage mathematical input must be explicitly provided before submission; optional text does not gate arithmetic. Required values cannot be NULL; nullable optional fields need explicit NULL plus evidence. Future fields do not block self/manager submission and incomplete totals remain SQL/JSON NULL. Finalization requires every mathematical cell plus required master fields and a unique threshold candidate. Core370 calculates all details exactly. Final grade code/name64 carry candidate.code; final_grade_evidence retains candidate.description500 and complete calculation evidence, recomputed even when score is unchanged.
Partial batch finalization commits each employee independently and returns item receipts; active persists while any review needs calibration, completed follows the last finalized employee. Repeating a completed employee returns alreadyFinalized only for the same batch. Cycle status preserves pending appeals. Appeal amendment requires explicit appealReviewAllowed, pending appeal, nonself APPEAL_REVIEW and salary intersection; rejected appeal retains prior final revision. Confirmed records remain immutable; correction cycles create only explicitly selected employees and preserve predecessor/reason/business period.
Salary read requires current PERFORMANCE_READ and PAYROLL_DETAIL_READ; write requires PERFORMANCE_READ, PERFORMANCE_MANAGE, COMPENSATION_MANAGE and field/stage authority. Current/history omit the complete salary cell without authority. Calculation/action/review/export projections contain no salary input. Employee-self before final visibility sees only configured self-stage cells and preview:null without live RESULT_READ; independent preview rejects. All writes use IdempotencyInterceptor and captureBody:false audit; input/history reads use required metadata-only sensitive-read audit.
Migration372 replaces only11 formal performance actor FKs with sys_user(id) references plus unified same-tenant/current selected-park author guard. All business composite FKs remain. Protected tenant super uses the exact enabled system/builtin/platform SUPER_ADMIN contract; ordinary cross-home-park users need a target-park binding. Historical stable authors require same-tenant existence, not current privileges. No auth table/index/grant changes. Pure helpers retain SECURITY INVOKER and existing ACL; migration/API verify actual connection EXECUTE, never grant PUBLIC or assume a production role from examples.

## 4. Validation & Error Matrix
Unknown/missing/type/precision/invalid UUID/policy ->400. Missing live authority/field or premature preview ->403; invisible scoped review ->404. Stale pointer/stage/incomplete/ambiguous final ->409. Idempotency same key/body replays; changed body conflicts. Direct SQL rejects unadvanced heads, foreign revision/author, wrong stage, forged evidence/grade, nonfinite scores, premature batch completion and confirmed mutation. SQL constraints explicitly handle NULL to prevent UNKNOWN acceptance.

## 5. Good / Base / Bad Cases
Good: two detail IDs share one item, self/manager submit NULL final totals, calibrator explicitly provides the rest, then one employee finalizes while another remains incomplete. Base: old published dimension version still runs its original full lifecycle with selected-park actors. Bad: infer missing0/NULL, infer letter-role business labels, truncate complete candidates, use description as a64-character grade name, trust stale salary JWT, or update a confirmed prior review.

## 7. Wrong vs Correct
Wrong: lock batch or appeal before the parent cycle, or check history head/count/page with independent snapshots. Correct: lock cycle before review/batch/action and read policy history head/count/page in one SQL snapshot. Wrong: apply current author privileges to unchanged historical authors. Correct: retain same-tenant history while validating each new/changed author against actual selected-park bindings. Wrong: call API completion production acceptance. Correct: retain independent review, UI, release/runtime and real business acceptance boundaries.

## Optional per-detail appraisal (migration374)
SchemaVersion1 retains exact old JSON. Optional `detailAppraisalPolicy` must be paired with optional `appealReviewAllowed.detailAppraisal`; unknown/mismatched keys fail. When enabled, every independent input detail has one `appraisal` cell; when absent the key is forbidden. PATCH `field=detailAppraisal` requires exact detailId,0..200 Unicode codepoints for VALUE, explicit policy-controlled NULL, true server actor/time/evidence and existing stage/live authority/CAS. Required text cannot be blank. Optional text does not gate math; required text gates its stage and final readiness. Self prefinal current/history omit the complete nonself-stage appraisal cell. Repeated item IDs never merge details.
Migration374 uses CREATE OR REPLACE on only workflow_valid/policy_for/cells/input_valid/calculate/stage_complete, preserving signatures/OIDs/ACL/SECURITY INVOKER. calculate excludes the narrative from math completeness but never changes core370 arithmetic. Old no-extension and enabled extension must each pass actual required PG/HTTP lifecycle; narrative-only appeal keeps the same score and confirmed history immutable. See `docs/testing/hr-performance-detail-appraisal.md`. This does not grant source qualification or activation credit.

Required detail appraisal blank detection uses the ECMAScript trim whitespace set consistently in API, SQL input validation and stage completion, including U+FEFF and U+00A0. This is classification only: stored text is preserved verbatim, optional text may remain blank, and existing master narrative semantics are unchanged. Required PG regressions cover API rejection, direct SQL rejection and required/optional stage readiness for these Unicode characters.
