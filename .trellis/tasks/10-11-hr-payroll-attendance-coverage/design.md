# Design
Extend HrPayrollFormalRunOptionsQueryDto, FormalPayrollRunOptions and hrApi.formalPayrollRunOptions narrowly. Reuse HrPayrollFormalRunService.options confirmed-input locking, requirements classifier, scoped attendance candidate query and coverage predicates. A provided candidate may be incomplete but must otherwise be valid; only its exact item membership determines page flags. Preserve global roster counts independently of pagination. Existing create validates complete coverage again and remains unchanged.

On PayrollRunCreation select incomplete candidates for inspection (no disabled option), retain visible warning and existing explicit creation rejection. Bind options response to selected input version and attendance batch; abort stale reads when selection changes. Combined source roster uses existing bounded paging for attendance-only or insurance rules. Do not introduce auto-source/defaults, duplicate endpoints, money calculations or source changes. Use null/unknown honestly, DS variants and existing local layout only.
