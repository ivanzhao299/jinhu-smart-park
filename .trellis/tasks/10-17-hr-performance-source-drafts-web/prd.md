# 绩效资料维护现代页面

## 目标
在已有现代绩效工作台正常入口查看和维护正式资料草稿、明确绑定和修订历史，后续补导差异不覆盖人工修改；不要求用户进入旧数据只读区或看到来源资格阻断。与后台子任务共同实现实际可操作草稿，父D完整启用/正常办理仍保留。

## 需求
1. 正常绩效页按真实用户模板/绩效read/manage权限展示“资料维护”入口，source追溯可折叠。独立模板/评价资料、来源候选和已保存资料分页/选择；read-only账号不发写候选请求，模板only不发评价请求。
2. 预览完整可维护业务字段和固定来源证据，全部记录通过分页/分组可达，无30/20截断。数字/金额字符串全程保存不转Number，明确null不等于0；原作者/时间和历史计算结果为来源追溯，正式业务作者/时间实际记录。
3. 明确人员/组织/期间绑定、既有严格definition/workflow编辑器可复用，缺项可保存草稿，不能提示已审批/已启用。salary服务端省略时不显示伪空字段、不得由全snapshot替换清空隐值。
4. 创建/保存/refresh各自稳定原payload/key重试、同步提交锁、409保留草稿并提示具体重载/差异行为、失败不清空、成功receipt严格核对后重读、刷新失败不能重复提交。切换kind/draft/auth/scope时所有target-bound表单/历史/错误/请求generation重置，迟到回调不能覆盖新目标。
5. 资料已人工修订的新来源refresh冲突必须保留当前资料。历史完整分页当前权限投影，reader不能通过错误/历史/preview看到隐藏pay或其他master。无源候选状态说明暂无资料可整理，正常模板/周期功能仍可用，不推断漏导或让用户重新分析数据。
6. DS全局surface/表单/按钮、文字留白、图标与其他现代工作台一致；手机390px无横向溢出，按钮不逐字换行，触摸操作稳定。

## 验收
精确API合同冻结后才实施。真实组件interaction：角色reachability、所有分页/选择、62字段V/R/P可达、source定义与workflow配对、工资隐藏保持、同请求retry、切换/迟到、失败/409/成功回读、无来源empty。shared最新生产者build再跑消费者，Weblint/typecheck/必要build；actualcomponent native desktop+390px截图/scrollWidth和点击实测。synthetic不得冒充production真实数据。启用link/receipt与完整评价办理另由父D交付，不以本子任务宣布全部完成。
