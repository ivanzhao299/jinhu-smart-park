# 修复当前开放 Issues 209 与 215-217

## Goal

修复 GitHub 当前开放的 #209、#215、#216、#217，并沿用上一轮 issue 修复的隔离分支、根因分析、防复发测试、完整验证与审查闭环。

## Requirements

- 基于最新 `origin/main` 实施，不污染原工作区已有改动。
- #209 点击巡检任务“执行”后不得再触发整页客户端异常；运行时响应缺失、脱敏或形态异常时应可控降级并给出错误信息。
- #215 巡检点位的楼层候选必须受楼栋约束，房源候选必须受楼层约束；修改父级时清理不再合法的下游值。
- #216 新增和编辑用户时，默认园区及可访问园区必须在候选数据加载完成后可靠显示；加载失败或目标租户无园区时不得提交空的必填值。
- #217 开通租户时套餐候选必须与后端实际可解析的有效套餐目录一致，不得只查询当前园区导致空列表。
- 修复应覆盖同类运行时集合投影、级联选择、异步候选生命周期和“可解析但不可列举”的接口契约风险。
- 不自动合并，不改动生产数据，不编辑已应用迁移。

## Acceptance Criteria

- [ ] 四个 issue 均有可复现的失败用例和对应回归测试。
- [ ] Web/API 相关单测、lint、typecheck、build 全部通过。
- [ ] 有意义的前端页面在桌面和 390px 级手机宽度完成实际浏览器检查，或明确记录环境阻塞。
- [ ] 仅提交本任务文件并推送专用分支，创建关联 #209、#215、#216、#217 的 PR 并请求 Codex review。
- [ ] 审查反馈按“验证根因—修复同类风险—补测试/规范—复验—回复线程”的方式闭环。
