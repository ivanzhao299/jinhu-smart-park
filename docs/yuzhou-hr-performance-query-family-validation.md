# 绩效查询族：合成非空功能验证

## 实现边界

旧查询在运行时关联当前人员和部门，不要求先创建现代绩效周期。
本候选通过旧结果的 subject identity、精确 T0 owner map 和当前员工/主组织
取得姓名及权限范围，不再依赖缺失的现代 cycle employee 而隐藏全部历史结果。

- 维度结果和汇总结果分别绑定自己的 identity fact kind，不能互相替代。
- 最终服务读取只允许 `verified` 的 T0 owner map；`loaded` 不足以提供姓名或
  本人/团队权限依据。000306 的事务内 candidate helper 保持原有阶段语义。
- `web_ass` 保留内连接行为；`web_assessmentquery` 的园区读取保留孤立旧结果，
  无可用人员映射时姓名为 null。本人/团队范围不能通过该保留行为绕过身份校验。
- 当前人员或组织变化反映到当前查询，不冒充冻结的历史姓名/部门快照。
- 已删除、跨域、无有效组织和歧义候选按现有现代权限规则拒绝或隐藏。
  `web_assquery` 遵守现代界面选择的期间，明确区别于旧过程丢弃期间参数的行为。

## 验证与证据分离

`node scripts/e2e/yuzhou-performance-query-family-direct-pg.mjs` 使用短生命周期、
只绑定 loopback 的合成 PostgreSQL 容器。七项实际 SQL/服务测试覆盖：

1. 无现代周期时的当前人员查询及读取审计；
2. 两个 person-summary 入口不同的孤立结果语义；
3. 负责人组织树、本人及无权账号范围；
4. 缺失、停用、歧义、删除、无组织和跨域人员的拒绝行为；
5. 人员 owner map 未校验时，不显示姓名、不赋予本人/团队可见性；
6. 当前员工姓名与组织变化后的查询；
7. 新增冲突 T0 候选后，内连接拒绝，保留旧结果的入口不附会员工姓名。

未校验映射负例先在真实 PostgreSQL 中复现：assessmentValue 错误返回 1 条。
收紧最终读取谓词后七项全部通过。临时容器在成功或失败后均由所属 runner
停止并自动删除；本测试不连接真实源或生产。

必须区分这类测试和 PR #624 的实际导入链测试：本文件对应的 query-family
fixture 为了验证非空结果语义，会创建最小表结构、手工配置 verified 映射和
批次可见状态，再运行原 000306 identity materializer。它不是生产 loader，
这些人为状态不得作为迁移成功、生产兼容积分或真实源有结果数据的证据。

PR #624 的独立证据使用实际 total writer 装载配置/关系，再由真实服务查询
并回滚；其权威形状中的结果仍为零。两类证据互补，不能互相替代。
本候选尚不证明完整存储过程等价、真实业务 UAT、生产导入或最终 M0-M5/P0-P4
产品验收。本轮前端仅更正两处说明文案；未新增浏览器运行证据。
